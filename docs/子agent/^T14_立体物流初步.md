# T14 立体物流初步（T9 P1 最小可用：B1 垂直提升机）喵

## 目标喵
对「立体物流」做**初步尝试**：从 T9 方案 P1 中选 B1 垂直提升机实现最小可用版本，只动独立新文件，不碰共享注册文件（`BlockdustryBlocks` / `BlockdustryClient`），编译通过，注册清单交给主会话喵。

---

## 一、方案选择喵

| 候选 | 选择 | 理由 |
| --- | --- | --- |
| A 上下坡传送带 | 否 | 需改 ConveyorBlock/Entity 交接坐标与 directionOf，可能破坏现有平面逻辑，风险高喵 |
| **B1 垂直提升机** | **是** | Duct 式单格垂直带，一格存 1 件 + `progress∈[0,1]`，`front=pos.above()`，一列 n 格即 n 段接力，零新概念、改动面最小喵 |

B1 已实现为一个**独立新方块 `elevator`**：接受物品后沿 +y 方向逐格上移，顶格交给上方 sink（另一节提升机，或 Router/机器）喵。

## 二、实现喵

### 2.1 新增 Java 文件（均未注册，编译已通过）喵

| 文件 | 职责 |
| --- | --- |
| `src/main/java/com/blockdustry/building/ElevatorBlock.java` | 方块：继承 `BlockdustryBuildingBlock`（size=1），无水平朝向，`getFacing(BlockState)` 恒返回 `Direction.UP`；碰撞/选中用基类默认整格立方体喵 |
| `src/main/java/com/blockdustry/building/ElevatorBlockEntity.java` | 方块实体：**单槽**（`SLOTS=1`）+ `progress[0]∈[0,1]`，`SPEED=0.046`（与传送带一致）；实现 `BlockdustryItemSink/Source`（继承自基类）喵 |
| `src/main/java/com/blockdustry/building/ElevatorBlocks.java` | **独立自包含注册类**（DeferredRegister 三件套：block / BlockItem / BE type），新文件、不并入共享注册表，保证编译期无未注册符号；主会话只需 `ElevatorBlocks.register(bus)` 激活喵 |
| `src/main/java/com/blockdustry/client/ElevatorBlockEntityRenderer.java` | BER：画带内物品，`y = 0.25 + p*15.5` 从格底升到格顶（0.25→15.75），物品平躺缩小 50%（沿用 Conveyor 渲染风格）喵 |

### 2.2 交接逻辑（ElevatorBlockEntity）喵

- **收件 `acceptItem(source, item)`**：同队 + 来源**非上方**（上方是输出端，不收）+ 槽空喵。
  - 来源方位 `directionOf`：先判 `.above()` → UP，再扫水平四邻，再判 `.below()` → DOWN；其余返回 null 拒收喵。
  - 因此可从**下方**（上一节提升机交接）或**水平侧**（传送带喂入）收件喵。
- **上移 `tickAnchor()`**：槽空直接返回；`front = level.getBlockEntity(worldPosition.above())`，转 `BlockdustryItemSink` 判出口；
  - 出口可收 → 推进上限 1.0；被堵 → 上限 `NEXT_MAX_BLOCKED=0.95`（顶到 0.95 停住不穿模进上方格）喵。
  - `progress += SPEED` 后若 `>= 1.0` 且上方 sink `acceptItem+handleItem` 成功 → 清空本格（交给上方）喵。
  - `syncBelt()`：`setChanged()` + `sendBlockUpdated(...,3)`，客户端随 NBT 同步喵。
- **持久化**：`bd_elevator_item`（Registry 名） + `bd_elevator_progress`，与 Conveyor 同风格喵。

### 2.4 使用方式（激活后）喵
- 底端：把**传送带**的出口对着提升机底节侧面喂入（物品从格底起步上移）喵。
- 中段：`elevator` 竖着叠 n 格，上一节顶到 `progress=1` 时交给下一节，接力上移，任意高度喵。
- 顶端：提升机只向上方交接，**顶部放 Router / 任何不拒方向的机器**接收后水平吐出（传送带顶面不收——Conveyor 的 `directionOf` 只查水平邻接，见「已知限制」）喵。
- 链路示例：`传送带 → elevator×N → Router → 传送带`，即可完成垂直物流演示喵。

## 三、注册清单（给主会话）喵

本任务**未**改 `BlockdustryBlocks` / `BlockdustryClient`，激活需主会话做以下任选其一喵：

### 激活方式 A（推荐，最小改动）
1. `Blockdustry.java` 构造器里 `BlockdustryBlocks.register(modEventBus);` 后追加一行：`ElevatorBlocks.register(modEventBus);`
2. 创造栏：`BlockdustryBlocks.java` 的 `TAB` 的 `displayItems` 里加 `output.accept(ElevatorBlocks.ELEVATOR_ITEM);`
3. 渲染器：`BlockdustryClient.java` 的 `registerRenderers` 里加 `event.registerBlockEntityRenderer(ElevatorBlocks.ELEVATOR_ENTITY.get(), ElevatorBlockEntityRenderer::new);`
4. 完成后 `/give @p blockdustry:elevator` 或创造栏取用喵。

### 激活方式 B（并入共享注册表）
把 `ElevatorBlocks` 里的 `ELEVATOR / ELEVATOR_ITEM / ELEVATOR_ENTITY` 声明与 `elevatorBlock()` 工厂方法平移进 `BlockdustryBlocks`，其余同 A 的 2/3 步喵。

### 不需要额外动作
- blockstate / 模型 / item 模型 / lang 已随文件就位，无需复制喵。
- 编译已通过（`./gradlew compileJava` BUILD SUCCESSFUL），激活后同样应编译通过喵。

## 五、后续方向喵

### P1 剩余
- **方案 A 上下坡传送带**：`ConveyorBlock` 加 `SLOPE(UP/DOWN)`，交接坐标 `.above()/.below()`，`directionOf` 支持 UP/DOWN；改动现有 Conveyor，需守住平面逻辑回归（建议另起子任务，对照 `docs/传送带上下坡.md`）喵。

### P2 方向（T9 建议）
- **方案 C 立交桥/高架**：MC 天然 3D，把带铺到 y+1 空块即交叉不干扰；需补放置支撑语义喵。
- **方案 D 分拣器**：短距跨层转移臂，两点可跨 y，独立新方块 + BER 动画，工作量中高喵。

### 本方案已知限制 / 待改进（提升机自身）喵
1. **顶部交接只能向上**：Conveyor 顶面不收（`directionOf` 只查水平），故顶格需 Router/机器中转；后续可给提升机加「顶部水平吐口」状态或给 Conveyor `directionOf` 增补 UP/DOWN 支持喵。
2. **`dumpItem` 不向上卸货**：`BlockdustryBuildingEntity.dumpItem` 只扫水平四邻，Router/物品源无法从下方喂提升机；当前靠侧喂。后续可给 dumpItem 加向上候选喵。
3. **单槽吞吐低**：一格 1 件，`SPEED=0.046` 格/tick；后续 B2（anchor 管整列、`vProgress` 贯穿全高）可提吞吐，但复杂度高，暂缓喵。
4. **模型复用传送带贴图**：竖管视觉是临时占位，后续可按 `贴图.md` 命名规范画 `elevator_*` 专属贴图（顶面=1/侧面=2/底面=3）喵。
