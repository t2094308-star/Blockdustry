# T18 科技树实现 A（数据/存档/门控）阶段产出喵

## 目标喵
按 T16 拆分落地科技树 A 组：数据层（节点定义/依赖图/成本公式）、存档（ResearchSavedData）、门控（EntityPlaceEvent 禁放），参数忠实搬运 Mindustry 喵。

## 一、实现内容总览喵
新增 7 个文件（全部 `com.blockdustry.research` 包，独立新文件，未碰任何共享注册文件）喵：
| 文件 | 职责喵 |
|---|---|
| `ResearchNode.java` | 节点 record（id/parents/unlockContent/defaultUnlocked/buildRequirements/researchCostOverride/costMultiplier/perItemMultiplier）+ Builder 喵 |
| `ResearchCost.java` | Mindustry 公式 `round10(60*mult + 建造量^1.11*20*mult*物品倍率)` 喵 |
| `ResearchTree.java` | 懒加载单例：id/解锁内容索引、children、depth、沿父链累乘倍率、有效研究需求喵 |
| `ResearchNodes.java` | 全部节点静态定义（树结构 + Mindustry 参数）喵 |
| `ResearchSavedData.java` | SavedData 挂 overworld：unlocked 集合 + progress 表，显式 setDirty 喵 |
| `ResearchManager.java` | 服务端权威 API：isUnlocked/canResearch/spend/unlock/autoUnlock + PlayerLoggedInEvent 占位喵 |
| `ResearchGateHandler.java` | `BlockEvent.EntityPlaceEvent` 服务端兜底：未解锁建筑禁放 + 提示喵 |

## 二、数据层设计喵
- **注册方式**：Java 静态注册（`ResearchNodes.all()`），懒加载（`ResearchTree.get()` 双检锁，首次访问在注册完成后），无需改 `Blockdustry.java` 喵。
- **研究需求计算**：每节点存 Mindustry 建造配方（`buildRequirements`）+ 自身 `costMultiplier` + 按物品倍率；`ResearchTree` 沿父链累乘后对每项套公式得有效需求；有 `researchCostOverride`（Mindustry researchCost）则直接覆盖喵。
- **默认解锁**：`defaultUnlocked=true` 节点门控直接放行，SavedData 无需记录喵。
- **倍率累乘**：`effectiveMult = 父有效倍率 * 自身 costMultiplier`；`perItem` 同理累乘，镜像 Mindustry TechNode 构造逻辑喵。

## 三、存档设计喵
- `ResearchSavedData extends SavedData`，`get(ServerLevel)` 统一走 `server.overworld().getDataStorage()`（跨维度同一份）喵。
- NBT 结构：`unlocked`=String ListTag；`progress`=CompoundTag{ 节点id: CompoundTag{ 物品id: int } }，全用 RL 字符串，load 不依赖 HolderLookup 内容喵。
- 每处变更（unlock/addProgress）显式 `setDirty()`，规避 Level attachment 原地改不持久化坑喵。
- 多人同步留 B 组（`ResearchManager.onPlayerLoggedIn` 已留占位）喵。

## 四、门控设计喵
- `ResearchGateHandler.onPlace` 订阅 `BlockEvent.EntityPlaceEvent`（与既有 `BlockdustryTeamHandler` 同事件共存）喵。
- 判定：只拦 `BlockdustryBuildingBlock` 子类（已核对 Conveyor/Elevator/ItemSource/PowerSource 均继承之）、玩家放置、非创造模式；未解锁则 `event.setCanceled(true)`（回滚 BlockSnapshot）并发送 `blockdustry.research.locked` 提示喵。
- 服务端权威：客户端 UI 过滤是 B 组锦上添花，门控不依赖客户端喵。
- 创造模式默认绕过（对应 Mindustry sandbox 全解锁），可后续加 config 开关喵。

## 五、Mindustry 参数表（Build 需求 → 研究需求）喵
公式：`round10(60*mult + 建造量^1.11*20*mult*物品倍率)`，物品映射 铜→铜锭/铅→blockdustry:lead/石墨→blockdustry:graphite/硅→blockdustry:silicon/钍→硅替代（Blockdustry 无钍）喵。

| 节点 | 父 | 默认解锁 | Mindustry 建造需求 | 计算研究需求喵 |
|---|---|---|---|---|
| core | — | 是 | 铜×1000 铅×800 | alwaysUnlocked 免费喵 |
| conveyor | core | 是 | 铜×1 | **override 铜×5**（conveyor.researchCost）喵 |
| router | core | 是 | 铜×3 | 铜×130 喵 |
| drill | core | 是 | 铜×12 | **override 铜×10**（mechanical-drill.researchCost）喵 |
| power_node | core | 是 | 铜×2 铅×6 | 铜×100 铅×210 喵 |
| combustion_generator | core | 是 | 铜×25 铅×15 | 铜×770 铅×460 喵 |
| power_source | core | 是 | 调试源 | 免费喵 |
| item_source | core | 是 | 调试源 | 免费喵 |
| graphite_press | core | 否 | 铜×75 铅×30 | 铜×2470 铅×930 喵 |
| battery | power_node | 否 | 铜×5 铅×20 | 铜×180 铅×620 喵 |
| turret（duo） | core | 否 | 铜×35 | 铜×1100 喵 |
| scatter | turret | 否 | 铜×85 铅×45 | 铜×2830 铅×1430 喵 |
| fuse | scatter | 否 | 铜×225 石墨×225 钍×100 | 铜×8220 石墨×8220 硅×3380 喵 |
| arc | turret | 否 | 铜×50 铅×50 | 铜×1600 铅×1600 喵 |
| unit_factory（ground-factory） | core | 否 | 铜×50 铅×120 硅×80（mult 0.5） | 铜×800 铅×2060 硅×1330 喵 |
| elevator | core | 否 | 铜×3（原创，取小配方） | 铜×130 喵 |

树结构（缩进=父子关系）喵：
```
core
├─ conveyor(默认)  router(默认)  drill(默认)  power_node(默认)
│   └─ battery
├─ combustion_generator(默认)
├─ graphite_press
├─ turret
│   ├─ scatter ─ fuse
│   └─ arc
├─ unit_factory
├─ elevator
└─ power_source(默认)  item_source(默认)
```

## 七、编译状态与风险喵
- `./gradlew compileJava` **通过**（仅既有 deprecation 警告，无新错误）喵。
- 风险 1：研究数值较大（数千铜）为忠实 Mindustry；若觉过肝，B 组可加全局倍率 config 喵。
- 风险 2：门控只拦 `EntityPlaceEvent`（anchor 格）；fill 格经 `setBlockAndUpdate` 不触发该事件但同 block，直接 setblock 也会被同 block 检查拦喵。
- 风险 3：多人客户端当前不知解锁状态（同步在 B 组），但门控服务端权威，未解锁建筑仍禁放喵。
- 风险 4：研究进度按世界存档，新世界重置；跨维度统一走 overworld 喵。
