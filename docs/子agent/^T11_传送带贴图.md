# T11 传送带贴图 完善 产出喵

## 目标喵
以 Mindustry 原版 blend 帧为基准，为 Blockdustry 传送带五类贴图（straight/corner/t/cross/none）合成正确的帧动画贴图，修正 T1 指出的映射错位，并核对带面高度后确定贴图内容喵。

## 来源喵
- 参考图已由协调者就位：`D:\Blockdustry\像素图片绘制尝试\物流\传送带\conveyor-{0-4}-{0-3}.png`，共 20 个 32×32 RGBA 文件喵。
- 与 Mindustry 原版 `D:\Blockdustry\Mindustry\core\assets-raw\sprites\blocks\distribution\conveyors\` 逐像素比对 diff=0，确认完全一致，直接以参考图为源喵。
- 复用方式：每类 MC 贴图 = 对应 blend 的 4 帧按 0→1→2→3 从上到下竖排成 32×128，与原 mcmeta `frames:[0,1,2,3]` 一一对应喵。

## 映射修正喵
按 T1 研究结论核对现有贴图（逐像素比对），确认错位项并修正喵：

| MC 贴图 | 修正前 blend | 修正后 blend | 说明 |
|---|---|---|---|
| conveyor_straight | 0 | 0 | 直线/孤立 ✓（内容未变） |
| conveyor_corner | 2（T 型，错） | **1** | 标准 90° 转角，带面触及左缘+底缘喵 |
| conveyor_t | 4（S 形弯带，错） | **2** | 前+后+一侧 的 T 型，带面全内缩喵 |
| conveyor_cross | 3 | 3 | 十字/全向 ✓（内容未变） |
| conveyor_none | 0 | 0 | 孤立（同直线贴图）✓（内容未变） |

- 结论：`conveyor_corner.png`、`conveyor_t.png` 两个文件内容被替换；straight/cross/none 重生成后字节未变（原就正确）喵。
- 不改 Java/模型 JSON/blockstates：本轮只换贴图与 mcmeta 喵。

## 高度处理喵
- 核对 `models/block/conveyor_*.json`：五个模型结构完全一致，只有一个元素 `from[0,0,0] to[16,4,16]`（高 4px 底座），`up` 面（UV 0,0,16,16）贴 `#belt`，其余面贴 `minecraft:block/stone`。**当前模型没有独立的「带面层（y2~6）」元素**，带面就是底座顶面 y=4 的整面平面喵。
- 据此确定贴图内容：直接整面使用原版俯视帧即可正确表达带面在方块顶部的视觉高度/厚度，无需再加工——
  - 原版帧本身是「完整方块 + 带面在顶」的俯视结构：带面为内缩的暗色条带，四周有浅色金属框，条带内有横纹（滚轴/板节），明暗层次天然给出带面「凸起在方块上」的立体感，不是平面贴纸喵。
  - corner（conveyor-1）带面触及左缘/底缘，能自然衔接相邻格；其在左下角有 36 个透明像素（弧形切角），属原版设计，能强化「带面是独立凸起物」的观感，保留不动喵。
  - 已知限制（非本任务范围，T1 问题 5/6 之外）：直线带面内缩，相邻直线格之间带面不跨格连续（需模型/逻辑改造才能加 connector）；左/右转镜像因 MC 模型 JSON 不支持贴图翻转而无法区分喵。
- 若日后要让带面真正高于底座，需在模型 JSON 增「带面层」元素，属模型改造，本任务按约束不动模型喵。

## mcmeta 动画喵
- 保留 `animation.frames:[0,1,2,3]`，`frametime` 由 2 调整为 **3**（任务允许 2~3）喵。
- 依据 T1 校准：Mindustry 帧循环≈10.87 刻/循环；`frametime=3` → 4×3=12 刻/循环，最接近且能较好对齐带面花纹与物品移动速度；`frametime=2`（8 刻/循环）偏快约 26% 喵。
- 五类贴图 mcmeta 统一改为 `{"animation":{"frametime":3,"frames":[0,1,2,3]}}` 喵。
