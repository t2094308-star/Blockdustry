# T1 传送带转角 探索产出喵

## 目标喵
深度探索 Mindustry 传送带转角（corner）的贴图与动画机制，为 Blockdustry 的传送带转角动画化提供依据与疑似问题清单喵。

## 结论/产出喵

### 一、Mindustry 转角贴图与动画机制喵

**1. 贴图文件与 blend 类型喵**
- 贴图位于 `core/assets-raw/sprites/blocks/distribution/conveyors/conveyor-{0-4}-{0-3}.png`，共 5 种 blend 类型 × 4 个动画帧，每帧 32×32 喵。
- `Conveyor.java` 用 `@Load(value = "@-#1-#2", lengths = {7, 4})` 加载为 `TextureRegion[7][4]`，但实际只有 blend 0-4，运行时 `blendbits` 只取 0-4，索引 5/6 从不使用喵。
- **转角不是单独一种贴图**：Mindustry 的拐角由「主贴图 + 向邻格延伸的半个贴图（connector）」组合渲染喵。

**2. blend 类型与连接语义映射（关键）喵**

`Autotiler.buildBlending` 的 `num` 计算（检查方向：dir0=前方不参与 num，dir1=左，dir2=后，dir3=右），经 `transformCase` 得到 `bits[0]`（blendbits）与 Y 翻转喵：

| num | 实际连接集合 | Mindustry 贴图 | 用途/形状 |
|---|---|---|---|
| -1 | 仅前，或 前+后（直线） | conveyor-0 | 直线/孤立（hourglass 带，带面全内缩） |
| 4 | 前+左 | conveyor-1（Y 翻转） | 90° 左转（带面触及左缘与底缘） |
| 5 | 前+右 | conveyor-1 | 90° 右转 |
| 2 | 前+后+左（T 缺右） | conveyor-2 | T 型（带面全内缩，两条带汇合） |
| 3 | 前+后+右（T 缺左） | conveyor-2（Y 翻转） | T 型镜像 |
| 0 | 前+后+左+右（十字） | conveyor-3 | 十字/全向 |
| 1 | 前+左+右（T 缺后） | conveyor-4 | S 形弯带（特殊 T） |

- **结论：标准的 90° 转角（带从一侧进、从前方出）在 Mindustry 用的是 conveyor-1，不是 conveyor-2**。conveyor-1 的带面唯一触及贴图边缘（左缘+底缘），转角带面能与相邻格自然衔接喵。
- conveyor-2 实为「前+后+一侧」的 T 型贴图，带面完全内缩，不与任何边缘相接喵。
- 镜像转角（左转 vs 右转）通过 `blendsclY = -1`（垂直翻转）区分，Mindustry 没有独立镜像贴图喵。

**3. 动画机制喵**
- 渲染代码：`Draw.rect(regions[blendbits][frame], x, y, tilesize*blendsclx, tilesize*blendscly, rotation*90)`，所有 blend 类型共用同一帧逻辑，转角不例外喵。
- 帧选择：`frame = enabled && clogHeat <= 0.5f ? (int)((Time.time * speed * 8f * timeScale * efficiency) % 4) : 0`。conveyor `speed = 0.046`，故帧以 `0.368/刻` 推进，约 `2.72 刻/帧`（≈45ms），循环周期约 `10.87 刻`（0.18s）喵。
- 转角 4 帧的差异覆盖整个带面（帧间像素差 bbox 覆盖 x[0,31] y[4,31]），说明动画是沿曲线的带面花纹流动，不是整块平移喵。
- 堵塞（clogHeat>0.5）或未启用时 frame 固定为 0（动画停）；过载/时间加速（efficiency/timeScale）会改变帧速喵。

### 二、MC 现有实现状态喵

**1. 贴图（全部 32×128 = 4 帧竖条，且都带 mcmeta 动画）喵**

| MC 贴图文件 | 逐像素比对结果 | 说明 |
|---|---|---|
| conveyor_corner.png | = Mindustry conveyor-2（4 帧全部 diff=0） | 转角用了 T 型贴图，**错** |
| conveyor_cross.png | = Mindustry conveyor-3（4 帧全部 diff=0） | 十字 ✓ |
| conveyor_none.png | = Mindustry conveyor-0（4 帧全部 diff=0） | 孤立 ✓ |
| conveyor_straight.png | = Mindustry conveyor-0（与 none 完全相同） | 直线 ✓（但缺 connector，见问题清单） |
| conveyor_t.png | = Mindustry conveyor-4（4 帧全部 diff=0） | T 用了 S 形弯带贴图，**错** |

- 所有 `.png.mcmeta` 均为 `{"animation":{"frametime":2,"frames":[0,1,2,3]}}`，转角贴图**本身已是帧动画**，并非纯静态喵。

**2. 模型喵**
- `models/block/conveyor_*.json` 全部为「全宽底座 0-4 高 + 顶面带材 + 侧面 stone」，5 个模型结构完全一致，仅 `#belt` 贴图不同喵。
- `blockstates/conveyor.json` 含 `corner(9) × facing(4) × conn(5)` 共 180 个变体，但 1×1 传送带 `cornerFor(0,0,1)=NW`，实际只有 `corner=nw` 的 20 个变体可达，其余 160 个是死变体喵。
- 转角只有一套模型 + 按 `facing` 的 y 旋转，**无法表达左转/右转镜像**，也无法区分前+侧 与 后+侧 两种拐角喵。

**3. 方块逻辑喵**
- `ConveyorBlock.computeConnection` 把 4 向连接归并为 NONE/STRAIGHT/CORNER/T/CROSS 五类，丢失了「哪一侧连接」的信息，故模型层无法正确选贴图喵。
- `connects` 判定 `myFacing == dir || nFacing == dir.getOpposite()` 是 Mindustry `lookingAtEither` 的简化，与 blend 语义大体一致喵。
- `ConveyorBlockEntity.SPEED = 0.046`（格/MC 刻），但 Mindustry 是 0.046 格/游戏刻（60 刻/秒），MC 物品实际移动速度约为 Mindustry 的 1/3（0.92 vs 2.76 格/秒），是既有逻辑问题，非本任务范围喵。

### 三、转角动画化可行性喵

- **可行**：MC 方块模型贴图帧动画（mcmeta）与 Mindustry 的 4 帧循环天然同构，`frames:[0,1,2,3]` 的顺序与 Mindustry `% 4` 递增一致，直接映射即可喵。
- 局限：MC 的 mcmeta 是**全局固定帧速**，无法反映 Mindustry 的堵塞停帧（clogHeat）与效率加速（efficiency/timeScale）喵。
- 帧速建议：Mindustry 帧周期≈10.87 刻/循环（0.18s）。MC 端若按「带面花纹与物品移动同步（花纹周期 0.5 格）」校准，`frametime=3` 最接近（4×3=12 刻/循环）；当前 `frametime=2`（8 刻/循环）偏快约 26% 喵。若按真实时间对齐，则 `frametime=1`（4 刻/循环）更近，二者取一需人工按视觉效果定喵。
- 镜像：MC 方块模型 JSON **不支持贴图翻转**，左/右转镜像需额外生成一张水平翻转（或垂直翻转）的贴图与对应模型喵。

### 四、疑似问题清单（供人工排查）喵

1. **转角贴图用错**：`conveyor_corner.png` 用了 Mindustry conveyor-2（T 型），标准 90° 转角应为 conveyor-1（带面触及边缘的直角弯）。这是「转角不理想」的最可能根因喵。
2. **T 型贴图用错**：`conveyor_t.png` 用了 Mindustry conveyor-4（S 形弯带），T（前+后+一侧）应为 conveyor-2（或其镜像）喵。
3. **镜像缺失**：转角左转/右转、T 的两种镜像在 MC 中无法表达，全部用同一模型+y 旋转渲染，至少一半朝向曲线方向错误喵。
4. **blockstate 缺侧向信息**：`conn=corner` 未记录「连的是左还是右/前还是后」，模型层无法区分多种拐角子形态；需扩展状态属性（或拆分 conn）喵。
5. **直线缺 connector 衔接**：Mindustry 直线靠「向邻格画 conveyor-0 半贴图」实现带面跨格连续；MC 每格独立整格贴图，直线带面内缩、相邻格之间有浅色边框断裂感（用户未提但属同类问题）喵。
6. **动画帧速偏差**：mcmeta frametime=2 与 Mindustry 的 ~3 不符，转角/直线带面花纹与物品流速视觉不同步喵。
7. **死变体**：blockstate 中 `corner=n/n/ne/w/c/e/sw/s/se` 共 160 个变体对 1×1 传送带不可达，冗余但无害喵。
8. **旋转方向映射未验证**：blockstate 的 `facing→y` 映射（north→270, east→0, south→90, west→180）是否让带面方向正确需进游戏目测确认（本次纯静态分析无法定论）喵。
