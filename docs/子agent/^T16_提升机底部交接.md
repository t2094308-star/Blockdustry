# T16 提升机底部贴图与顶部交接修复喵

## 一、结论（TL;DR）喵

- **问题一（底部贴图缺失/黑紫）**：根因是 `models/block/elevator.json` 的 **down 面与内侧面复用了 `conveyor_none`（32×128 动画贴图，带 mcmeta）**，而全工程只有提升机把这张动画贴图用在 down/内侧面（其他方块 down 面全用静态贴图），动画贴图 + down 面 UV 旋转采样异常 → 黑紫喵。修复：down 面与内侧面改用静态 `#side`（`conveyor_side`），up 面保留 `#post`（与传送带顶面同款，可正常渲染）喵。
- **问题二（顶部无法运送到传送带）**：根因是提升机顶格只把物品交给正上方 sink；若上方是传送带，`ConveyorBlockEntity.acceptItem` 的 `directionOf` 只查水平四邻，来自下方的提升机被拒收 → 顶格卡死喵。修复：顶格交接失败时**复用基类 `dumpItem(Item)` 水平 dump 给相邻（四邻）传送带/建筑**，物品即可从顶部运出喵。
- 两处修复均已通过 `./gradlew compileJava`（BUILD SUCCESSFUL，仅 2 条既有 EventBusSubscriber 过时警告）喵。

## 二、问题一：提升器底部贴图缺失/黑紫喵

### 2.1 排查喵

| 排查项 | 结论 |
| --- | --- |
| `blockstates/elevator.json` corner 键 | 9 个 variant 均为 `corner=nw`…`corner=se` 形式，**不是裸键**，全部覆盖 Corner 枚举，无未定义 variant 喵 |
| down 面引用什么贴图 | 引用 `#post` → `blockdustry:block/conveyor_none`，该 PNG **存在**且完全不透明（32×128）喵 |
| 贴图资源 | `conveyor_none.png`/`conveyor_side.png` 均在，且 build 产物与源一致喵 |
| 对比全工程 | **只有 `elevator.json` 在 down/内侧面用 `conveyor_none`（动画贴图）**；其余方块 down 面全部用静态贴图（`conveyor_side`/`turret_side`/`power_node`/`stone`）且不带 cullface 喵 |

### 2.2 根因喵

`conveyor_none.png` 是 **32×128 动画贴图**（`conveyor_none.png.mcmeta` 声明 4 帧）。方块模型 face 的 UV `[0,0,16,16]` 在 32 宽贴图上映射整条动画竖条；down 面在 `FaceBakery` 里又有 UV 旋转，动画 V 偏移与旋转叠加后采样越界 → 黑紫（缺失贴图棋盘格）喵。传送带只在 **up 面（顶面/带面）** 用 `#belt`（conveyor_none），down/侧面全用静态 `#side`，所以只有提升机踩中这个坑喵。

### 2.3 修复喵

文件：`src/main/resources/assets/blockdustry/models/block/elevator.json`

- down 面：`"texture": "#post"` → `"texture": "#side"`（静态 `conveyor_side`，与传送带 down 面同款）喵。
- 内侧面（朝竖管中心的面，south/east/north/west 中无 cullface 的 8 处）：`"texture": "#post"` → `"texture": "#side"`，竖管内壁与外侧同为金属质感喵。
- up 面（顶缘）：**保留 `#post`**（与传送带顶面同为 `conveyor_none` 动画带，up 面旋转与传送带一致，可正常渲染）喵。
- cullface 保留（地面/下方有实心块时 down 面正常剔除，避免与地面顶面 z-fighting）喵。

修复后任意面都不再踩「动画贴图用在不兼容面」的坑，底部显示为静态金属色而非黑紫喵。

## 三、问题二：物品到顶后无法运送到传送带喵

### 3.1 排查喵

`ElevatorBlockEntity.tickAnchor()` 顶格交接：

```java
BlockEntity frontBe = level.getBlockEntity(worldPosition.above());
BlockdustryItemSink frontSink = frontBe instanceof BlockdustryItemSink s ? s : null;
boolean headCanExit = frontSink != null && frontSink.acceptItem(this, item);
```

- 顶部是另一节提升机 / Router / 机器（基类不查方向）→ `acceptItem` 通过，正常交接喵。
- 顶部是**传送带** → `ConveyorBlockEntity.directionOf` **只扫水平四邻**，`source.getPos()`（提升机）在 `.below()` → 返回 null → 拒收 → `headCanExit=false`，顶格停在 0.95 永不交接（T14 已知限制 1）喵。

### 3.2 修复喵

文件：`src/main/java/com/blockdustry/building/ElevatorBlockEntity.java`

顶格交接失败（上方不可收 / 交接瞬间失败）时，复用基类四邻域 `dumpItem(Item)` 把物品水平递给相邻传送带/建筑喵：

```java
if (headCanExit && progress[0] >= 1.0f
        && frontSink.acceptItem(this, item)
        && frontSink.handleItem(this, item)) {
    items[0] = null;
    progress[0] = 0f;
} else if (!headCanExit && progress[0] >= NEXT_MAX_BLOCKED && dumpItem(item)) {
    // 上方不可收（如顶部是传送带：directionOf 只查水平邻接拒收）→ 水平 dump 给四邻喵
    items[0] = null;
    progress[0] = 0f;
}
```

- 行为不变：上方是提升机/Router/机器时仍优先垂直交接喵。
- 新增：`!headCanExit` 保证「上方可收时绝不在上升途中横甩」，仅当上方被堵（含传送带）且顶格到顶（≥0.95）后 `dumpItem` 扫水平四邻，传送带朝向合理即可收件，物品从顶部运出喵。
- `dumpItem` 对 size=1 的提升机候选为四邻，source 取提升机自身 BE，传送带 `directionOf` 判水平邻居通过；成功即 `handleItem` 真实移交，随后清空本格槽，无复制/丢失喵。
