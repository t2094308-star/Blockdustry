## 二、问题清单喵

### 1.【高】instantTransfer 判定集合与 Mindustry 不符，存在 sorter↔gate 同步递归卡死风险喵

- **位置**：`GateBlockEntity.isInstant()`（L44-46）= `RouterBlockEntity || GateBlockEntity`；`SorterBlockEntity.resolveTarget/canSideReceive`（L87/L109）仅判 `SorterBlockEntity`喵。
- **原版**：Mindustry 仅 `Sorter` 与 `OverflowGate` 置 `instantTransfer=true`，`Router` **不是** instantTransfer（已 grep 全仓库核实；Router.updateTile 靠 `instanceof Router` 特判正是因为它非 instantTransfer）喵。
- **偏差后果**：
  - (a) 门闸把 Router 当瞬时块 → 阻断了 Mindustry 允许的 router→gate 直通，强制门闸改走侧向，路由行为偏差喵。
  - (b) 分拣器与门闸互不把对方当瞬时块 → sorter 直通判定 `isSorter(source)` 拦不住「源是门闸」、门闸 `isInstant` 不含 Sorter → **sorter 与 gate 对脸直连（无传送带中转）时，acceptItem/handleItem 会同步递归**：conveyor→sorter→gate→sorter→…，同一 tick 内无限往返 → StackOverflow / 服务端卡死喵（Mindustry 用 `isSame` 双方瞬时即拒收，不会发生）喵。
- **建议修复**：统一瞬时谓词 = `SorterBlockEntity || GateBlockEntity`（排除 Router），在 GateBlockEntity 与 SorterBlockEntity 两处共用同一 helper；且 Sorter 直通/侧向检查改为「源与目标皆瞬时」才拒收（对齐 Mindustry `isSame` 语义），并在 `acceptItem` 里加递归深度/已转移计数兜底更稳喵。

### 2.【低/信息】科技树 parent 与原版树不同（按计划有意为之，非缺陷）喵

- Mindustry SerpuloTechTree：`distributor→router`、`overflowGate→sorter`、`underflowGate→overflowGate`（conveyor→junction→router）喵。
- 本实现按简报/整合清单：distributor→conveyor、两 gate→router、junction→conveyor、sorter→router、inverted_sorter→sorter 喵。
- 判定：**与任务简报一致（✓ 挂载正确）**，但与 Mindustry 原版树不同，仅记录备查（若后续追求与原版树一致需改 parent）喵。

### 3.【信息】其余无问题项喵

- lang `block.blockdustry.elevator` 键在中英文件各出现 2 次（历史遗留，非本批引入；JSON 合法，last-wins）喵。
- distributor 顶部旋转箭头动画未做（A1 清单已声明为可选增强，先机制）喵。

## 四、修复记录（A2 整改，2026-08-14）喵

> 针对 §二.1 高严重度问题「瞬时块判定集合与 Mindustry 不符」的整改喵。

### 1. 统一瞬时谓词 = Sorter | Gate（排除 Router）喵
- 新增 `src/main/java/com/blockdustry/logistics/LogisticsUtil.java`：`isInstant(Object)` = `instanceof SorterBlockEntity || instanceof GateBlockEntity`（兼容 BlockEntity / ItemSink / ItemSource 接口）；另含瞬时链递归深度兜底 `enterTransfer/exitTransfer`（ThreadLocal 深度，上限 16）喵。
- 已核实 Mindustry 原版：仅 `Sorter`（Sorter.java L28）与 `OverflowGate`（OverflowGate.java L22，overflow/underflow 共用基类）置 `instantTransfer=true`；`Router` 不是（Router.java L64 用 `instanceof Router` 特判正因它非 instantTransfer）喵。

### 2. 两处共用改判喵
- `GateBlockEntity`：删除私有 `isInstant`（原含 Router、漏 Sorter），改用 `LogisticsUtil.isInstant`；直通/两侧分支 `!(fromInst && isInstant(to/a/b))` 语义不变，现在正确覆盖 sorter↔gate 喵。
- `SorterBlockEntity`：删除私有 `isSorter/isSorterAt`（原只防 Sorter↔Sorter），直通防三连环与侧向判定改为 `LogisticsUtil.isInstant(source) && LogisticsUtil.isInstant(target)`（对齐 Mindustry `isSame` = 双方 instantTransfer 才拒收）喵。

### 3. 递归深度兜底喵
- `SorterBlockEntity` 与 `GateBlockEntity` 的 `acceptItem/handleItem` 入口加 `LogisticsUtil.enterTransfer()`，超限即返回 false（拒收），finally 释放；即使谓词漏判也能安全终止递归，杜绝 StackOverflow/服务端卡死喵。

### 4. 效果验证喵
- 修复 router→gate 直通被误阻（Router 不再视为瞬时，门闸正向可收 Router 来料）喵。
- sorter↔gate 对脸直连（无传送带中转）：双方瞬时谓词一致 → 直通/侧向均按「源+目标皆瞬时」拒收 → 不再同步递归喵。
- `./gradlew compileJava` 通过（无错误，仅既有 EventBusSubscriber.bus 弃用警告）喵。
