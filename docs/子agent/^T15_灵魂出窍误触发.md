# T15 灵魂出窍误触发排查（双击左键启动 freecam）喵

## 一、结论摘要喵

`FreecamHandler` 的切换逻辑**本身没有把攻击键当切换键**，F4/键盘键绑定下左键不可能触发 freecam 喵。
真正会让「左键/双击左键启动灵魂出窍」的场景是：**灵魂出窍被（误）绑定到了鼠标左键（攻击）或右键（使用）**——
此时点击左键会命中 `KeyMapping.click`，`consumeClick()` 在下一 tick 把 freecam 切换开启，用户第二下点击又会被 freecam 的交互屏蔽吃掉，症状即「双击左键启动灵魂出窍」喵。

已修复：`FreecamHandler` 增加防御，绑定为鼠标左/右键时**吞掉点击、绝不切换**，并提示一次喵。

## 二、排查过程与证据喵

### 2.1 按键定义与注册（正确）喵
- `client/freecam/FreecamHandler.java`：`KEY_FREECAM = new KeyMapping("key.blockdustry.freecam", KEYSYM, InputConstants.KEY_F4, "key.categories.blockdustry")` 喵。
- 1.21.1 反编译 `InputConstants.java`：`KEY_F4 = 293`（GLFW 标准值），`key.keyboard.f4` 也映射到 293，定义正确喵。
- `BlockdustryClient.registerKeyMappings(RegisterKeyMappingsEvent)` 注册该按键，`lang/zh_cn.json` 有 `key.blockdustry.freecam = 灵魂出窍`，无缺失喵。
- **实际绑定**：`run/client/options.txt` 第 129 行 `key_key.blockdustry.freecam:key.keyboard.c`——用户已把 F4 改成 **C 键**（仍是键盘键，不是鼠标）喵。

### 2.2 切换逻辑（正确）喵
- 切换在 `ClientTickEvent.Post`：`while (KEY_FREECAM.consumeClick()) setActive(!active, mc)`，只响应 `key.blockdustry.freecam` 的点击喵。
- `consumeClick()` 依赖 `clickCount`，只由 `KeyMapping.click(key)` 自增喵。
- `KeyMapping.click` 走 NeoForge `KeyMappingLookup.getAll(key)`，最终 `Map<InputConstants.Key, Collection<KeyMapping>>.get(keyCode)` 用 `InputConstants.Key.equals`（**type + value 同时比较**）精确匹配喵。
- 鼠标左键 = `(MOUSE, 0)`，C = `(KEYSYM, 67)`，F4 = `(KEYSYM, 293)`，三者互不等——**键盘键绑定下左键点击永远不可能给 freecam 累加 clickCount** 喵。

### 2.3 事件/交互路径（正确）喵
- 全仓仅此一个 `KeyMapping`（`KEY_FREECAM`），无其它鼠标键绑定、无双击检测代码喵。
- `FreecamMixinEntity`（turn 重定向）、`FreecamMixinLocalPlayer`（冻结输入）、`FreecamMixinMultiPlayerGameMode`（屏蔽交互）、`FreecamMixinGameRenderer/Camera/Gui` 全部仅在 `FreecamHandler.isActive()` 为真时生效，**没有任何触发开关的动作**喵。
- `FreecamHandler.onInteraction` / `TurretPossessHandler.onInteraction` 在激活态只 `setCanceled(true)` 屏蔽攻击/使用，不切换喵。
- 唯一能进入 `setActive(true)` 的入口就是 freecam 按键点击喵。

### 2.4 运行日志喵
- `tools/.game_log.txt`、`run/client/logs/debug.log`、`latest.log`：freecam mixin 全部正常加载，无 keybinding 冲突警告、无 freecam 相关异常喵。
- 6 个 crash-report 均为渲染/注册崩溃（PowerNode/Drill/Bullet/TeamScreen/RegisterEvent），与 freecam 无关喵。

### 2.5 根因判定喵
- 按键系统层面键盘键绑定下左键无法误触发，代码逻辑无直接 bug 喵。
- 唯一可复现「左键点击→freecam 开启」的路径就是 **freecam 绑定被设为鼠标左/右**（用户大概率在按键绑定界面「按任意键」提示时误点了鼠标左键，把绑定写成了 `key.mouse.left`，症状与「首击切换、次击被屏蔽」完全吻合）喵。
- 当前 `options.txt` 已改回 C，但防复发仍需加防御喵。

## 三、修复内容喵

文件：`src/main/java/com/blockdustry/client/freecam/FreecamHandler.java`

1. 新增 `isBoundToAttackOrUse()`：当 `KEY_FREECAM.getKey()` 是 `Type.MOUSE` 且 value 为 `MOUSE_BUTTON_LEFT`（0）或 `MOUSE_BUTTON_RIGHT`（1）时返回 true 喵。
2. `onClientTick` 切换处：若绑定为攻击/使用键，则**吞掉全部 `consumeClick()`、绝不调用 `setActive`**，并向玩家提示一次「灵魂出窍：请勿绑定到攻击/使用键（默认 F4）」喵。
3. 效果：绑定 C/F4 等键盘键时行为不变；即使误绑到鼠标左/右键，左键/双击左键也**永远不触发 freecam**，且给出一句提示引导改键喵。

```java
// 防御：freecam 若被（误）绑定到攻击键（鼠标左）或使用键（鼠标右），
// 左键/双击左键会因 KeyMapping.click 命中而触发切换，这里强制禁止喵
private static boolean isBoundToAttackOrUse() {
    InputConstants.Key key = KEY_FREECAM.getKey();
    if (key.getType() != InputConstants.Type.MOUSE) return false;
    int v = key.getValue();
    return v == InputConstants.MOUSE_BUTTON_LEFT || v == InputConstants.MOUSE_BUTTON_RIGHT;
}
```

```java
// 快捷键切换喵
if (isBoundToAttackOrUse()) {
    // 绑定被误设为攻击/使用键（鼠标左/右）：吞掉点击、绝不切换，
    // 保证「左键/双击左键」永远不触发 freecam，并提示一次喵
    while (KEY_FREECAM.consumeClick()) {}
    if (!invalidBindingWarned && mc.player != null) {
        invalidBindingWarned = true;
        mc.player.displayClientMessage(
                Component.literal("灵魂出窍：请勿绑定到攻击/使用键（默认 F4）"), true);
    }
} else {
    while (KEY_FREECAM.consumeClick()) {
        setActive(!active, mc);
    }
}
```

## 四、验证喵

- `./gradlew compileJava`：BUILD SUCCESSFUL，退出码 0 喵。
- 行为核对：
  - 默认 F4 / 现绑定 C（键盘）→ 按 F4/C 切换正常，左键点击不触发（按键系统精确匹配，无法命中）喵。
  - 误绑到鼠标左/右 → 点击被吞掉、freecam 不开启，提示一次引导改键喵。

## 五、遗留/可选建议喵

- `setActive` 的提示文案写死「F4 关闭」，用户改键后不准确；如需可改成 `KEY_FREECAM.getTranslatedKeyMessage()` 动态显示（本次未改，避免扩大改动面）喵。
- 若想更进一步，可在按键绑定界面拦截「把 freecam 设为鼠标左/右」的操作并拒绝，但需 hook 选项界面按键处理，改动面较大，本次未做喵。
