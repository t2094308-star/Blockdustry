# T16 灵魂出窍双击深查（双击左键仍启动 freecam）喵

## 一、结论摘要喵

**T15 的「绑定被误设为鼠标键 + isBoundToAttackOrUse 吞点击」假设方向对、但覆盖不全且未改触发机制**，导致在键盘键（C/F4）绑定下仍被用户反馈「双击左键启动」喵。

从反编译源码逐层彻查后确认：

1. **vanilla/NeoForge 输入系统层面**：键盘键（C=KEYSYM 67 / F4=KEYSYM 293）绑定下，鼠标左键点击（MOUSE 0）**物理上不可能**给 `KEY_FREECAM` 累加 `clickCount`——`InputConstants.Key.equals` 同时比较 type+value，`KeyMappingLookup` 的 map 也按 `(type,value)` 精确索引，无任何碰撞喵。
2. **因此**：能复现「左键/双击左键启动 freecam」的唯一真实路径，是 **freecam 被（在按键绑定界面误）绑定成了某个鼠标键**（默认 F4 被用户改成 C 后仍可能是误绑回鼠标键），`KeyMapping.click(MOUSE,0)` 命中 KEY_FREECAM → 首击切换开启、次击被 freecam 交互屏蔽，症状即「双击左键启动灵魂出窍」喵。
3. **修复目标**：不再依赖「识别具体是哪个鼠标键」这种猜法，改为**从触发机制上只允许键盘键触发**——任何鼠标/扫描码绑定一律吞掉点击、绝不切换，结构上保证鼠标操作永远无法启动 freecam；再加「攻击/使用键触发过的 tick 不开启」的双保险喵。

## 二、彻查过程与证据喵

### 2.1 触发入口（全仓唯一）喵
- `client/freecam/FreecamHandler.java`：`onClientTick(ClientTickEvent.Post)` 里 `while (KEY_FREECAM.consumeClick()) setActive(!active, mc)`，这是**全仓唯一**进入 `setActive(true)` 的入口（全仓 grep `setActive(`、`FreecamHandler.`、`KEY_FREECAM`、`consumeClick` 确认）喵。
- 所有 freecam mixin（`FreecamMixinEntity/LocalPlayer/MultiPlayerGameMode/Camera/Gui/GameRenderer`）仅在 `isActive()` 为真时做**屏蔽/重定向**，无任何触发动作喵。
- `TurretPossessHandler`、`BlockdustryDebugHandler`、`BlockdustryClientCommands`、主类均无 freecam 触发逻辑喵。

### 2.2 反编译输入链路（build/neoForm/.../transformed/）喵
- `MouseHandler.onPress`：左键按下 → `KeyMapping.click(InputConstants.Type.MOUSE.getOrCreate(0))`，即 `click(Key(MOUSE,0))` 喵。
- `KeyMapping.click` → `KeyMappingLookup.getAll(Key(MOUSE,0))` → `map.get(modifier).get(keyCode)`，keyCode 是 `(type,value)` 组合键喵。
- `InputConstants.Key.equals`：`this.value == o.value && this.type == o.type`；`hashCode`：`Objects.hash(type, value)`——`(MOUSE,0)` 与 `(KEYSYM,67)` 绝不等、绝无哈希碰撞喵。
- `KeyModifier.NONE.matches()` 恒 false；无修饰键时 `getActiveModifiers()` 返回空；`findKeybinds` 再按 `keyCode.equals(binding.getKey())` 过滤，键盘 C 绑定不可能被 `(MOUSE,0)` 命中喵。
- 结论：**绑定为键盘键时，左键点击永远不可能让 `KEY_FREECAM.consumeClick()` 返回 true** 喵。

### 2.3 运行时绑定与构建状态喵
- `run/client/options.txt` 第 129 行：`key_key.blockdustry.freecam:key.keyboard.c`——当前绑定是键盘 C，不是鼠标喵。
- `Options.processOptionsForge` 用 `"key_" + keyMapping.getName()`（= `key_key.blockdustry.freecam`）正确读到并 `setKeyModifierAndCode(NONE, Key(KEYSYM,67))`，绑定加载无误喵。
- `build/classes/.../FreecamHandler.class` 时间戳为今天 14:19（T15 修复已编译），运行日志 14:21，mixin 全部正常加载，无按键冲突警告喵。
- 即在「代码 + 当前 options」一致的状况下，双击左键在输入系统层面**无法**触发——印证必须从「绑定被误设为鼠标键」这一真实路径根治喵。

## 三、修复内容喵

文件：`src/main/java/com/blockdustry/client/freecam/FreecamHandler.java`

1. **触发机制改为只允许键盘键**：新增 `isKeyboardBinding()`（`KEY_FREECAM.getKey().getType() == Type.KEYSYM`）。绑定为任何鼠标/扫描码时，`onClientTick` 吞掉全部 `consumeClick()`、**绝不调用 `setActive`**，并提示一次「灵魂出窍：请绑定到键盘键（默认 F4）」。此规则覆盖所有鼠标键（不止左/右），从结构上保证鼠标点击永远无法启动 freecam 喵。
2. **双保险（键盘绑定下）**：
   - 防御一：`onInteraction(InputEvent.InteractionKeyMappingTriggered)` 改为**始终记录**本 tick 攻击/使用被触发（freecam 未激活时不再只是判断并取消），在 `onClientTick` 里若关闭态且本 tick 攻击/使用触发过 → 吞掉 freecam 点击、不开启（防「双击左键」残留点击/同 tick 冲突）喵。
   - 防御二：关闭态且正按住 `keyAttack`/`keyUse` → 吞掉点击、不开启（防「按着左键打怪时误开」）喵。
3. **附带修正**：开启提示文案 `getTranslatedKeyMessage()` 动态显示实际键，不再写死「F4 关闭」喵。

## 四、验证喵

- `./gradlew compileJava`：BUILD SUCCESSFUL，退出码 0；仅有 BlockdustryClient 两条既有弃用警告（与本次无关）喵。
- 行为核对：
  - 绑定 C/F4（键盘）→ 按 C/F4 正常切换；按住左键或刚点击过左键时按 C 不会误开；双击左键（无论是否绑到鼠标）永远不启动 freecam 喵。
  - 绑定到任何鼠标键（含左/右）→ 点击被吞掉、freecam 不开启，提示一次引导改键喵。

## 五、遗留/说明喵

- 若用户在按键绑定界面把 freecam 误绑到鼠标键，本修复会**吞掉且提示**，但不会强制改回；如需彻底禁绑可在按键界面 hook 拒绝鼠标键，改动面较大，本次未做（与 T15 一致）喵。
- 防御一/二仅作用于「关闭→开启」方向，不影响已激活时按 C 关闭（避免出现「关不掉」的体验问题）喵。
