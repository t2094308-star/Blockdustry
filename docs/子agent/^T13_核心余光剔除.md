# T13 核心余光失去渲染（视锥剔除）修复喵

## 现象喵

用户澄清：核心 3×3×3 视觉在「玩家背向核心」时消失，**不是背面 cull**，而是**余光问题**——核心在玩家视野边缘/余光中整颗不渲染，一旦视线偏转、立方体只部分在视野内就消失喵。

## 根因喵

BER（BlockEntityRenderer）的视锥剔除（frustum culling）基于 BE 的**渲染边界框**（render bounding box）判断喵。

- 核心整颗 3×3×3 立方体由**锚点格**（1×1×1）的 BE 绘制，锚点格默认渲染边界只有 1×1×1 喵。
- 玩家余光（视线方向偏转、立方体仅部分落在视锥内）时，LevelRenderer 拿锚点格那 1×1 的边界去和视锥求交，判定「BE 完全在视锥外」→ 整个 BER 不调用 render → 即使 3×3×3 立方体大部分在画面里也整颗消失喵。
- 之前 T8c 修的「背面 cull」是另一码事（quad 法线朝向导致背面被剔除），已用自建 NO_CULL 渲染类型 CORE_BASE_NO_CULL 解决；本次是**渲染包围盒太小导致视锥剔除**喵。

## 修复喵

NeoForge 的 `IBlockEntityRendererExtension` 提供 `getRenderBoundingBox(T be)`，在**渲染器上 override**（不是 BlockEntity 上；1.21.1 已移除 `BlockEntity.getRenderBoundingBox`，在 BE 上加会编译错「不覆盖超类型方法」喵）。

参考 `client/PowerNodeBlockEntityRenderer.java` 已有做法（它返回覆盖所有激光端点的 AABB），给 `client/CoreBlockEntityRenderer.java` 加同款 override 喵：

- 用 BE 的**锚点**（`be.hasAnchor() ? be.getAnchor() : be.getBlockPos()`，兼容单格/旧档）算边界喵。
- 立方体从锚点格本地坐标 0..3 画出，即世界坐标锚点 → 锚点+3；返回 `new AABB(anchor, anchor.offset(3,3,3))` 等价的双 double 构造的 AABB 喵。
- 再 `.inflate(2.0)` 留 2 格余量，余光/边缘视角也必然落在边界内，恒不被剔除喵。

```java
@Override
public AABB getRenderBoundingBox(CoreBlockEntity be) {
    BlockPos anchor = be.hasAnchor() ? be.getAnchor() : be.getBlockPos();
    BlockPos max = anchor.offset(3, 3, 3);
    return new AABB(anchor.getX(), anchor.getY(), anchor.getZ(),
            max.getX(), max.getY(), max.getZ()).inflate(2.0);
}
```

（注：此版本 `AABB(BlockPos, BlockPos)` 构造函数不存在，需用双 double 构造；`AABB.minmax`/`expandTowards` 亦可喵。）

## 验证喵

- `./gradlew compileJava` BUILD SUCCESSFUL（仅原有 EventBusSubscriber deprecation 警告）喵。
- 运行游戏预期：核心任意偏转视线、余光/背向时 3×3×3 立方体不再消失喵。
