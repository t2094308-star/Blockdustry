# T17 灵魂出窍 C 键双击左键深查（结构性闸门修复）喵

## 一、结论摘要喵

用户报告：freecam 绑到 **C 键** 时「双击左键」仍会触发；绑回默认 **F4** 则不触发喵。
本任务彻查后确认：

1. **输入系统层面铁律（再次验证）**：`KeyMapping.click(Key)` 只按 `(type,value)` 精确匹配；
   freecam 绑到键盘 C（`(KEYSYM,67)`）时，鼠标左键点击（`(MOUSE,0)`）**物理上不可能**
   给 freecam 累加 `clickCount`。`KeyMappingLookup` 的 map 按 `Key.equals`（type+value）精确索引，
   C 与 F4 在输入链路上完全等价，均不可能被鼠标点击命中（T15/T16 结论依旧成立）喵。
2. **C 与 F4 的真实差异在「物理/习惯」层**：C 是字母键、紧贴 WASD 下方（左手自然落区），
   且原版默认还被 `keySaveToolbarActivator`（保存工具栏）占用；F4 是远端功能键。
   用户「双击左键」时左手极易误触/按到 C，或在按键绑定界面误绑过鼠标键（T15 路径）喵。
3. **既有代码缺陷**：T16 的防御只在 `clickCount>0` 时判断「本 tick 攻击/使用」和「按住攻击键」。
   但双击左键的**两击间隙**（LMB 已松开、攻击事件已消费、`isDown()` 为 false）恰好能穿过
   两层防御——只要此时 freecam 有任意 clickCount（无论来自误触 C 还是任何污染源），
   就会被切换开启。**没有任何「必须是真实键盘按下」的结构性闸门**喵。

## 二、确定修复喵

文件：`src/main/java/com/blockdustry/client/freecam/FreecamHandler.java`

1. **结构性闸门（关键）**：新增 `@SubscribeEvent onKeyInput(InputEvent.Key)`。
   `InputEvent.Key` **只由 `KeyboardHandler`（真实键盘回调）发出**，鼠标事件走的是
   `InputEvent.MouseButton`，永远无法走到这里。只有「绑定键被真实物理按下」才置位
   `freecamKeyPressedThisTick`。切换时若该标志为 false → **一律吞掉 click、绝不切换**。
   从结构上保证：无论 `clickCount` 被什么污染（鼠标误路由、残留、脏点击），
   **鼠标操作永远不可能启动 freecam**。自动重复（按住）不置位，顺带修掉「按住键反复切换」喵。
2. **双击窗口防御**：记录 `lastAttackOrUseTick`（`onInteraction` 触发时写 `clientTickCounter+1`）。
   关闭状态下若最近 **6 tick（约 300ms）** 内攻击/使用触发过（覆盖双击左键的两击间隙）→ 吞掉、不开启喵。
3. **保留既有三层**：`isKeyboardBinding()`（鼠标/扫描码绑定直接禁）、
   本 tick 攻击/使用触发过 → 不开启、按住 `keyAttack`/`keyUse` → 不开启。
   「关闭→开启」方向全部加闸；「开启→关闭」方向不受影响（避免关不掉）喵。

## 三、逐层验证喵

- `./gradlew compileJava`：BUILD SUCCESSFUL，退出码 0；仅 BlockdustryClient 两条既有弃用警告，与本次无关喵。
- 输入链路（反编译源码复核）：
  - `KeyboardHandler.keyPress`：键盘按下 → `KeyMapping.click(InputConstants.getKey(key, scanCode))`
    → 行尾 `ClientHooks.onKeyInput(...)` 发 `InputEvent.Key`（按下=1、松开=0、重复=2）喵。
  - `MouseHandler.onPress`：鼠标按下 → `KeyMapping.click(Type.MOUSE.getOrCreate(button))`
    → 只发 `InputEvent.MouseButton`，**绝无 `InputEvent.Key`** 喵。
  - `runTick` 顺序：`runAllTasks`（输入回调）→ `handleKeybinds`（onInteraction）→
    `keyboardHandler.tick` → `fireClientTickPost`（onClientTick）。同 tick 内先置位、后消费，时序正确喵。
- 行为核对：
  - 绑定 C/F4（键盘）→ 按 C/F4 正常切换（真实键盘按下才切）喵。
  - 双击左键 + 期间误触 C → 窗口防御（6 tick）吞掉、不开 freecam 喵。
  - 双击左键、不按任何 freecam 键 → clickCount 恒 0 + `freecamKeyPressed` 恒 false，结构上不可能开喵。
  - 误绑鼠标左/右 → `isKeyboardBinding()` false，点击全吞、提示一次改键喵。

## 四、遗留/说明喵

- 窗口防御仅作用于「关闭→开启」，若用户真要在攻击后 300ms 内立刻开 freecam，会被延迟一拍；该取舍针对
  「双击左键误触」场景，正常使用不受影响喵。
- 若彻底禁止在按键绑定界面把 freecam 设为鼠标键，需 hook 按键界面，改动面大，本次未做（与 T15/T16 一致）喵。
