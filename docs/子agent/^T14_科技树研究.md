# T14 科技树（Tech Tree）系统研究阶段产出喵

## 目标喵
深度研究 Mindustry 科技树系统（`core/src/`），为 Minecraft 模组 Blockdustry 移植设计依据，输出 TechNode 结构、解锁流程、成本公式与 MC 迁移方案喵。

## 一、总体结论喵
Mindustry 科技树是**按行星（Planet）分树**、每树一个根节点、向下递归挂子节点的多叉树，**不是按 Team 分树**（阵营只影响解锁后的可用性，不决定树结构）喵。
- 全局两棵静态树：`SerpuloTechTree`（根 `coreShard`）与 `ErekirTechTree`（根 `coreBastion`），分别挂在 `Planets.serpulo.techTree` / `Planets.erekir.techTree` 上喵。
- 树用**嵌套 Runnable 构建器**声明：`node(parentContent, () -> node(child, () -> ...))`，`context` 静态栈记录当前父节点喵。
- 研究进度与解锁状态都持久化在 `Core.settings`（按键为内容名），多人时房主把解锁集合放进 `state.rules.researched` 同步给客户端喵。
- 解锁只做**正向门控**：不主动锁回，未解锁内容在建造菜单/蓝图/单位工厂等入口被过滤掉喵。

## 二、TechTree 与 TechNode 结构喵

### 1. TechTree 工具类（`mindustry/content/TechTree.java`）喵
静态字段：
- `context`：构建时的当前节点（静态栈），`node()` 压栈、子 Runnable 跑完出栈喵。
- `all`：全部节点 Seq，`roots`：根节点 Seq（每颗行星一个根）喵。

构建方法：
- `nodeRoot(name, content, requireUnlock, children)`：建根节点，`requiresUnlock` 为 true 时该根需先解锁才能在选择器中进入（如 Erekir 根）喵。
- `node(content, requirements, objectives, children)`：以 `context` 为父建节点，插入缺失的 `SectorComplete` 目标（父是 SectorPreset 时自动补），递归跑 children，恢复 context 喵。
- 每个节点构造后设 `content.techNode = this`、`content.techNodes.add(this)`、`all.add(this)`，并把 `getDependencies()` 的结果（方块建造所需物品、输入物）变成 `Research` 目标加进 `objectives` 喵。

### 2. TechNode 内部类字段（核心）喵
| 字段 | 说明 |
|---|---|
| `int depth` | 树深度，根为 0，子 = 父.depth+1 喵 |
| `@Nullable TechNode parent, rootNode` | 父节点与根节点引用喵 |
| `UnlockableContent content` | 本节点解锁的内容（Block/Unit/Item/Liquid/SectorPreset 等）喵 |
| `ItemStack[] requirements` | 研究材料需求（构造时已应用累计倍率）喵 |
| `ItemStack[] finishedRequirements` | 已投入的研究材料，长度与 requirements 一致，进度即差喵 |
| `Seq<Objective> objectives` | 解锁前置目标（Research/Produce/SectorComplete/OnPlanet 等）喵 |
| `Seq<TechNode> children` | 依赖本节点的子节点喵 |
| `ObjectFloatMap<Item> researchCostMultipliers` | 按物品的累计研究成本倍率，**从父节点继承**喵 |
| `@Nullable String name / boolean requiresUnlock` | 仅根节点用：树显示名与解锁门槛喵 |
| `@Nullable Planet planet` | 关联行星，null 自动检测喵 |

构造函数关键逻辑（L104-139）：
1. 有父时挂进 `parent.children`，`rootNode`/`planet`/`researchCostMultipliers` 都继承父；无父（根）时新建空倍率表喵。
2. `depth = parent == null ? 0 : parent.depth + 1` 喵。
3. **若继承的 `researchCostMultipliers.size > 0`，把 requirements 复制后逐项 `amount *= 倍率`**，这就是倍率向所有后代累计的关键喵。
4. `setupRequirements()` 用设置键 `"req-{content.name}-{item.name}"` 载入已投入量喵。
5. 内容依赖转 `Research` 目标、写回 `content.techNode`、加入 `all` 喵。

遍历与持久化：
- `each(Cons<TechNode>)`：递归含自身遍历子树（用于加数据库标签/行星）喵。
- `save()`：把 `finishedRequirements` 按物品写回 `Core.settings`（键 `req-...`，0 值不写）喵。
- `reset()`：清零 finishedRequirements 并 save 喵。
- `remove()`：从 all 与父的 children 摘除（mod 重新定义研究时用）喵。

## 三、解锁机制与流程喵

### 1. UnlockableContent 解锁状态（`mindustry/ctype/UnlockableContent.java`）喵
- 字段：`boolean alwaysUnlocked`（始终解锁）、`@Nullable TechNode techNode`、`Seq<TechNode> techNodes`、`protected boolean unlocked`（构造时从设置读 `"{name}-unlocked"`）喵。
- `unlock()`：未解锁且非 alwaysUnlocked 时置 true、写设置、调 `onUnlock()`、触发 `UnlockEvent` 喵。
- `quietUnlock()`：只改状态与设置，不触发事件喵。
- `clearUnlock()`：再锁回去（调试用）喵。
- 读状态三连：
  - `unlocked()`：客户端 = alwaysUnlocked || unlocked || `state.rules.researched.contains(this)`；单机 = unlocked || alwaysUnlocked 喵。
  - `unlockedHost()`：客户端看房主 researched 集合，否则同 unlocked 喵。
  - `unlockedNow()` = `unlocked() || !state.isCampaign()`（自定义非战役图全解锁）；`unlockedNowHost()` = `!campaign || unlockedHost()` 喵。

### 2. 研究面板点击解锁（`mindustry/ui/dialogs/ResearchDialog.java`）喵
- `spend(node)`：对每个需求算 `used = min(req.amount - completed.amount, items.get(req.item))`，从 `items`（聚合所有已占殖民地的核心库存 + 当前核心）扣掉，`completed.amount += used` 喵。
- 全部需求达到 → `unlock(node)`：`node.content.unlock()`，再沿 parent 链全部 unlock（保证多人下父链一致），触发 `ResearchEvent`，播放解锁音喵。
- 每次操作后 `node.save()` 与 `itemDisplay.rebuild()` 刷新进度条（`research.progress` = 已投入价值/总价值，上限 99%）喵。
- `canSpend(node)`：目标全完成且非客户端，且至少一项材料有库存或节点本就锁定喵。
- `items` 是自定义 `ItemSeq`，其 `add(item, -n)` 会按各殖民地库存**按比例分摊扣除**，当前所在核心最后扣（L248-295）喵。

### 3. 自动解锁与自由节点喵
`Control.checkAutoUnlocks()`（L350-358）在 NewGame/UnlockEvent 时遍历 `TechTree.all`，对「父已解锁 + requirements 为空 + 目标全完成」的节点自动 `unlock()` 喵。
- `Block.researchRequirements()` 中 `researchCostMultiplier <= 0` 返回空需求 → 即免费自动解锁节点喵。

### 4. 门控检查点（谁在阻止使用）喵
- 建造菜单：`PlacementFragment.unlocked(block)` = `block.unlockedNowHost() && placeablePlayer && environmentBuildable && supportsEnv`；分类列表 `getUnlockedByCategory` 用它过滤喵。
- 蓝图放置：`Schematics.toPlans` 里 `removeAll(s -> ... || !s.block.unlockedNow())` 喵。
- 具体交互点：传送带/管道替换、ItemSelection 物品选择、单位工厂单位列表、液体条、着陆场物品等都各自判 `unlockedNow()` 喵。
- 服务端放置校验 `Build.validPlace` 本身**不查解锁**（解锁是 UI 层过滤，服务端靠 `beginPlace` 前客户端已拦），MC 移植时服务端必须兜底校验喵。

### 5. 多人同步喵
- 房主 `Logic.java` 监听 `UnlockEvent` → `Call.researched(content)`，远端 `researched()` 把内容加进 `state.rules.researched`（随存档的 rules 持久化）喵。
- 客户端 `unlockedHost()` 因此读 `rules.researched`，客户端本地 `unlocked` 只影响自己的单机解锁喵。

### 6. research/techtree 命令喵
本版本**无 `research`/`techtree` 控制台命令**喵；研究入口是快捷键 `J`（`Binding.research`，仅战役）与 HUD 树按钮（`ui.research.show()`，`state.isCampaign()` 才显示）喵。

## 四、研究成本公式喵

### 1. 方块（`mindustry/world/Block.java` L1270-1282）喵
```java
public ItemStack[] researchRequirements(){
    if(researchCost != null) return researchCost;          // 显式覆盖喵
    if(researchCostMultiplier <= 0f) return ItemStack.empty; // 免费自动解锁喵
    ItemStack[] out = new ItemStack[requirements.length];
    for(int i = 0; i < out.length; i++){
        int quantity = Mathf.round(60 * researchCostMultiplier
            + Mathf.pow(requirements[i].amount, 1.11f) * 20 * researchCostMultiplier
            * researchCostMultipliers.get(requirements[i].item, 1f), 10);
        out[i] = new ItemStack(requirements[i].item, UI.roundAmount(quantity));
    }
    return out;
}
```
- 即**每项研究量 = 四舍五入到 10 的 `60*mult + (建造材料量^1.11) * 20 * mult * 单项倍率`** 喵。
- `researchCostMultiplier` 默认 1；`researchCostMultipliers` 是按物品的追加倍率（ObjectFloatMap）喵。

### 2. 单位（`mindustry/type/UnitType.java`）喵
- 默认 `researchCostMultiplier = 50`，`researchRequirements()` = 首个需求的每项 `amount * 50`（`UI.roundAmount`），零需求项剔除喵。

### 3. 倍率累计喵
- 根节点可 `context().researchCostMultipliers = map`（如 Erekir 全物品 0.9、氧化物 0.5、类星合金 0.7、碳化 0.3、相位织物 0.2）喵。
- `TechNode` 构造时把父的 `researchCostMultipliers` 继承过来并对 requirements 逐项相乘 → **倍率沿祖先链累乘到每个后代**喵。
- 结论：Mindustry 的「累计倍率」= 每级节点构造时乘一次祖先表；数值呈几何级数增长，靠各内容自身的 `researchCostMultiplier` 控制单点陡峭度喵。

## 五、研究 UI/流程要点喵
- 根选择器：多颗行星都有可进树时显示顶栏，`requiresUnlock` 根未解锁则隐藏（需先解锁才可选）喵。
- 布局：`BranchTreeLayout` 把子节点分左右两半，左半根在上、右半根在下拼成竖排树；连接线用 `Lines.line` 画，锁定时灰色、解锁时强调色喵。
- 节点态：`unlocked`=普通按钮，`locked && !selectable`（目标未完成）=红底，`locked && selectable`=默认按钮，未解锁且不可选时图标画锁（`Icon.lock`）喵。
- 桌面点击直接消耗；移动端悬停显示详情 + 底部「研究」按钮喵。
- 弹窗暂停游戏（`shouldPause = true`），研究面板只统计**有基地的非冻结殖民地核心**物品喵。

## 六、mod 侧定义研究（对本移植最有参考价值）喵
`mindustry/mod/ContentParser.java` L1339-1421：内容 JSON 里的 `research` 字段决定入树方式喵。
- 可为字符串（= 父内容名）或对象 `{ parent, requirements, objectives, planet, root, name, requiresUnlock }` 喵。
- 非根时按 `parent` 找到父节点挂上；找不到父就告警忽略喵。
- 物品/液体默认追加 `Produce` 目标（需先产出过）喵。
- 这证明科技树可**完全由数据文件驱动**，是 MC 用 JSON/数据包落地的直接范本喵。

## 七、Blockdustry（MC/NeoForge）迁移方案喵

### 1. 数据层：JSON 科技树定义 + 研究节点喵
- 建议用 NeoForge 数据包 `data/blockdustry/tech_tree.json`，结构仿 Mindustry mod 的 research 字段喵。
- 节点内容：`{ "id": "drill", "parent": "core", "requirements": [{"item":"minecraft:iron_ingot","count":64}], "costMultiplier":1.0, "perItemMultiplier":{}, "objectives":[] }` 喵。
- 编译期加载到内存 `Map<String, ResearchNode>`，`parent` 建依赖边、`children` 反向索引，供遍历与画树喵。

### 2. 存档层：研究进度持久化喵
- 用 `SavedData`（每世界一份）存：`Set<String> unlocked` + `Map<ResearchNodeId, Map<ItemId, Integer>> progress` 喵。
- 与 Mindustry 不同（解锁在 Core.settings 全局），MC 建议**按世界存档**，避免不同世界串解锁喵。
- 存档时机：解锁或进度变化时 `setDirty()`，服务端存档事件时落盘喵。

### 3. 门控检查：放置/合成处拦截喵
- 放置：拦截 `BlockEvent.EntityPlaceEvent`/`PlayerInteractEvent.RightClickBlock` 或自定义 `BlockdustryBuildingItem` 的 `onPlace`，未解锁则 `cancel` 并提示喵。
- 合成：自定义 `ResearchGatedItem` 检查或对 `PlayerContainer` 打开/配方检查拦截；JEI/创造菜单按 `ResearchManager.isUnlocked(player, id)` 过滤（客户端读同步数据）喵。
- 服务端权威：所有检查必须服务端兜底（Mindustry 把解锁过滤放 UI 层，MC 联机必须双端都查）喵。

### 4. 研究消耗与解锁流程喵
- 仿 `ResearchDialog.spend`：玩家打开研究屏幕，把背包/核心存储的材料按节点需求扣入进度，进度满 → `unlock(id)` 喵。
- `unlock(id)`：加入 unlocked 集合、触发客户端同步、递归检查子节点是否可免费自动解锁（父已解锁 + 无需求 + 目标完成），对应 `checkAutoUnlocks` 喵。
- 联网：服务端推进度后向客户端发包同步 `unlocked`/`progress`，对应 Mindustry 的 `Call.researched` 喵。

### 5. UI 层喵
- 客户端做一棵竖排树 Screen：父-子连线（父解锁亮色/否则灰）、锁定节点画锁、可点节点显示需求与进度条、点击消耗背包材料喵。
- 简化起步：第一版用列表/网格平铺「可研究项」，满足后再上连线树喵。

### 6. 成本公式落地方案喵
- 完全照搬 Mindustry：`研究量 = round10(60*mult + ceil(建造配方里该物量^1.11) * 20 * mult * perItemMult)` 喵。
- MC 配方更灵活，可退化为**显式 requirements 表**（Mindustry 的 `researchCost` override 路径），每个方块在 JSON 里直接写研究材料，不跑公式，最可控喵。
- 推荐：先在 JSON 显式写死需求，后续要「成本随配方增长」再加公式喵。

### 7. 分阶段建议喵
- **阶段 1（数据+存档+门控）**：JSON 节点 + SavedData + 放置拦截，无 UI（全自动免费解锁链）喵。
- **阶段 2（研究面板）**：客户端研究 Screen + 消耗背包材料 + 进度条 + 服务端同步喵。
- **阶段 3（倍率/公式）**：`costMultiplier` 累计倍率与 per-item 倍率、自动解锁免费节点喵。
- **阶段 4（进阶）**：目标系统（产出过 X / 击杀 / 占点）、JEI 集成、多"行星"分支树、与 Blockdustry 队伍系统联动喵。
