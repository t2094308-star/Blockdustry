# T18 科技树实现 B（网络/UI）阶段产出喵

## 目标喵
在 A 组（数据/存档/门控）基础上落地 B 组：网络同步（登录全量推送 + 研究请求/广播）、ResearchScreen 竖排树 UI、材料扣背包、按键打开，并给出创意栏过滤（v2）方案喵。

## 一、网络同步喵
新增 5 个网络文件（`com.blockdustry.research`）喵：
| 文件 | 方向 | 职责喵 |
|---|---|---|
| `ResearchStatePayload` | S→C | 全量状态：`Set<String> unlocked` + `Map<String, Map<String,Integer>> progress`（RL 字符串传输）喵 |
| `ResearchUnlockPayload` | S→C | 单节点解锁事件（提示音/飘字）喵 |
| `ResearchSpendPayload` | C→S | 请求研究指定节点（服务端扣料/解锁）喵 |
| `QueryResearchPayload` | C→S | 开屏/入服兜底拉取最新状态喵 |
| `ResearchNetwork` | — | `RegisterPayloadHandlersEvent` 注册 4 个 payload（独立于 BlockdustryNetwork，同 namespace registrar 共享底层注册表，不冲突）喵 |

同步时机喵：
- **登录全量**：`ResearchManager.onPlayerLoggedIn`（A 组占位已补全）→ `sendToPlayer(buildState(level))` 喵。
- **研究后广播**：`ResearchNetwork.handleSpend` → `ResearchManager.spend(player, id)` 扣背包 → 若刚完成发 `ResearchUnlockPayload` → `sendToAllPlayers(buildState)` 喵。
- **兜底刷新**：Screen 打开时发 `QueryResearchPayload`，服务端回全量喵。
- `ResearchManager.buildState(ServerLevel)` 新增公开方法，从 `ResearchSavedData.progressMap()`/`unlockedSet()` 构建字符串映射喵。

## 二、客户端缓存与 UI喵
| 文件 | 职责喵 |
|---|---|
| `com.blockdustry.client.ResearchClientCache` | 网络同步写入的解锁集合+进度；`isUnlocked`（默认解锁恒真）/`getProgress`/`onUnlock`（提示）；图标/名称解析喵 |
| `com.blockdustry.client.ResearchScreen` | 竖排缩进树：每行节点（图标+名称+状态），未解锁且父全解锁=可点研究（发 `ResearchSpendPayload`），已解锁绿字、未达前置红字、可研究黄字+进度条；悬停显示每项 `材料: 投入/需求` tooltip；滚轮滚动；暂停游戏喵 |
| `com.blockdustry.client.ResearchScreenHandler` | 持有 `KEY_RESEARCH`（默认 J），`ClientTickEvent.Post` 检测按下开/关屏喵 |
| `com.blockdustry.client.ResearchKeyRegistrar` | `RegisterKeyMappingsEvent`（MOD bus 客户端）注册 `KEY_RESEARCH`，独立于共享 `BlockdustryClient` 喵 |

Screen 设计要点（参考 Mindustry ResearchDialog）喵：
- 布局：`x = 16 + depth*14` 缩进，行高 24，滚轮滚动（`mouseScrolled` 4 参数）喵。
- 行状态三态：已解锁/可研究/锁定；可研究行整体可点击，点击即 `spend`（一次尽量扣，满则解锁）喵。
- 进度条 = 已投入总件数 / 需求总件数；tooltip 逐材料明细喵。
- 材料扣除：服务端 `ResearchManager.spend` 用 `player.getInventory().clearOrCountMatchingItems(...)` 扣背包（v1）喵。

## 四、主会话注册清单喵
1. **无需改动**：所有新类 `@EventSubscriber` 自动注册；`ResearchNetwork` 走 MOD bus 自注册 payload，`ResearchKeyRegistrar` 自注册 J 键，`ResearchScreenHandler` 自检测按键，均不依赖 `Blockdustry.java`/`BlockdustryClient.java` 喵。
2. **lang 需加**（共享资源，主会话整合）喵：
   - `"screen.blockdustry.research.title"`（科技树 / Research）喵
   - `"key.blockdustry.research"`（科技树 / Research）喵
   - `"blockdustry.research.completed"`（"研究完成：%s" / "Researched: %s"）喵
   - A 组已加 `blockdustry.research.locked` 喵。
3. **可选**：若主会话偏好统一按键管理，把 `ResearchScreenHandler.KEY_RESEARCH` 的 `event.register(...)` 挪进 `BlockdustryClient.registerKeyMappings`，删 `ResearchKeyRegistrar` 即可喵。
4. **实测建议**：runClient → 按 J 打开面板 → 点可研究节点（背包备好材料）→ 进度条增长、满则解锁并提示 → 到创造栏/生存放刚解锁建筑应成功、未解锁建筑仍被拦喵。

## 五、编译状态与风险喵
- `./gradlew compileJava` **BUILD SUCCESSFUL**（仅既有 deprecation 警告）喵。
- 风险 1：多人时研究为「一世界共享」，登录全量 + 变更广播已覆盖；若以后要按队伍分树，payload 需加 team 维度（接口已预留）喵。
- 风险 2：客户端类（Screen/Handler/Cache）经 `value = Dist.CLIENT` 隔离，专用服不会加载；`ResearchNetwork` 在 lambda 内用 FQN 引用客户端缓存，避免专用服 ClassNotFound（沿用 `BlockdustryNetwork` 既有做法）喵。
- 风险 3：Screen 是纯客户端绘制，防作弊仍靠服务端门控 + spend 校验；客户端只读缓存喵。
- 坑补充：本次踩到 4 个 1.21.1 API 签名坑，已写入 `docs/坑/API签名与编译.md` §4-7（EntityPlaceEvent.getLevel 返回 LevelReader / BuiltInRegistries.getValue→get / mouseScrolled 4 参 / renderTooltip 要 FormattedCharSequence）喵。
