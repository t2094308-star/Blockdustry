# T2 上帝视角（God View）可行性研究 阶段产出喵

## 目标喵
研究在 Blockdustry（NeoForge 1.21.1）实现「上帝视角」（俯视/顶视相机，第三人称，高度/倾斜角可调，玩家可继续操控）的可行性，并解析参考工程 GrandTeleport 的相机实现喵。

## 一、GrandTeleport 实现解析喵
- 定位: Fabric 多版本工程（1.20.1 / 1.21.1 / 1.21.11 / 26.x），实现 GTA 风格传送转场相机喵。
- 核心思路: **不是独立渲染**，而是用 Mixin 直接覆盖 Minecraft 原生 `Camera` 的位置与角度，让相机「脱离玩家眼睛」喵。
- 关键文件（src/main 为较新版本，src/mc1_21_1 与 Blockdustry 目标版本同为 Mojang 映射 1.21.1）喵:
  - `TeleportTransitionController.java`: 状态机，按 tick 时间线生成 `CameraFrame(pos, yaw, pitch)` 喵。时间线 = 出体 → 拉升（zoom out 三段高度）→ 顶视等待 → 高空平移（按距离算 tick）→ 顶视等待 → 回落（zoom in）→ 入体，pitch 恒 90°（正俯视）喵。
  - `mixin/CameraMixin.java`: `@Inject(method="setup", at=@At("TAIL"))`，拿到帧后经 `CameraAccessor` 调用 `setPosition(Vec3)` + `setRotation(yaw, pitch)` 改写相机喵。
  - `mixin/CameraAccessor.java`: `@Invoker("setPosition")` / `@Invoker("setRotation")`，访问 Camera 的 protected 方法喵。
  - `mixin/KeyboardInputMixin.java` 与 `MouseHandlerMixin.java`: 转场期间屏蔽玩家移动/鼠标输入喵。
  - `mixin/EntityRendererMixin.java`: 转场期间隐藏本地玩家模型喵。
  - `mixin/GuiMixin.java`: `Gui.render` TAIL 注入全屏闪光 HUD 效果喵。
  - `TeleportTransitionController.requestTerrainVisibilityUpdate(...)`: 相机远离玩家时，按区块步进调 `levelRenderer.needsUpdate()` 强制刷新地形可见性（否则高空看不到远处 chunk）喵。
  - 配置: 每维度（主世界/下界/末地）独立 3 段 zoom 高度与 tick，`GtaLikeTeleportConfig` 用 properties 文件持久化喵。
- 用了哪些 NeoForge 事件/渲染钩子: **没有**，纯 mixin + Fabric 生命周期事件；对 NeoForge 移植需替换事件层，mixin 层可照搬喵。

## 二、迁移到 Blockdustry（NeoForge 1.21.1）可行性喵
### 2.1 相机覆盖方式喵
- NeoForge 1.21.1 用 Mojang 映射，`net.minecraft.client.Camera` 与 GrandTeleport 的 mc1_21_1 分支一致，mixin 目标 `Camera.setup` 直接可用喵。
- 最可靠方案: 照搬 mixin —— `CameraMixin`（setup TAIL）+ `CameraAccessor`（`@Invoker setPosition(Vec3)` / `setRotation(float,float)`）喵。项目已启用 mixin（`EntityTypeMixin`），无需新依赖喵。
- 备选: Access Transformer（`META-INF/accesstransformer.cfg` 把 protected 变 public，build.gradle 里已预留注释）可替代 accessor，等价喵。
- NeoForge 原生事件补充:
  - `ViewportEvent.ComputeCameraAngles`（NeoForge.EVENT_BUS，客户端）只能改角度 yaw/pitch/roll，**不能改位置**；且 1.21 早期版本存在「pitch/yaw 改动未作用到相机 rotation 字段」的 bug（NeoForge issue #1123），谨慎使用喵。
  - 位置覆盖在 NeoForge 1.21.1 **无原生事件**（`ViewportEvent.RenderCamera`/`ComputeCameraPosition` 此版本不存在，仅有 `CalculateDetachedCameraDistanceEvent` 控制第三人称相机距离），位置必须用 mixin 喵。
- 结论: 位置+角度都走 mixin 最稳，事件层只做辅助（HUD、tick、世界线框）喵。

### 2.2 上帝视角设计方案（Blockdustry 专用）喵
- 目标: 可开关的俯视相机；相机 = 玩家头顶上方固定高度 + 固定俯仰角；WASD 移动照常；鼠标控制相机水平旋转（yaw）；高度/倾斜角可配置喵。
- 相机位置: `cameraPos = player.getPosition(partialTick) + (0, height, 0)`，height 可配（如 6~60 格）喵。
- 相机角度: `yaw = player.getYRot()`（跟随鼠标），`pitch = 90 - tilt`（tilt 可配，0=正俯视）喵。
- 关键一步: 每 tick `player.setXRot(godPitch)` 同步玩家俯仰，使 `mc.hitResult` / 准星 / 调试棒 / Jade 都指向相机中心（俯视目标）；`player.setYRot` 由鼠标自然控制，相机 yaw 跟随喵。
- 切换动画: 借鉴 GrandTeleport 的 smoothStep/lerp 做约 0.5s 的「升空/降落」过渡喵。

### 2.3 与现有系统兼容性喵
- 炮塔索敌（`TurretBlockEntity`）: **服务端自动索敌**（nearestLiving/nearestBuilding），与相机无关，上帝视角零影响喵。
- 调试棒右键（`BlockdustryDebugHandler`）: 用 `mc.hitResult` 判定目标喵。上帝视角下同步玩家 look 指向相机中心后，右键可正常选中俯视下的方块/实体；保留现有 `isClientSide` 判断即可喵。
- Jade（`BlockdustryJadePlugin`）: 基于 `mc.hitResult` + 相机投影渲染悬浮信息，相机覆盖后投影仍正确，叠加兼容喵。
- `BlockdustryHighlightHandler`: `RenderHighlightEvent.Block` 用 `event.getCamera().getPosition()` 做框线偏移，相机覆盖后自动适配俯视视角喵。
- 建筑/实体渲染器: 相机从高空看，所有 BER/实体渲染正常；相机 y 大幅变化时建议 `levelRenderer.needsUpdate()` 喵。
- 输入: 上帝视角下鼠标水平旋转 = 玩家 yRot（原样），垂直 pitch 被覆盖为固定值；倾斜角调整用滚轮/按键而非鼠标垂直，或捕获垂直增量叠加到 tilt 喵。
- 视角恢复: 切上帝视角前记录原 `CameraType`，退出时恢复（GrandTeleport `restoreCameraType` 思路）喵。

## 三、关键技术点喵
- 相机渲染钩子:
  - 位置+角度: mixin `Camera.setup` TAIL（核心）喵。
  - HUD 覆盖/准星: `RenderGuiEvent.Post`（NeoForge.EVENT_BUS）喵。
  - 世界空间线框（可选，如范围圈）: `RenderLevelStageEvent.AFTER_LEVEL`，poseStack 平移 `-camera.getPosition()` 喵。
  - 每 tick 逻辑: `ClientTickEvent.Post` 同步玩家 look、推进过渡动画喵。
- 相机位置插值: 直接取 `player.getPosition(partialTick)`（引擎已插值）；切换动画用 smoothStep/lerp 喵。
- 坐标转换: 相机位置为绝对世界坐标 `Vec3`；世界→屏幕由引擎处理；画世界线框时 poseStack 平移 `-camera.getPosition()` 喵。
- 玩家与相机解耦: 位置解耦（头顶上方）、角度部分解耦（pitch 固定，yaw 跟随鼠标）；look 向量需同步到玩家以保证交互（mc.hitResult/准星/Jade/调试棒）喵。

## 四、风险喵
- `ComputeCameraAngles` bug（1.21 早期）→ 优先 mixin 而非事件喵。
- 高空视距: 远处 chunk 未加载 → 参考 `requestTerrainVisibilityUpdate` 按区块步进 `needsUpdate()`，或提示玩家加大渲染距离喵。
- 第三人称碰撞: 覆盖在 setup TAIL 之后，不受原碰撞影响，但原第三人称距离计算仍会先执行，有轻微多余开销，可接受喵。
- 与其他相机 mod 冲突: 多个 mixin 覆盖 `Camera.setup` 按优先级执行，注意别盖掉其他相机效果喵。
- 玩家视角异常: xRot=90 时 `getLookAngle` 垂直向下，挖矿/放方块变「朝脚下」，符合 RTS 预期，需在配置说明中写明喵。
- 切换时机: 打开 GUI（背包/队伍界面）时应退出上帝视角或暂停鼠标旋转，避免视角漂移喵。

## 五、代码思路（骨架，供主会话整合）喵
```java
// 包: com.blockdustry.godview（新建，独立文件）喵
// 1) 状态: GodViewState 记录 active/height/tilt/过渡 tick/原 CameraType 喵
// 2) 控制器: @EventBusSubscriber(modid=MODID, value=Dist.CLIENT)
//    - ClientTickEvent.Post: 若 active，player.setXRot(90-tilt)；推进升空/降落动画喵
//    - RenderLevelStageEvent(Stage.AFTER_LEVEL): 可选画范围圈（poseStack.translate(-cam.x,-cam.y,-cam.z)）喵
//    - RenderGuiEvent.Post: 可选画俯视指示/准星喵
// 3) 相机覆盖: com.blockdustry.mixin.CameraAccessor（@Invoker setPosition/setRotation）喵
// 4) 相机覆盖: com.blockdustry.mixin.CameraMixin
@Mixin(Camera.class)
public abstract class CameraMixin {
    @Inject(method = "setup", at = @At("TAIL"))
    private void blockdustry$godView(BlockGetter level, Entity focused, boolean thirdPerson,
                                     boolean inverseView, float partialTick, CallbackInfo ci) {
        CameraFrame f = GodViewState.computeFrame(focused, partialTick); // null=不生效喵
        if (f == null) return;
        CameraAccessor a = (CameraAccessor) this;
        a.blockdustry$setPosition(f.pos());
        a.blockdustry$setRotation(f.yaw(), f.pitch());
    }
}
// 5) 配置: BlockdustryConfig 增加 godview.height / godview.tilt（ModConfigSpec）喵
// 6) 开关: BlockdustryClientCommands 加 /blockdustry godview on|off|height <n>|tilt <n>，或新增 KeyMapping 喵
// 7) blockdustry.mixins.json 增加 "client": ["CameraAccessor", "CameraMixin"] 喵
```
