# T16 上下坡传送带（T9 P1 方案 A）喵

> ## ⚠️ 已废弃（T19 回滚）喵
> 本任务（T16 上下坡逻辑 + T17 上下坡模型）已按主会话决定**全部回滚删除**：传送带恢复纯平面，垂直升降全靠提升机喵。本文档仅作历史存档，勿再按它实现喵。

## 目标喵
给 `ConveyorBlock` 加「上下坡」能力（最小可用）：新增 `slope` 状态属性，物品沿朝向移动时 y 随 progress 插值抬升/下降，交接目标按坡度切到 `.above()/.below()`，`directionOf` 支持高度差喵。模型暂不倾斜（复用现有带面模型），物品 y 插值先行喵。

---

## 一、slope 设计喵

### 1.1 状态属性（`ConveyorBlock.java`）喵

```java
public enum Slope implements StringRepresentable {
    FLAT("flat"), UP("up"), DOWN("down");
    // getSerializedName() 返回 name
}
public static final EnumProperty<Slope> SLOPE = EnumProperty.create("slope", Slope.class);
```

- 默认 `FLAT`；`createBlockStateDefinition` 注册 `FACING, CONN, SLOPE` 三个属性喵。
- `getSlope(BlockState)` 供 BE/渲染器读取；旧档无 slope 属性自动补默认 FLAT，兼容喵。
- 语义：`UP` = 沿 `facing` 方向从本格底部(0)升到顶部(1)；`DOWN` = 反向；`FLAT` = 原平面行为喵。

### 1.2 放置/邻居自动判定（`ConveyorBlock.java`）喵

- `getStateForPlacement`：按「前方三层是否有传送带 + 地形」判定坡度喵。
- `onPlace` / `neighborChanged`：`updateSlope` 只按**前方同层/高一格/低一格的传送带邻居**微调坡度（`refineSlope`），地形不参与——避免「随便在带前放个方块就把带改成坡」喵。
- `refineSlope` 返回 `null` 时保持放置时判定的坡度（地形坡不被覆盖）喵。

| 前方状态 | 判定 |
|---|---|
| 前方同层是传送带 | FLAT（平带接续） |
| 前方高一格是传送带 | UP（爬上） |
| 前方低一格是传送带 | DOWN（下坑） |
| 前方是完整方块（墙） | UP（放置时） |
| 前方是空 + 下方实心（坑） | DOWN（放置时） |
| 其余 | FLAT |

## 二、交接喵

### 2.1 出口（`ConveyorBlockEntity.tickAnchor`）喵

```java
BlockPos frontPos = switch (getSlope()) {
    case UP   -> worldPosition.relative(facing).above();
    case DOWN -> worldPosition.relative(facing).below();
    case FLAT -> worldPosition.relative(facing);
};
```

### 2.2 来源方位判定（`ConveyorBlockEntity.directionOf`）喵

水平四邻照旧；新增「背向+下/上」对角线判定，返回 `facing.getOpposite()`（视为尾插）喵：

```java
BlockPos back = worldPosition.relative(getFacing().getOpposite());
if (back.below().equals(source.getPos()) || back.above().equals(source.getPos())) {
    return getFacing().getOpposite();
}
```

- 接收方（高一格平带收 UP 坡、低一格平带收 DOWN 坡）与坡接坡（UP→UP 走背向下、DOWN→DOWN 走背向上）都靠这条对角线规则连上喵。
- 交接后接收方按**尾插**（progress=0.001）入带，语义与正后方直带一致，无新概念喵。

### 2.3 可行链路（手工推演）喵

| 链路 | 状态 |
|---|---|
| 平带(y) → UP坡(y) → 平带(y+1) | 顺畅，入口 0.25→出口 0.25 微差 |
| UP坡 → UP坡（逐格爬升 n 格） | 顺畅（背向下对角线交接） |
| DOWN坡 → DOWN坡（逐格下探 n 格） | 顺畅（背向上对角线交接） |
| 平带(y) → DOWN坡(y) | 功能可用，但入口有 ~0.75 格视觉抬升（见风险） |
| UP坡 → 上方提升机 / Router | **不通**（提升机/Router 不认对角线来源，见风险） |

## 三、渲染（`ConveyorBlockEntityRenderer.java`）喵

- 物品 y 随 progress 用 **smoothstep** 插值，避免首尾突变「瞬抬」喵：

```java
float baseY = 0.25f;
float dy = switch (slope) {
    case UP   -> 0.75f * smoothstep(p);          // 0.25 → 1.0
    case DOWN -> 0.75f * (1f - smoothstep(p));   // 1.0 → 0.25
    case FLAT -> 0f;
};
private static float smoothstep(float x) { return x * x * (3 - 2 * x); }
```

- 模型暂不倾斜：slope=up/down 仍用现有 `conveyor_*` 平带模型，靠物品 y 抬升表现坡度喵。

## 六、风险 / 已知限制喵

1. **DOWN 坡入口视觉抬升**：同层平带直接喂 DOWN 坡时，入口在坡顶（y≈1.0）而平带面在 0.25，物品交接有 ~0.75 格上跳喵。推荐 DOWN 坡由上方 DOWN 坡/合适高度的坡或提升机供料，同层直喂仅作功能可用喵。
2. **UP 坡出口 0.25 格微差**：UP 坡顶 y=1.0，接收方高一格平带面 y=1.25，交接有 0.25 下跳（3 槽瞬移交接固有的视觉 pop）喵。
3. **坡 → 提升机/Router 不通**：`ElevatorBlockEntity`/Router 的 `directionOf` 只认轴上邻接，不认「背向+下/上」对角线，坡顶/坡底只能交给传送带喵。如需互通，后续给 Elevator 的 `directionOf` 也补对角线（本任务不越界改）喵。
4. **模型未倾斜**：坡块仍是 0~4 平带模型，物品爬到 1.0 时浮在带面之上，视觉是「物品上浮」占位态喵。后续加楔形带面模型（`conveyor_slope_up/down.json`）时注意 MC 模型元素 rotation 的 faces UV 不随旋转变换（`docs/坑/方块模型.md`）喵。
5. **碰撞箱未楔形**：坡块碰撞仍是 0~4 平台，玩家走上坡是平地，后续按需加楔形 VoxelShape 喵。
6. **坡度随邻居自动变**：拆掉坡顶高一格带会让坡回落 FLAT，带内物品会瞬间平带化（progress 连续，仅 y 渲染跳变），可接受喵。
