## 零、数据核对结论（先纠偏任务描述）喵

- Mindustry `Blocks.java L1729-1783`（`wallHealthMultiplier = 4` 为 Blocks.java 内局部变量，已计入）：
  | 方块 | 类 | size | 血量(health) | 需求 | 额外 |
  |---|---|---|---|---|---|
  | plastanium-wall | Wall | 1 | 125×4 = **500** | 塑钢×5 + 钢化玻璃×2 | insulated=true, absorbLasers=true, schematicPriority=10 |
  | plastanium-wall-large | Wall | 2 | 125×4×4 = **2000** | ×4 = 塑钢×20 + 钢化玻璃×8 | 同上 |
  | thorium-wall | Wall | 1 | 200×4 = **800** | 钍×6 | — |
  | thorium-wall-large | Wall | 2 | 200×4×4 = **3200** | 钍×24 | — |

## 三、行为要点（验收对照）喵
- 放置：1×1 单格、2×2 四象限跨格模型 + 整组碰撞箱 + 组血（2000/3200/3680）喵
- 血量：500/2000 / 800/3200 / 920/3680（与原版 wallHealthMultiplier=4 后完全一致），armor 均 0 喵
- surge 特效：任意弹道（BlockdustryBulletEntity 或 MC 箭，PROJECTILE 伤害）命中 surge 墙时 5% 概率从墙中心向子弹来向放一道黄白闪电（damage20），对路径敌对活体/建筑全额伤害；大型墙从整组中心放电喵
- 无动画/无 tick（静态墙）；损坏裂纹由 BlockHealth 系统自动（无需新代码）喵

## 四、风险 / 待人工排查喵
- **【并行冲突·必须处理】BE 类型 id 冲突**：批1F T43（`defense/WallRegistrar.java`）与 T44（`defense/DefenseRegistrar.java`）**均已注册 BE id「wall」**（各自 Builder.of 含其方块），本批为避让用 id「advanced_wall」。三者 `DeferredRegister` 均以 modid 注册，若同时挂载会导致重复注册崩溃。**建议主会话整合时统一合并所有墙（copper/scrap/titanium/plastanium/thorium/surge）到同一个 BE 类型**（可删 advanced_wall 改为并入「wall」并在其 Builder 追加本批 6 墙），并让 T43/T44 二选一保留「wall」注册喵。
- plastanium 的 insulated（阻止电力节点自动连接）/ absorbLasers（吸收激光）未实现：Blockdustry 电力节点连接逻辑无绝缘判定、且无激光武器体系。属机制缺失非动画缺失，本轮按原版数据保留字段语义、视觉无体现，待电力/激光系统支持时补喵。
- 放电近似：原版 lightningLength=17 段较长，MC 取 3 格短闪电链；闪电色用 Pal.surge 黄白（与 arc 浅蓝区分）。受击方向取自子弹速度反向（BlockHealthDamageEvent 无子弹角度，此为适配近似）喵。
- 2×2 大型墙贴图是 Mindustry 正面视角图，四象限模型顶面裁剪显示其分区（与 container/scatter 同模式）；侧面用 stone（与既有迁移一致）。视觉非完美但符合本 mod 统一简化喵。
- 科技树 parent 暂挂 core（原版 parent 铜/钛墙由批1F 迁移），主会话按批1F 整合后若已有 titanium_wall 节点可改挂 titanium_wall 更贴原版喵。
