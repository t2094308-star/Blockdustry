# T19 提升机顶格 Y+1 输出与底面贴图修复喵

## 一、结论（TL;DR）喵

1. **问题一（顶部交接回落到输入端同 Y）**：根因是 T16/T18 的兜底 `dumpItem(item)` 在**提升机自身 Y 层**扫水平四邻——物品视觉已顶到本格上沿（Y+1），但卸货目标却在输入层（同 Y），看起来「没升上去」喵。修复：新增 `dumpItemTop`，改为向 **Y+1 顶面四邻**卸货（源定位在候选格正下方，配合传送带「正下方源」判定），输出保持在提升后的一层高喵。
2. **问题二（提升机底面仍无模型/黑紫）**：模型 down 面带 `cullface: down`，落地/叠放时被下方实心块剔除 → 底部无面（无模型）喵。修复：去掉 down 面 `cullface: down`，底面始终渲染静态金属 `#side`（`conveyor_side` 64×64 静态不透明，存在且有效）喵。
3. 两处均 `./gradlew compileJava` + `processResources` 通过，src/build 一致（模型哈希 `1ede1e92` 相同）喵。

## 二、问题一：顶部交接回落到输入端同 Y 喵

### 2.1 根因喵

`ElevatorBlockEntity.tickAnchor()` 顶格兜底原调用基类 `dumpItem(item)`：

```java
} else if (!headCanExit && progress[0] >= NEXT_MAX_BLOCKED && dumpItem(item)) { ... }
```

基类 `dumpItem` 以 `base = hasAnchor() ? anchor : worldPosition`（即提升机自身 Y 层）扫「全占地四邻域」的水平邻居 → 物品在顶格（progress≈0.95，视觉已到 Y+1 层上沿）却**水平吐给同 Y 层**的传送带/建筑。用户输入端传送带也在同 Y，于是看起来「物品交到了与输入传送带同一 Y 的传送带，而不是提升到 Y+1」喵。

物品上移本身没问题：`progress[0] += SPEED` 单槽推进，顶格 `front=worldPosition.above()`（Y+1），交接目标也是 `worldPosition.above()`（Y+1）；只是**兜底卸货层算错了**（用了自身 Y 而非 Y+1）喵。

### 2.2 修复喵

文件：`src/main/java/com/blockdustry/building/ElevatorBlockEntity.java`

- 新增 `dumpItemTop(Item)`：扫 **`worldPosition.above()`（Y+1 层）** 的水平四邻，源用 `TopSource(p.below())`——源 `getPos()` 返回候选格**正下方一格**，使传送带 `directionOf` 按「正下方源」判定（与垂直交接同分支）收件，沿带向运走喵。
- `TopSource` 内嵌类：实现 `BlockdustryItemSource`，`getTeam()` 委托电梯、`getPos()` 返回候选格正下方喵。
- `tickAnchor` 兜底改为 `dumpItemTop(item)`，注释同步更新喵。

文件：`src/main/java/com/blockdustry/building/ConveyorBlockEntity.java`

- `directionOf` 的「正下方源」分支从 `source instanceof ElevatorBlockEntity && ...` 放宽为 `worldPosition.below().equals(source.getPos())`，以兼容 `TopSource`（非 Elevator 实例，但 getPos 定位在候选格正下方）喵。
- 安全性：全仓只有电梯/提升机向上推物品（`frontSink` 垂直交接、`dumpItemTop` 顶面卸货）；Router/物品源/钻机等 `dumpItem` 只扫水平四邻，不会把物品推给正上方传送带；放宽后无回归喵。

### 2.3 效果喵

- 顶格物品始终在 **Y+1 层**输出：
  - 正上方是传送带/机器 → 垂直交接（`frontSink`，Y+1）喵。
  - 正上方不可收 → `dumpItemTop` 吐给 **Y+1 层**水平四邻传送带/建筑喵。
  - 输入端同 Y 层的传送带不再是目标（回吐被方向判定拒绝或不再被扫到）喵。

## 三、问题二：提升机底面无模型/黑紫喵

### 3.1 根因喵

`models/block/elevator.json` 的 4 个 down 面用了 `"cullface": "down"`：电梯落地（下方实心块）或叠放（下方电梯 shape 是整格立方体、遮挡）时，down 面被**剔除** → 底部没有面（无模型）喵。而对比 `conveyor_straight.json` 的 down 面是**无 cullface** 的（始终渲染）喵。

### 3.2 修复喵

文件：`src/main/resources/assets/blockdustry/models/block/elevator.json`

- 4 个角柱 down 面去掉 `"cullface": "down"`，保留 `"texture": "#side"`（静态 `conveyor_side`）喵。
- 贴图本身无问题：`conveyor_side.png` 64×64、RGBA 全不透明、非动画（无 mcmeta），灰色金属色系；`#side` 引用有效喵。
- 取舍：底面始终渲染，落地时与地面顶面共面存在轻微 z-fighting 风险（与传送带 down 面无 cullface 行为一致，风险可接受）喵。
