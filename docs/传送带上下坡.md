## 1. Mindustry 传送带「垂直/上下坡」——结论：没有真 3D，全部在 2D 平面内喵

Mindustry 世界是 **2D 俯视**，每个 tile 只有 (x, y)，没有 Y 轴喵。传送带的一切移动、绘制、交接都在同一层做喵。所谓「跨层/跨高度」在 Mindustry 里不存在，跨障碍靠**桥**、跨远距靠**质量驱动器**、跨区块靠**发射台**（sector 间，非本层内）喵。

### 1.1 Conveyor（基础传送带，`Conveyor.java`）

核心数据结构是 **capacity=3 的平行数组**，`ys[i]` 是沿朝向的进度（0=尾部 → 1=头部），`xs[i]` 是横向偏移喵：

```java
public class ConveyorBuild extends Building implements ChainedBuilding{
    private static final float itemSpace = 0.4f;
    private static final int capacity = 3;
    public Item[] ids = new Item[capacity];
    public float[] xs = new float[capacity], ys = new float[capacity];
    public int len = 0;               // 实际物品数，恒 < capacity
    public @Nullable Building next;
    public @Nullable ConveyorBuild nextc;
    public boolean aligned;            // 下一格是否同向直连
}
```

**移动逻辑**（`updateTile`）：从尾到头逐件，`ys[i]` 每 tick 增加 `moved = speed * edelta()`，并受「前一件进度 − ITEM_SPACE」限位；头部到达 `nextMax`（对齐=1.0，否则=1−间距）就调用 `pass()` 交接给 front 格喵：

```java
float nextMax = aligned ? 1f - Math.max(itemSpace - nextc.minitem, 0) : 1f;
float moved = speed * edelta();
for(int i = len - 1; i >= 0; i--){
    float nextpos = (i == len - 1 ? 100f : ys[i + 1]) - itemSpace;
    float maxmove = Mathf.clamp(nextpos - ys[i], 0, moved);
    ys[i] += maxmove;
    if(ys[i] > nextMax) ys[i] = nextMax;
    xs[i] = Mathf.approach(xs[i], 0, moved*2);
    if(ys[i] >= 1f && pass(ids[i])){
        if(aligned) nextc.xs[nextc.lastInserted] = xs[i];  // 对齐横向偏移
        items.remove(ids[i], len - i);
        len = Math.min(i, len);
    }else if(ys[i] < minitem){
        minitem = ys[i];
    }
}
```

**交接**（`pass`）：只调 `next.acceptItem + next.handleItem`，物品从一格「瞬移」进下一格（视觉靠下一格从 0 继续动画），全程无 Y 变化喵：

```java
public boolean pass(Item item){
    if(item != null && next != null && next.team == team && next.acceptItem(this, item)){
        next.handleItem(this, item);
        return true;
    }
    return false;
}
```

**绘制插值**（`draw`）：物品世界坐标 = 格子中心 + 沿朝向方向 × `ys[i]` + 横向 × `xs[i]`，**z 深度仅用于遮挡排序，不是高度**喵：

```java
Tmp.v1.trns(rotation * 90, tilesize, 0);
Tmp.v2.trns(rotation * 90, -tilesize / 2f, xs[i] * tilesize / 2f);
float ix = (x + Tmp.v1.x * ys[i] + Tmp.v2.x);
float iy = (y + Tmp.v1.y * ys[i] + Tmp.v2.y);
Draw.z(layer + (ix / wwidth + iy / wheight) * scaling);  // 2D 遮挡序
Draw.rect(item.fullIcon, ix, iy, itemSize, itemSize);
```

**关键结论**：`ys[i] ∈ [0,1]` 只对应「沿朝向一个格子的水平位移」，没有任何字段表示高度喵。MC 移植要加 Y 轴，必须**自己造**喵。

### 1.2 StackConveyor（堆叠传送带，`StackConveyor.java`）

三态（`stateMove/stateLoad/stateUnload`）、capacity=10、可「吞」多条物品成堆喵。物品在**相邻两格之间**做平滑插值（从一个格子被「卷」到下一格）：

```java
Tmp.v1.set(from.worldx(), from.worldy());  // 来源格中心
Tmp.v2.set(x, y);                          // 本格中心
Tmp.v1.interpolate(Tmp.v2, 1f - cooldown, Interp.linear);  // 相邻格之间插值
Draw.rect(stackRegion, Tmp.v1.x, Tmp.v1.y, ...);
```

仍然是**同一平面内相邻格插值**，无高度喵。

### 1.3 ItemBridge（物品桥，`ItemBridge.java`）

用来**跨障碍**传物（能飞越中间任意地形），但 `positionsValid` 强制**直线且同行/同列**：

```java
public boolean positionsValid(int x1, int y1, int x2, int y2){
    if(x1 == x2) return Math.abs(y1 - y2) <= range;   // 同列
    else if(y1 == y2) return Math.abs(x1 - x2) <= range; // 同行
    else return false;                                  // 不允许斜/对角
}
```

运输是每隔 `transportTime` 从缓冲 `items.take()` 直接移交，`draw` 里桥体和箭头沿直线画，**物品本身无逐帧插值、无 Z** 喵。

### 1.4 MassDriver（质量驱动器，`MassDriver.java` + `MassDriverBolt.java`）

唯一的「远距抛射」喵。装填 `minDistribute` 件后发射 `MassDriverBolt`（直线子弹，`collidesTiles=false` 穿透地形），命中判定是**直线距离和**近似：

```java
float baseDst = data.from.dst(data.to);
float dst1 = b.dst(data.from);
float dst2 = b.dst(data.to);
if(Math.abs(dst1 + dst2 - baseDst) < 4f && dst2 <= hitDst){
    data.to.handlePayload(b, data);   // 命中接收
}
```

`collidesTiles=false` + 直线弹道，语义是「跨越」（可飞越障碍/高地差的地形），但**没有真实抛物线 Z**，本质仍是 2D 弹道喵。MC 移植若要「抛射上抛」，可参考这个「直线弹道+距离命中」的简化做法（避免真抛物线）喵。

### 1.5 其它

- `Duct`（水下管道）：progress 语义类似，`front()` 取朝向格，仍 2D 喵。
- Payload 系（`PayloadConveyor`/`PayloadMassDriver`/`PayloadLauncher`）：运载整块建筑，发射台用于 **sector 之间**（跨地图），不是层间喵。

### 1.6 Mindustry 侧总结

| 机制 | 是否含高度 | 语义 |
|---|---|---|
| Conveyor | 否 | 同层逐格推进，`ys[i]` 只有水平进度 |
| StackConveyor | 否 | 相邻格插值，可堆叠 |
| ItemBridge | 否 | 直线跨障碍，瞬移式移交 |
| MassDriver | 否（直线弹道） | 远距抛射，可飞越地形 |
| Duct | 否 | 水下同层管道 |
| PayloadLauncher | 否 | 跨 sector，非层间 |

**结论：Mindustry 没有可照抄的垂直/上下坡代码，MC 移植需自行设计 Y 轴方案**喵。

## 2. MC 模组（Create 机械动力）传送带垂直升降——参考方案喵

本地 `neoforge-docs` 无 Create 资料，以下基于公开资料 + web 查证（源码参考 [Creators-of-Create/Create BeltInstance.java](https://github.com/Creators-of-Create/Create/blob/55e3f50f64ee7f9c2cce2fb2165bec337471783b/src/main/java/com/simibubi/create/content/contraptions/relays/belt/BeltInstance.java) 与 [Create 传送带 wiki](https://create.fandom.com/wiki/Mechanical_Belt)）喵。

Create 的 `Mechanical Belt`（机械传送带/履带）其实是一种「轴传动 + 运输」复合方块，块状态设计非常值得抄喵：

```java
// 伪代码：Create BeltBlock 的核心状态
BeltSlope SLOPE;          // 枚举：HORIZONTAL / UPWARD / DOWNWARD / SIDEWAYS / VERTICAL
Direction HORIZONTAL_FACING;
BeltPart PART;            // START / END / MIDDLE  —— 多格带的分段标识
```

- **斜坡（Diagonal，45°）**：带可以沿对角线**上坡/下坡**，每段升高/降低 1 格，即 UPWARD/DOWNWARD 喵。
- **垂直（VERTICAL / SIDEWAYS）**：直上直下，或沿墙垂直贴壁运行喵。
- **多格分段**：PART 标记带体是起点/终点/中间段，配合 HORIZONTAL_FACING 与 SLOPE 决定每段模型旋转与贴图滚动方向喵。
- **物品渲染**：`BeltInstance` 根据 slope 计算每段的 rotX/rotY/rotZ，物品沿带面滚动，**上坡时物品 y 随段位平滑抬升**喵。
- **参数**：水平/垂直总长 ≤20 格（含端点），对角线 ≤15 格；必须两端有同向 Shaft（传动杆）供电并确定起止喵。
- **放置**：玩家在两 shaft 间拉带，中间经过的 shaft 自动把带弯成坡喵。

Create 的核心思想：**把「带」建模成一个多格线性结构，坡度写在块状态（SLOPE+PART）里，渲染按段旋转，物品 y 由段的坡度决定**喵。这跟「方块工业」现有「单格方块 + 进度插值」的思路不同，但斜坡段的「SLOPE 上/下」枚举 + 「y 随 progress 抬升」可直接借鉴喵。

## 3. 「方块工业」可行实现方案喵

### 3.1 现状回顾（决定改哪些文件）

- `ConveyorBlock`：`FACING`（HORIZONTAL_FACING）+ `CONN`（none/straight/corner/t/cross），碰撞箱 `Block.box(0,0,0,16,4,16)` 喵。
- `ConveyorBlockEntity`：`Item[] items[3]` + `float[] progress[3]`，`SPEED=0.046` 格/tick、`ITEM_SPACE=0.4`、`NEXT_MAX_BLOCKED=0.95`；`tickAnchor()` 逐件限位 + 头部 `frontSink.accept+handle` 交接；NBT 存 `bd_belt_items` / `bd_belt_progress` 喵。
- `ConveyorBlockEntityRenderer`：`along = p - 0.5`，`translate(0.5 + facing.getStepX()*along, 0.25, 0.5 + facing.getStepZ()*along)` 画物品喵。

### 3.2 方案 A（推荐）：Create 式单格斜坡「上下坡」

核心思路：**一个斜坡块 = 完整一格，但带面从尾部 0 高渐变到头部 1 格高**；物品 y 由 `progress` 插值决定；头尾交接目标随坡度改到 `.above()/.below()` 喵。

**A1. 块状态新增坡度**（`ConveyorBlock.java`）：

```java
public enum Slope implements StringRepresentable {
    FLAT("flat"), UP("up"), DOWN("down");
    // getSerializedName() 返回 name
}
public static final EnumProperty<Slope> SLOPE = EnumProperty.create("slope", Slope.class);
// 默认 FLAT，放入 createBlockStateDefinition(builder) 并注册到默认 state
```

- 语义：`UP` = 沿 `FACING` 方向从本格底部(0)升到本格顶部(1)，`DOWN` = 反之，`FLAT` = 原行为喵。
- blockstate JSON 的 variant 数量会膨胀（现有 `corner×facing×conn` 已 80 个，加 slope 变 240 个），继续用 python 脚本生成 JSON（仓库已有此惯例）喵。
- 模型：加 `conveyor_slope_up/down.json`，楔形带面（顶面做成从 `[..,0,..]` 到 `[..,16,..]` 的斜带面，可用**旋转元素**近似，或沿用「完整方块 + 顶面贴图」（忠于 Mindustry 铁律，弯道就是靠贴图）喵。注意：MC 模型元素 `rotation` 的 faces UV 不随旋转变换（仓库已踩过此坑），所以**斜坡顶面贴图建议直接画一张带坡度透视的贴图**，或接受纯色斜带面喵。

**A2. 物品 y 随 progress 插值**（`ConveyorBlockEntityRenderer.java`）：

```java
float p = Math.min(1f, prog[i]);
double along = p - 0.5;
Slope slope = state.getValue(ConveyorBlock.SLOPE);
float baseY = 0.25f;                       // 现有带面高度（4/16）
float dy = switch (slope) {
    case UP   -> 0.75f * ease(p);          // 0 → 1 格
    case DOWN -> 0.75f * (1f - ease(p));   // 1 → 0 格
    case FLAT -> 0f;
};
// ease 建议 smoothstep：x*x*(3-2x)，避免首尾突变
pose.translate(0.5 + facing.getStepX() * along, baseY + dy, 0.5 + facing.getStepZ() * along);
```

**A3. 交接目标随坡度改高度**（`ConveyorBlockEntity.java` 的 `tickAnchor`）：

```java
BlockPos frontPos = switch (slope) {
    case UP   -> worldPosition.relative(facing).above();   // 上坡头 → 高一格
    case DOWN -> worldPosition.relative(facing).below();   // 下坡头 → 低一格
    case FLAT -> worldPosition.relative(facing);
};
BlockEntity frontBe = level.getBlockEntity(frontPos);
// 其余不变：frontSink.accept+handle 交接、progress 限位逻辑原样
```

**A4. 尾/侧接受要兼容垂直邻接**（`acceptItem`）：

- `UP` 坡的**尾**应从 `pos.relative(facing.getOpposite()).below()` 收（前一格较低）喵。
- `DOWN` 坡的**尾**应从 `.above()` 收喵。
- `directionOf(source)` 目前只遍历 `Direction.Plane.HORIZONTAL`，需扩展判断：若本格是 UP/DOWN，且来源在 `relative(opposite).above()/.below()`，视为合法尾插喵。
- 侧插仍限水平，坡道不建议侧插（或按原中段规则处理）喵。

**A5. 放置/成型**：

- 简单版：新增独立方块「传送带上坡/下坡」进创造栏，玩家显式摆放（`getStateForPlacement` 用 `ctx.getClickedFace()` 或朝向判 UP/DOWN）喵。
- 进阶版（Create 风）：`neighborChanged` 里检测「端头一格高一格/低一格且有带相对」时，自动把端头格改成 UP/DOWN 并更新两端 CONN 喵。推荐先做简单版，成型逻辑后续迭代喵。

**A6. 参数**：

- 坡度每格升 1 格（45°，与 Create 一致）喵。
- `SPEED=0.046` 不变，但视觉上 y 抬升 0~1 格用 smoothstep 平滑，避免玩家看到「瞬抬」喵。
- 3 槽平行数组、`ITEM_SPACE=0.4`、NBT 全部复用，**只改块状态与交接坐标**，改动面最小喵。

### 3.3 方案 B（垂直提升机，Create VERTICAL 风 / Mindustry Duct 风）

适合「直上直下、一次多格」的场景喵。两种粒度：

**B1. 单格逐传（最贴现有架构，推荐先做）**：仿 Mindustry `Duct`，一格存 1 件 + `progress∈[0,1]`，`front = pos.above()`，物品每 tick `progress += SPEED*2`，到 1 就交接给上一格喵。一列 n 格就是 n 段接力，天然支持任意高度，实现零新概念喵：

```java
// 伪代码：垂直带 BE（一格一段）
BlockPos up = worldPosition.above();
if (level.getBlockEntity(up) instanceof VerticalConveyorEntity e
        && e.acceptItem(this, current) && e.handleItem(this, current)) {
    items.remove(current, 1);
    current = null;
    progress = 0f;
}
```

**B2. 整列提升机（吞吐高）**：一个 anchor BE 管理整列，`vProgress` 贯穿全高，物品 y = 底部 + vProgress×高度，头到顶交接给上方水平带喵。需要记录列长、跨格 NBT，复杂度更高，作为二期优化喵。

### 3.4 方案 C（不推荐）：物品弹射上抛

头部物品 `discard()` 后 `level.addFreshEntity(new ItemEntity(...))` 带向上速度喵。问题：ItemEntity 有物理、碰撞、合并、掉落物回收逻辑，慢、不可控、多人同步差，与「Mindustry 忠实移植」理念冲突喵。**排除**喵。

### 3.5 推荐与路线

- **推荐：方案 A（单格斜坡 UP/DOWN）作为「上下坡」主功能**，改动集中在 `ConveyorBlock`（加 SLOPE）+ `ConveyorBlockEntity`（交接坐标）+ Renderer（y 插值）+ 2 个新模型，完全复用现有 3 槽进度系统喵。
- **垂直直上直下：先补方案 B1（Duct 式单格垂直带）**，能复用同一套 `progress` 语义；B2 整列提升机等有需要再做喵。
- 忠实 Mindustry 铁律：斜坡带面贴图不自行乱画，能复用 conveyor 贴图就复用；模型以完整方块 + 贴图表现为主，不做复杂 3D 楔形喵。

## 附录：NeoForge 1.21.1 落地要点（来自本地文档镜像）

- 块状态属性：`EnumProperty<Slope>` 需枚举 implements `StringRepresentable`（`getSerializedName`），现有 `ConveyorBlock.Connection` 已是模板喵（`neoforge-docs\docs\1.21.1\blocks\states.html`）喵。
- BE 同步：新放置时客户端 anchor 初始同步不到，须 override `getUpdatePacket()`（返回 `ClientboundBlockEntityDataPacket.create(this)`）+ `getUpdateTag()`（返回 `saveWithoutMetadata`），且状态变化处 `level.sendBlockUpdated` 喵。
- NBT：NeoForge 21.1.235 的 `saveAdditional/loadAdditional(CompoundTag, HolderLookup.Provider)` 都带 Provider，照现有 conveyor 的 `bd_belt_items`/`bd_belt_progress` 写法加字段即可喵。
- 模型：JSON 模型元素 `rotation` 的 faces UV 不随旋转变换（仓库已踩坑），斜坡顶面贴图若要旋转元素须自制贴图，或接受纯色/贴图直铺喵。
- blockstate variant 数量大时用 python 脚本生成（仓库惯例，现有 80 variant）喵。
