# 研究-核心染色无效修复

## 一、结论（根因）

**根因在 `CoreBlockEntityRenderer` 的 UV 裁剪喵。**

旧代码在锚点格顶面叠画 `core_team.png` 时，把 UV 固定裁到左上 1/3 象限（`u0=0, v0=0, u1=1/3, v1=1/3`）喵。
但 `core_team.png`（从 Mindustry `core-shard-team.png` 拷贝）的透明像素分布是**十字形**：只有 N / W / C / E / S 五格有内容，四角 NW / NE / SW / SE **整格全透明**喵。

而核心 3×3 的锚点格恰好是 NW 角格喵。
于是旧代码采样的 UV (0,0)-(1/3,1/3) 对应的正是**全透明的 NW 角**，实际画出来的是一片透明四边形，所以用户完全看不到队伍色层喵。

像素实测（PIL 解码 `src/main/resources/assets/blockdustry/textures/entity/core_team.png`，96×96 RGBA，非透明像素按 32×32 格统计）喵：

```
row 0: [0,   548, 0  ]   ← NW=0（全透明）, N=548, NE=0
row 1: [548, 912, 548]   ← W=548, C=912, E=548
row 2: [0,   548, 0  ]   ← SW=0, S=548, SE=0
```

与 Mindustry 原图 `D:\Blockdustry\Mindustry\core\assets-raw\sprites\blocks\storage\core-shard-team.png` 布局完全一致喵。

## 二、逐项排查结果

1. **`client/CoreBlockEntityRenderer.java`**：渲染逻辑本身（`RenderType.entityTranslucent`、`setColor`、`OverlayTexture.NO_OVERLAY`、`0xF000F0` 全亮、y+1.001 抬升）都正确，与已正常的 `CombustionGeneratorBlockEntityRenderer` 一致喵。
   唯一错误是 UV 裁剪把可见内容全部裁掉喵。
2. **`building/BlockdustryBuildingEntity.java`**：`bd_team` 同步链路完整喵——
   - `saveAdditional` 写 `bd_team`（服务端经 `getTeam()` 读 ServerLevel attachment）喵；
   - `loadAdditional` 读 `bd_team` 到 `clientTeam`，客户端 `getTeam()` 返回 `clientTeam` 喵；
   - `getUpdatePacket` / `getUpdateTag` 均携带完整 BE 数据（`saveWithoutMetadata`），放置时 `sendBlockUpdated` 触发同步喵。
   同步机制与燃烧发电机 `bd_warmup` 同款，无问题喵。
3. **贴图存在性**：`src/main/resources/assets/blockdustry/textures/entity/core_team.png` 存在，96×96 RGBA，为原图正确拷贝喵。
4. **队伍色获取**：`BlockdustryTeam.getColor()` 返回 ARGB（如 SHARDED=0xFF5b7cfa，alpha=255），渲染 `setColor(r,g,b,a)` 解包正确喵。
5. **渲染问题**：`entityTranslucent` 叠加、y+1.001 防 z-fighting、全亮光照与 CombustionGenerator 同款，均无问题喵。

## 三、修复代码

只改 `src/main/java/com/blockdustry/client/CoreBlockEntityRenderer.java`，把 1×1（裁左上 1/3）改成在锚点格顶面画**整张 3×3 平面**（uv 0..1 覆盖整个核心占地）喵：

```java
package com.blockdustry.client;

import com.blockdustry.Blockdustry;
import com.blockdustry.building.CoreBlockEntity;

import com.mojang.blaze3d.vertex.PoseStack;
import com.mojang.blaze3d.vertex.VertexConsumer;

import net.minecraft.client.renderer.MultiBufferSource;
import net.minecraft.client.renderer.RenderType;
import net.minecraft.client.renderer.blockentity.BlockEntityRenderer;
import net.minecraft.client.renderer.blockentity.BlockEntityRendererProvider;
import net.minecraft.client.renderer.texture.OverlayTexture;
import net.minecraft.resources.ResourceLocation;

// 核心队伍染色渲染：Mindustry 核心 = base（方块模型，9 格各切 1/3 切片）+ team 层（整张 3×3 贴图乘队伍颜色）喵
// 关键：core_team.png 的透明内容在十字形（N/W/C/E/S），四角 NW/NE/SW/SE 全透明。
// 旧实现只把 UV 裁到左上 1/3（NW 格）——而那正是全透明角，故用户看不到队伍色层喵
// 修复：锚点格是 3×3 的 NW 基准格，在其顶面叠画整张 core_team.png（uv 0..1 覆盖整个 3×3 占地）喵
public class CoreBlockEntityRenderer implements BlockEntityRenderer<CoreBlockEntity> {
    private static final ResourceLocation TEX =
            ResourceLocation.fromNamespaceAndPath(Blockdustry.MODID, "textures/entity/core_team.png");

    public CoreBlockEntityRenderer(BlockEntityRendererProvider.Context ctx) {
    }

    @Override
    public void render(CoreBlockEntity be, float partialTick, PoseStack pose,
                       MultiBufferSource buffer, int light, int overlay) {
        if (!be.isAnchor()) return; // 只在锚点格画一次整张队伍层喵
        int teamColor = be.getTeam().getColor(); // ARGB，忠于原作 Team 构造喵
        int a = (teamColor >> 24) & 0xFF;
        int r = (teamColor >> 16) & 0xFF;
        int g = (teamColor >> 8) & 0xFF;
        int b = teamColor & 0xFF;
        pose.pushPose();
        // 锚点格是 NW 角格，渲染器已平移到该格本地原点；抬到顶面 y+1.001 防 z-fighting 喵
        pose.translate(0f, 1.001f, 0f);
        VertexConsumer vc = buffer.getBuffer(RenderType.entityTranslucent(TEX));
        var matrix = pose.last().pose();
        // 3×3 平面（0..3 × 0..3），uv 覆盖整张贴图：四角透明透出 base，十字染上队伍色喵
        vc.addVertex(matrix, 0f, 0f, 0f).setUv(0f, 0f).setColor(r, g, b, a).setOverlay(OverlayTexture.NO_OVERLAY).setLight(0xF000F0).setNormal(0f, 1f, 0f);
        vc.addVertex(matrix, 0f, 0f, 3f).setUv(0f, 1f).setColor(r, g, b, a).setOverlay(OverlayTexture.NO_OVERLAY).setLight(0xF000F0).setNormal(0f, 1f, 0f);
        vc.addVertex(matrix, 3f, 0f, 3f).setUv(1f, 1f).setColor(r, g, b, a).setOverlay(OverlayTexture.NO_OVERLAY).setLight(0xF000F0).setNormal(0f, 1f, 0f);
        vc.addVertex(matrix, 3f, 0f, 0f).setUv(1f, 0f).setColor(r, g, b, a).setOverlay(OverlayTexture.NO_OVERLAY).setLight(0xF000F0).setNormal(0f, 1f, 0f);
        pose.popPose();
    }
}
```

关键改动说明：
- 平面从 `-0.5..0.5`（1×1）改为 `0..3 × 0..3`（整核心占地）喵；
- UV 从 `0..1/3` 改为 `0..1`（整张贴图）喵；
- 平移从 `(0.5, 1.001, 0.5)` 改为 `(0, 1.001, 0)`，即锚点格本地原点（NW 角）喵；
- 顶点与 UV 映射保持与方块模型「上表面」一致：v=0 在北（-z）、v=1 在南、u=0 在西、u=1 在东喵。

## 四、可选加固（未改，属非必需）

- 3×3 平面超出锚点格 1×1 渲染包围盒；相机正对 SE 且锚点 NW 完全出屏时才可能整层被剔除喵。
  如需彻底解决，可在 `CoreBlockEntity` 覆写 `getRenderBoundingBox()` 返回锚点格向东南扩展 3×3 的 AABB，但通常不必喵。

## 五、验证建议

- 放置核心后，从上方俯视：应看到核心表面「十字形」（N/W/C/E/S）按队伍色染色（SHARDED 蓝），四角透出灰蓝 base 喵；
- DERELICT（无主）时十字为灰，对比度低属正常，换队后应变色喵；
- 确认 `bd_team` 同步正常（换队即时变色）喵。
