# 研究：机器方块侧面贴图问题

## 背景与现象

「方块工业」mod 的机器方块模型多数是完整 cube，顶面用 Mindustry 俯视贴图，侧面却引用了 `minecraft:block/stone` 喵。玩家反馈机器侧面是石头的贴图，与机器的金属科技风严重不搭喵。

## 现状梳理（已读模型确认）

按模型结构分三类喵：

1. **cube_all 六面全用 Mindustry 俯视贴图**（侧面不会出现石头）喵：
   - `power_node.json`、`combustion_generator.json`、`battery.json`、`router.json`、`turret.json`、`drill.json`（`drill.json` 未被 blockstate 引用，实际不生效）喵。
   - 这类方块侧面是「俯视贴图直接贴上去」，部分方块（如 power_node、battery 圆形面板）尚可接受，但本质也是拉伸喵。

2. **完整 cube：顶面 Mindustry 贴图 + 侧面 `minecraft:block/stone`**（问题主体）喵：
   - `graphite_press_nw.json`、`graphite_press_ne.json`、`graphite_press_sw.json`、`graphite_press_se.json` 共 4 个喵。
   - 顶面 UV 裁剪：石墨压机是 2×2 多格，64×64 顶图每格裁剪 32×32（nw 用 `uv [0,0,8,8]`、ne 用 `[8,0,16,8]`、sw 用 `[0,8,8,16]`、se 用 `[8,8,16,16]`）喵。

3. **薄片 16×16×4：顶面传送带贴图 + 侧面 `minecraft:block/stone`**（同样问题）喵：
   - `conveyor_none.json`、`conveyor_straight.json`、`conveyor_corner.json`、`conveyor_t.json`、`conveyor_cross.json` 共 5 个喵。
   - 侧面 UV 是 `[0,0,16,4]`（只取贴图上部 1/4，16 宽对 4 高，1:1 不拉伸）喵。

4. **已有自定义侧面贴图的先例**（正确做法）喵：
   - `drill_nw/ne/sw/se.json` 侧面用 `blockdustry:block/drill_side`，不是石头喵。

### 引用 stone 的文件完整清单（共 9 个）

- `models/block/graphite_press_nw.json`
- `models/block/graphite_press_ne.json`
- `models/block/graphite_press_sw.json`
- `models/block/graphite_press_se.json`
- `models/block/conveyor_none.json`
- `models/block/conveyor_straight.json`
- `models/block/conveyor_corner.json`
- `models/block/conveyor_t.json`
- `models/block/conveyor_cross.json`

物品模型 `models/item/graphite_press.json`、`models/item/conveyor.json` 直接继承方块模型，改方块模型即自动修复物品图标喵。blockstate、Java 代码均无需改动喵。

## 问题分析

- `minecraft:block/stone` 是灰岩质噪点纹理，颜色和质感都与 Mindustry 机器（深灰金属外壳）不一致，侧视第一眼非常扎眼喵。
- 传送带渲染器 `ConveyorBlockEntityRenderer` 只负责画带上的物品，方块本身仍用标准方块模型渲染，所以传送带模型的石头侧面是真实可见的喵。

## 可选方案调研

**a. 侧面直接用 Mindustry 方块贴图（cube_all 或顶图贴侧面）**
- 优点：零新资产，整块方块六个面都是该机器喵。
- 缺点：俯视贴图贴到侧面会显得平板/拉伸，石墨压机 64×64 顶图压到 16×16 侧面，细节全糊、噪点重喵。
- 结论：适合面板类/圆形节点类方块（power_node、battery 现状即如此），不适合石墨压机这类复杂机械喵。

**b. 用自身贴图做侧面（会拉伸）**
- 本质同 a，只是 UV 不裁剪时的效果，不推荐作为通用方案喵。

**c. 自定义侧面纹理（推荐）**
- 参照 `drill_side.png` 的先例，新建一个共享 `machine_side.png` 金属外壳面板，或按方块分别做 `graphite_press_side.png`、`conveyor_side.png` 喵。
- 取色建议：从机器自身顶图的边缘色取样。实测 `graphite_press.png` 边缘条带平均色 ≈ RGB(107,108,116)（深灰蓝），正是外壳色，用它做侧面观感最一致喵。
- 零成本变体：不新建贴图，直接把 9 个文件侧面指向现成的 `blockdustry:block/drill_side`（中性深灰，亮度 110，作为通用机器外壳可接受）喵。
- 优点：视觉最协调，与 drill 的做法统一，符合 Mindustry「机器有独立外壳」的视觉习惯喵。
- 缺点：需要新增 1~2 张 PNG 贴图（工作量很小）喵。

**d. 模型做成立方体六面都合理（完整 3D 建模）**
- 工作量大，且 Mindustry 原版就是俯视绘制、没有真正的侧面美术，Mindustry 移植到 MC 的通行做法就是「盒子 + 外壳色」喵。
- 结论：属过度设计，本次不做喵。

## 推荐修复

主推方案 c，分两步喵：

1. **新建共享外壳贴图** `src/main/resources/assets/blockdustry/textures/block/machine_side.png` 喵。
   - 建议 16×16 纯色面板即可（取 RGB(107,108,116) 系深灰蓝），或 64×64 带细微铆钉/面板线提升质感喵。
   - 16×16 纯色对传送带 4px 高侧面尤其友好：`uv [0,0,16,4]` 取上部 1/4，纯色无接缝问题喵。

2. **改 9 个模型 JSON**：把 `"side": "minecraft:block/stone"` 一行改为 `"side": "blockdustry:block/machine_side"` 喵。

若想先零资产快速验证，可把上述 JSON 指向 `blockdustry:block/drill_side`，先看效果再决定是否新建贴图喵。

## JSON 修改示例

以 `graphite_press_nw.json` 为例，只改 textures 段喵：

```json
{
  "parent": "minecraft:block/block",
  "textures": {
    "particle": "blockdustry:block/graphite_press",
    "top": "blockdustry:block/graphite_press",
    "side": "blockdustry:block/machine_side"
  }
}
```

其余 8 个文件同样只需把 `"side"` 的 stone 替换为 `blockdustry:block/machine_side` 喵。

## 备注

`power_node`、`battery`、`combustion_generator`、`router`、`turret` 这 5 个 cube_all 方块没有石头问题，但它们侧面是「俯视贴图直接贴」的拉伸观感喵。若后续要整体提升质感，可统一改造为「顶面俯视图 + 侧面 machine_side」结构，优先级低于本次石头问题喵。
