# 研究：Mindustry duo 炮塔动画迁移到「方块工业」MC 模组

## 结论一句话

用「方块实体渲染器（BER）在炮塔方块上叠画 duo 顶部转盘 + 双炮管」实现：服务端 `TurretBlockEntity` 新增 `aimYaw`（朝向）与 `recoilL/recoilR`（每管后坐力）字段并随方块实体数据同步，客户端 `TurretBlockEntityRenderer` 用 `pose.mulPose(Axis.YP.rotationDegrees(aimYaw))` 旋转、再沿炮管反方向平移后坐力位移，基座沿用现有 cube_all 方块模型不另画喵。

## 二、Mindustry duo 动画源码解析

### 2.1 Turret.java（`core/src/mindustry/world/blocks/defense/turrets/Turret.java`）

| 字段/逻辑 | 值/行为 | 说明 |
|---|---|---|
| `rotate = true` | 方块带旋转 | 构造器里 `rotate = true; quickRotate = false` 喵 |
| `rotation` | 0~360° 浮点 | `turnToTarget()`：`rotation = Angles.moveToward(rotation, targetRot, rotateSpeed * delta() * efficiency)`，按 `rotateSpeed=10°/tick` 匀速转向目标角度喵 |
| `drawrot()` | `rotation - 90` | 渲染用的角度：`TurretBuild.drawrot() = rotation - 90` 喵 |
| `recoil = 0.5f` | 整体后坐力幅度（px） | 每次开火整体后坐力峰值 0.5px 喵 |
| `recoilPow = 1.8f` | 后坐力曲线幂 | 位移 = `pow(curRecoil, recoilPow)`，让回弹先快后慢喵 |
| `recoilTime = -1` → `init()` 里 = `reload`(20tick) | 后坐力回位时长 | `curRecoil = Mathf.approachDelta(curRecoil, 0, 1/recoilTime)` 线性衰减 20tick 回零喵 |
| `recoils = 2` | 每管独立后坐力计数器 | duo 双管，各一个计数器喵 |
| `curRecoils[]` | 每管后坐力 | `curRecoils[barrelCounter % recoils] = 1f;` 开火时把当前管置 1，再同样按 `1/recoilTime` 衰减喵 |
| `recoilOffset` | `Vec2`，每帧更新 | `recoilOffset.trns(rotation, -Mathf.pow(curRecoil, recoilPow) * recoil)`：整体向后（反朝向）位移，`trns(角度,长度)` = 按角度方向偏移喵 |
| `barrelCounter` | 开火管计数 | `shoot()` 里 `pattern.shoot(barrelCounter, ..., () -> barrelCounter++)`，每次开火自增，用于取 `curRecoils[]` 下标与 `ShootAlternate` 交替喵 |
| `warmup` / `shootWarmup` | 预热 0~1 | duo 无 `minWarmup`，`warmup` 仅影响音效/光，不影响炮管位置（炮管用 `recoil` progress 不用 warmup）喵 |
| `heat` | 炮管热发光 | duo 没有 `-heat` 贴图（`Core.atlas.find("duo-heat")` 找不到即 `found()=false`），不绘制热效果喵 |
| `shootX/shootY` | 炮口 | duo 用 `shootY=3f`（3px 前伸）喵 |
| 开火时机 | `rotation` 与目标角差 < `shootCone=15°` 且装填完成 | `Angles.angleDist(rotation, targetRot) < shootCone` 喵 |

要点：**rotation 是连续转向的角度，recoil 是「开火瞬间置 1、20tick 线性回零」的标量，curRecoils 是每管各一份**喵。

### 2.2 DrawTurret.java（`core/src/mindustry/world/draw/DrawTurret.java`）

绘制层级（`draw(Building)`）：

1. `Draw.rect(base, build.x, build.y)`：静态基座（duo 加载时 `base = Core.atlas.find("block-2")`，即通用 2 格深色底座，非 duo.png）喵。
2. `Draw.z(shadowLayer)` + `Drawf.shadow(...)`：投影（MC 不必迁移）喵。
3. `Draw.z(turretLayer)` + `drawTurret()`：`Draw.rect(block.region, build.x + recoilOffset.x, build.y + recoilOffset.y, drawrot())` —— **duo.png（旋转顶部）整体按 `drawrot()` 旋转，并按 `recoilOffset`（整体后坐力）平移**喵。
4. `parts` 遍历：对每个 `RegionPart`（炮管）设置 `PartParams`，`params.x/y = build.x + recoilOffset.x/y`（继承整体后坐力）、`params.rotation = tb.rotation`（原始角度，非 drawrot）喵。
   `params.setRecoil(part.recoilIndex >= 0 ? tb.curRecoils[part.recoilIndex] : tb.curRecoil)` —— 每个炮管取自己的后坐力喵。
5. `drawHeat()`：无 heat 贴图时跳过喵。

### 2.3 RegionPart（炮管）关键计算（`core/src/mindustry/entities/part/RegionPart.java`）

duo 的两个炮管是独立 `RegionPart`，各自配置：

```java
new RegionPart("-barrel-" + (i == 0 ? "l" : "r")){{
    progress = PartProgress.recoil;  // 位移进度 = 该管后坐力（1→0）
    recoilIndex = f;                 // 0=左管 duo-barrel-l，1=右管 duo-barrel-r
    under = true;                    // 画在炮塔本体之下一点（z - 0.0001）
    moveY = -1.5f;                   // 后坐力方向位移 -1.5px（沿炮管反方向）
}}
```

绘制数学（`draw(PartParams)`）：

```java
float prog = progress.getClamp(params);         // = params.recoil（该管后坐力）
float mx = moveX * prog, my = moveY * prog;      // mx=0, my=-1.5*prog
Tmp.v1.set((x + mx) * sign, y + my).rotateRadExact((params.rotation - 90) * degRad);
// rx = params.x + v1.x, ry = params.y + v1.y
// rot = params.rotation - 90   （与炮塔本体同向旋转）
```

含义：
- 炮管的**横向偏移（±3.5px）烘焙在贴图像素里**（barrel-l 在左半、barrel-r 在右半），代码里 `x=0` 不额外偏移喵。
- **后坐力位移**是局部 `(0, -1.5*prog)`，再旋转到炮管朝向，即沿「炮管反方向」平移，幅度峰值 1.5px 喵。
- 炮管旋转角 = 炮塔本体旋转角（`params.rotation - 90`），即炮管随整体一起转向喵。

### 2.4 duo 实际配置（`core/src/mindustry/content/Blocks.java:3258`）

```java
duo = new ItemTurret("duo"){{
    ...
    shoot = new ShootAlternate(3.5f);   // 双管交替，横偏 ±3.5px
    recoils = 2;                        // 双后坐力计数器
    shootSound = Sounds.shootDuo;
    recoil = 0.5f;
    shootY = 3f;
    reload = 20f;                       // 20tick/发
    range = 160;                        // 160px = 20 格
    shootCone = 15f;
    inaccuracy = 2f;
    rotateSpeed = 10f;
    ...
    drawer = new DrawTurret(){{
        for(int i = 0; i < 2; i ++){
            parts.add(new RegionPart("-barrel-" + (i == 0 ? "l" : "r")){{
                progress = PartProgress.recoil;
                recoilIndex = i;
                under = true;
                moveY = -1.5f;
            }});
        }
    }};
}};
```

`ShootAlternate(3.5f)` 交替规则：第 0 发 `index=(0%2)-0.5=-0.5` → xOffset=-1.75px（左管），第 1 发 +1.75px（右管），即 **Mindustry 首发是左管**喵。

## 三、duo 贴图确认

| 贴图 | 尺寸 | 透明 | 作用 |
|---|---|---|---|
| `duo.png` | 32×32 RGBA | 有透明（bbox=4,11-28,29，透明像素 708/1024） | 旋转顶部（炮塔转盘本体）喵 |
| `duo-barrel-l.png` | 32×32 RGBA | 有透明（bbox=4,4-13,19，透明像素 946/1024） | 左炮管（像素在左半）喵 |
| `duo-barrel-r.png` | 32×32 RGBA | 有透明（bbox=19,4-28,19，透明像素 946/1024） | 右炮管（像素在右半）喵 |
| `duo-preview.png` | 32×32 RGBA | 有透明 | 建造预览图（不迁移）喵 |

结论：三张都是 32×32 RGBA 带透明底，可直接用于 MC 的 `RenderType.entityCutout`（透明底正常显示），无需预处理喵。注意 Mindustry 1 格 = 8px，32px 图是 2 格炮塔；当前 MC turret 方块是 **1×1**，迁移时把 32px 图铺到 1 格方块即可（与现有 `turret.png`（32×32 cube_all）同密度）喵。

另：`duo.png` 与现有 `block/turret.png` 并非同一像素图（已比对不同），turret.png 是当前基座/整块的方块贴图喵。

## 四、MC 迁移方案

### 4.1 总览

- **基座**：沿用现有方块模型（`models/block/turret.json` = cube_all `turret.png`），BER 不画基座，避免与方块模型叠画重复喵。
- **BER 负责叠画**：旋转顶部（duo.png）+ 左炮管（duo-barrel-l.png）+ 右炮管（duo-barrel-r.png），三者都随 `aimYaw` 旋转，各自带后坐力位移喵。
- **状态来源**：服务端实体持有朝向与后坐力，随方块实体 NBT 同步到客户端；客户端在渲染器里做平滑插值喵。

### 4.2 服务端实体改造（`building/TurretBlockEntity.java`）

新增字段：

```java
// 炮塔朝向（MC 渲染角，度；0=sprite 贴图"上"对准 +Z 南向）喵
private float aimYaw;
// 两管后坐力 0..1，开火置 1、20tick 线性回零（Mindustry curRecoils）喵
private float recoilL, recoilR;
// 整体后坐力（Mindustry curRecoil），供转盘本体位移喵
private float recoilTop;
// 上次同步的朝向，用于判断是否需要发更新喵
private float lastSyncedYaw;
```

`tickAnchor()` 内（在现有索敌/开火逻辑里插入）：

```java
// 1) 每 tick 衰减后坐力（线性，recoilTime=reload=20）喵
float decay = 1f / 20f;
recoilL = Math.max(0, recoilL - decay);
recoilR = Math.max(0, recoilR - decay);
recoilTop = Math.max(0, recoilTop - decay);

// 2) 转向：现有代码已算出目标中心（targetCenter），求水平方向角并匀速逼近 aimYaw 喵
float dx = (float)(targetCenter.x - worldPosition.getCenter().x);
float dz = (float)(targetCenter.z - worldPosition.getCenter().z);
if (dx * dx + dz * dz > 1e-6f) {
    float targetYaw = (float) Math.toDegrees(Math.atan2(dx, dz));
    aimYaw = moveToward(aimYaw, targetYaw, 10f);   // rotateSpeed=10°/tick，含最短角差
}
```

`fireAt()` 里开火成功处：

```java
// 3) 开火后：当前管后坐力置 1 + 整体后坐力置 1（Mindustry bullet()）喵
if (barrel == 0) recoilR = 1f; else recoilL = 1f;   // 按当前管映射（见注意点 6）
recoilTop = 1f;
markDirty();                                        // 触发同步
```

持久化与同步：

```java
// saveAdditional：写入 aimYaw/recoilL/recoilR/recoilTop 喵
// loadAdditional：读回（客户端收到 updateTag 时自动更新）喵
// 变化超过阈值或开火时 setChanged() + level.sendBlockUpdated(worldPosition, state, state, 3) 喵
```

建议同步策略：**开火时必发**；转向过程中当 `|aimYaw - lastSyncedYaw| > 2°` 再发，静止不发（20tick/发的射速下约 1~5 次/秒，量很小）喵。

客户端本地平滑（渲染器内做，不写实体）：
- 朝向：`displayYaw` 每帧朝同步值做指数插值，弥补稀疏同步的跳变喵。
- 后坐力：记录收到同步的 `clientLastSyncTick = level.getGameTime()`，渲染时按 `max(0, recoil - (gameTime + partialTick - clientLastSyncTick)/20f)` 本地衰减，免去每 tick 同步后坐力喵。

### 4.3 客户端渲染器（新建 `client/TurretBlockEntityRenderer.java`）

仿照 `DrillBlockEntityRenderer`（已是 `RenderType.entityCutout` + 平面 quad 画法），关键流程：

```java
@Override
public void render(TurretBlockEntity be, float partialTick, PoseStack pose,
                   MultiBufferSource buffer, int light, int overlay) {
    if (!be.isAnchor()) return;                     // 1×1 恒为锚点喵

    // 1) 朝向平滑 + 后坐力本地衰减（见 4.2）喵
    float yaw = lerpYaw(be.aimYaw, partialTick);    // 显示用角度
    float top = Math.max(0, be.recoilTop  - elapsed(be, partialTick) / 20f);
    float rl  = Math.max(0, be.recoilL    - elapsed(be, partialTick) / 20f);
    float rr  = Math.max(0, be.recoilR    - elapsed(be, partialTick) / 20f);

    // 2) 移到方块中心上方，先整体旋转（Mindustry drawrot 的角色）喵
    pose.pushPose();
    pose.translate(0.5, 1.02, 0.5);                 // 1×1 块顶面，避免 z-fighting 喵
    pose.mulPose(Axis.YP.rotationDegrees(yaw));

    // 3) 转盘本体：整体后坐力沿炮管反方向平移（÷8 从 px 换到格）喵
    float topBack = (float) Math.pow(top, 1.8f) * 0.5f / 8f;
    pose.pushPose();
    pose.translate(0, 0, topBack);
    drawQuad(pose, buffer, TEX_TOP, light, overlay);   // duo.png，-0.5..0.5 铺满 1 格喵
    pose.popPose();

    // 4) 双炮管：各自在整体后坐力基础上再加 moveY=-1.5px 的后坐力喵
    drawBarrel(pose, buffer, TEX_BARREL_L, topBack + 1.5f * rl / 8f, light, overlay);
    drawBarrel(pose, buffer, TEX_BARREL_R, topBack + 1.5f * rr / 8f, light, overlay);
    pose.popPose();
}
```

角度换算（贴图"上"对准目标的推导）：

- 平面 quad 顶点顺序与 drill 相同：`(-0.5,0,-0.5)uv(0,0)`、`(-0.5,0,0.5)uv(0,1)`、`(0.5,0,0.5)uv(1,1)`、`(0.5,0,-0.5)uv(1,0)`，则**贴图"上"（uv v=0 边）指向局部 -Z**喵。
- 旋转 `Axis.YP.rotationDegrees(a)` 把局部 -Z 映到 `(-sin a, 0, -cos a)`；要让它对准水平目标 `(dx,dz)`，解 `a = atan2(-dx, -dz)`（= `atan2(dx,dz)+180°`）喵。
- **后坐力反方向 = 局部 +Z**，所以上面用 `pose.translate(0, 0, +dist)` 喵。
- 建议写一个 `static float yawForAim(float dx, float dz)` 并把公式在游戏里对照实际朝向校准 ±180°（贴图烘焙的"前"方向以 duo.png 实图为准）喵。

quad 绘制（复用 drill 的 `VertexConsumer` 写法，`RenderType.entityCutout(RL)`，法线 `(0,1,0)`，尺寸 -0.5..0.5）喵。

## 六、注意点与风险

1. **1×1 vs 2×2**：Mindustry duo 是 2 格炮塔，当前 MC turret 是 1×1 方块；贴图按 1 格铺（32px 图用于 1 格方块，密度 32px/格），与现有 turret.png 一致喵。若想还原 2 格占地需把方块改 2×2（改 `BlockdustryBuildingItem` 尺寸、blockstate/模型、射程逻辑），工作量更大，非本次动画迁移必需喵。
2. **旋转平滑**：客户端指数插值显示角，服务端 2° 阈值触发同步，炮塔转向是"快照 + 平滑"，演示级够用喵。
3. **后坐力本地衰减**：依赖客户端收到同步时的 `getGameTime()` 记录，若区块卸载/重载会短暂跳一下，可接受喵。
4. **warmup / heat / 阴影 / outline**：duo 的 warmup 不参与炮管位置、无 heat 贴图、outline 是描边、shadow 是投影，四者 MC 侧一律不迁移喵。
5. **基座**：保留 cube_all 方块模型做基座；若嫌转盘与基座重影，可给 duo.png 转盘单独抬高层级（y≈1.02 已高于块顶 1.00）喵。
6. **左/右管映射**：Mindustry 抽屉把 `recoilIndex 0 → duo-barrel-l`、`1 → duo-barrel-r`，且 `ShootAlternate` 首发是左管（index=0）；而现有 MC 实体 `barrel==0` 是右管（spawn 时 sign=+1）。动画上若想严格对应，需把 `fireAt` 里管序与 recoil 下标映射统一（改为 barrel 0→recoilL）或仅接受视觉上左右管后坐力互换喵。
7. **透明度**：三张图均为 RGBA 透明底，必须用 `RenderType.entityCutout` 而非普通 block 渲染，否则透明像素会变黑喵。
