# 研究：炮塔「黑色阴影」真正来源彻查（第二轮）喵

## 结论一句话喵

炮塔的「黑色阴影」**不是**贴图内容、**不是**透明裁切失效、**也不是**三张 quad 共面 z-fighting，而是**底座方块模型 `models/block/turret.json` 用 `cube_all` 把 Mindustry 俯视底座贴图 `turret_base` 直接铺满六面**喵。turret_base 是「俯视方块底座」：中心亮 RGB(176,186,192)，四周带深灰蓝边框（左列/顶左渐变/底部 6 行 = RGB(110,112,128)）喵。把它贴到**侧面**后，每个侧面的底部就出现一条深色阴影带，再乘 MC 侧面方向光（东西 ×0.6、南北 ×0.8）后暗到 RGB(66~90)，从侧视/俯视远看就是一个「黑色阴影基台」喵。这个观感与 BER quad 完全无关，所以上一个 agent 加的 y 偏移（当前代码里 0/0.004/0.008）**无法消除**它喵。

---

## 1. 关键证据：turret_base.png 就是带深色边框的俯视底座喵

用 PIL 逐像素统计 `src/main/resources/assets/blockdustry/textures/block/turret_base.png`（32×32，全不透明）喵：

| 区域 | 像素 RGB | 含义喵 |
|---|---|---|
| 中心主体 | (176,186,192) 亮灰蓝 | 底座台面喵 |
| 左侧 0~4 列 | (110,112,128) 深灰蓝 | 边框阴影喵 |
| 顶部 0 行渐变 | (110~152) | 顶边阴影喵 |
| 底部 26~31 行（6 行 = 19% 高） | (110,112,128) 深灰蓝 | 底边阴影带，最扎眼喵 |
| 右下角过渡 | (152,154,164) | 高光角喵 |

- 贴图无任何黑色像素，但**底边 6 行是一条深色带**，且与中心亮度差 66+，对比强烈喵。
- `cube_all` 把这张「俯视图」贴到上/下/前/后/左/右六面喵。

### 1.1 侧面为什么变「黑阴影」喵

侧面贴图是「俯视图直接拉伸」，侧面的**底部条带**正好是贴图底部那条深色带（RGB 110,112,128）喵。MC 对侧面做方向光衰减，`ClientLevel.getShade` 反编译确认（`build/neoForm/.../net/minecraft/client/multiplayer/ClientLevel.java`）：

```java
switch (direction) {
    case DOWN:    return 0.5F;   // 底面喵
    case UP:      return 1.0F;   // 顶面喵
    case NORTH:
    case SOUTH:   return 0.8F;   // 南北侧面喵
    case WEST:
    case EAST:    return 0.6F;   // 东西侧面喵
}
```

数值推导喵：

```
侧面底部深色带 × 东西方向光 = (110,112,128) × 0.6 = (66,67,76)   // 深灰近黑喵
侧面底部深色带 × 南北方向光 = (110,112,128) × 0.8 = (88,90,102)  // 深灰喵
```

在亮色地表（草/石，亮度约 130~200）衬托下，这个 RGB(66~90) 的底带就是一条「黑色阴影」喵。四个侧面底部连成一圈，正是「黑色基台/平台」观感喵。

### 1.2 顶面也带深色边框喵

顶面 `up` 面 UV `[0,0,16,16]` 铺满贴图，贴图底部 6 行深色带对应**方块顶面南缘**喵。三张 quad 的透明区被 discard 后露出顶面，所以在转盘/炮管外围会看到一圈暗框（尤其南缘）喵。这是 Mindustry 底座贴图自带的设计，但 MC 里把它放成实体方块顶面后观感比 Mindustry 平面 sprite 更明显喵。

## 2. 排除项：上一轮「quad 共面 z-fighting」结论被证伪喵

### 2.1 y 偏移已生效，但阴影仍在喵

当前 `TurretBlockEntityRenderer.java` 已给三张 quad 分高度喵：

```java
pose.translate(0, 0.008f, topBack);        // 转盘世界 y = 1.028 喵
drawBarrel(..., TEX_BARREL_L, 0f, ...);    // 左管世界 y = 1.020 喵
drawBarrel(..., TEX_BARREL_R, 0.004f, ...);// 右管世界 y = 1.024 喵
```

源码与编译产物同为 08-12 12:49（`build/classes/java/main/.../TurretBlockEntityRenderer.class`），即该修复**已构建并实测**，用户仍见阴影喵。

### 2.2 深度精度计算：正常视距下 0.004 分离足够喵

24 位深度缓冲 + near=0.05，深度可分辨间隔 ≈ `dz·near/z²`，与缓冲分辨率 1/2²⁴ 对比喵：

| 视距 | 0.004 分离 | 0.02 分离（quad 距块顶）喵 |
|---|---|---|
| 10 格 | 33.5× 分辨率，够 | 167× 够喵 |
| 30 格 | 3.7× 分辨率，够 | 18.6× 够喵 |
| 50 格 | 1.3× 分辨率，临界 | 6.7× 够喵 |
| 80 格 | 0.5× 分辨率，失效 | 2.6× 够喵 |

正常游戏视距（5~40 格）下 0.004 分离远超深度精度，三 quad 不再共面，LEQUAL 深度测试确定化，转盘总是盖住炮管根部喵。**唯一残余风险是 50 格外三 quad 又进入 z-fighting 区间**，但那只是次要的远距离闪跳，不是用户持续看到的「黑色阴影」喵。

### 2.3 其余渲染环节全部排除喵

- **透明变黑**：`client-extra.jar` 内 `rendertype_entity_cutout.fsh` 确认 `if (color.a < 0.1) discard;`，alpha=0 像素被正确丢弃，不会露黑喵。
- **光照**：`light.glsl` 的 `minecraft_mix_light` 对法线 (0,1,0) 与 `Light0/1_Direction`（都含正 Y）得 `lightAccum = min(1, 2×0.6+0.4) = 1.0` 全亮；`getLightColor(blockpos)` 白天地表 = `0xF00000`（sky=15），光贴图采样全白，quad 不暗喵。
- **overlay**：`BlockEntityRenderDispatcher.setupAndRender` 传 `OverlayTexture.NO_OVERLAY`，采 overlay 纹理第 10 行全白像素，不压黑（对照 `docs/研究-PowerNode激光黑色.md` 的 `0xFFFFFF` 越界黑案例，本处无此问题）喵。
- **blockstate 空 variant**：`BlockModelDefinition.predicate` 对空 key 生成空属性谓词，匹配该方块全部 corner 状态，模型正常加载，不是「missing model」黑盒喵。

## 3. 真正主因：底座 `cube_all` 侧面贴俯视图 = 「深色基台」喵

上一轮报告 `docs/研究-炮塔黑色阴影.md` 的主因判断（三 quad 共面 z-fighting）**是错的**，但其「次要成因」**才是真正主因**喵。对照钻机：

| 项目 | 钻机 drill（正常）喵 | 炮塔 turret（黑色阴影）喵 |
|---|---|---|
| 底座模型 | `drill_nw/ne/sw/se`：顶面 `drill.png` 俯视 + **侧面 `drill_side.png` 外壳** 喵 | `cube_all`：**六面全贴俯视 `turret_base.png`** 喵 |
| 侧面观感 | 设计的金属外壳面板，不显「拉伸俯视图」喵 | 俯视图拉伸 + 底部深色阴影带，显「黑基台」喵 |
| 侧面方向光 | ×0.6/0.8 后是「设计的深灰外壳」喵 | ×0.6/0.8 后是「俯视图的深色边框带」喵 |

钻机侧面虽也深，但是**设计的机器外壳**（`drill_side.png` 是正面面板图，含深灰面板），观感协调；炮塔侧面是**俯视图拉伸**，底部那 6 行深色带在四条侧面上正好合成一圈「阴影基台」，用户描述为「黑色阴影」喵。

## 4. 最小可落地修复方案喵

### 4.1 主修复（模型，零新资产）：turret.json 改「顶面俯视 + 侧面外壳」喵

参照 `models/block/drill_nw.json` 的写法，把 `models/block/turret.json` 从 `cube_all` 改为六面体：顶面贴 `turret_base`（保留 Mindustry 俯视底座），**侧面贴 `drill_side`（与 drill 统一的机器外壳）**喵：

```json
{
  "parent": "minecraft:block/block",
  "textures": {
    "particle": "blockdustry:block/turret_base",
    "side": "blockdustry:block/drill_side",
    "top": "blockdustry:block/turret_base"
  },
  "elements": [
    {
      "from": [0, 0, 0],
      "to": [16, 16, 16],
      "faces": {
        "down":   { "uv": [0, 0, 16, 16], "texture": "#side" },
        "up":     { "uv": [0, 0, 16, 16], "texture": "#top" },
        "north":  { "uv": [0, 0, 16, 16], "texture": "#side" },
        "south":  { "uv": [0, 0, 16, 16], "texture": "#side" },
        "east":   { "uv": [0, 0, 16, 16], "texture": "#side" },
        "west":   { "uv": [0, 0, 16, 16], "texture": "#side" }
      }
    }
  ]
}
```

- `blockstate`、Java、物品模型均无需改动（`models/item/turret.json` 直接继承方块模型，物品图标自动更新）喵。
- 若想让侧面更贴合炮塔风格，可新建 `textures/block/machine_side.png`（RGB(107,108,116) 系深灰蓝面板，见 `docs/研究-机器侧面贴图.md` 方案 c），再把上面 `side` 指向它喵。

### 4.2 可选加固（仅当确认有远距离闪跳才做）喵

当前三 quad 的 y 分离（0/0.004/0.008）在 50 格外会退回 z-fighting 区间喵。若用户在远距离还看到「脏/闪跳」，可把分离加大到 0.02 一档（转盘 +0.06、右管 +0.04、左管 +0.02），或改用 `RenderType.entityCutoutNoCullZOffset` 对 quad 做恒定深度偏移（该类型带 polygon offset）喵。此步骤是锦上添花，不是「黑色阴影」的主修复喵。

## 5. 验证手段喵

1. **只改模型验证主因**：把 `models/block/turret.json` 临时改成纯六面 `minecraft:block/stone`（或上面的顶+侧结构），重进游戏或按 `F3+T` 重载资源喵。若「黑色阴影」消失 → 铁证是底座模型喵。
2. **反证 quad 假说**：临时在 `TurretBlockEntityRenderer` 里只画转盘一张 quad（注释掉两处 `drawBarrel`）喵。若「黑色阴影」仍在 → 与 quad 数量/共面完全无关喵。
3. **远近距离区分**：在 50 格外再观察是否有残余「脏/闪跳」（那是远距离 z-fighting，需 4.2 加固）；近距离的「黑基台」则靠 4.1 模型修复喵。
