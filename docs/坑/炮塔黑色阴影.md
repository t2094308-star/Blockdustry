# 研究：炮塔「黑色阴影」根因排查与修复喵

## 结论一句话喵

炮塔的「黑色阴影」**不是**贴图问题、**不是**透明裁切失效、**也不是**与方块顶面的 z-fighting，而是**三层叠画的 quad（转盘 top + 左/右炮管）在 y=1.02 完全共面且互相重叠**，`RenderType.entityCutout` 又写深度，导致三张 quad 在重叠区发生**像素级 z-fighting**：GPU 按浮点深度噪声在每像素上随机选一个 quad，深色的 `duo-barrel-l`（RGB 143,102,91）就一块块「渗」到较亮的转盘上，形成**发暗、闪跳的阴影**。炮塔开火期间后坐力让三张 quad 永远错位（topBack 与 barrelShift 最大差 0.1875），所以阴影在开火时**持续存在**喵。

次要成因：底座是 `cube_all`，六面全贴俯视 `turret_base`，侧面是「俯视贴图直接贴」的拉伸观感，且该贴图带深灰边（RGB 110,112,128），使底座侧面像一圈深色基台，加重「黑影」观感喵。

修复：**给三张 quad 分配不同的 y 高度（差 0.005 即可，不可见）消除共面**，让深度排序确定化；底座模型改为「顶面俯视图 + 侧面外壳贴图」结构（与 drill 一致）喵。

---

## 1. 排查过程与排除项喵

### 1.1 贴图：全部干净，排除贴图内容喵

用 PIL 逐像素统计了 5 张贴图喵：

| 贴图 | 尺寸 | 透明分布 | 半透明 | 不透明黑像素(rgb<32) | 深色(rgb<64) | 最暗不透明RGB |
|---|---|---|---|---|---|---|
| `entity/turret_top.png` | 32×32 | a=0:708 / a=255:316 | 0 | 0 | 0 | (143,102,91) |
| `entity/turret_barrel_l.png` | 32×32 | a=0:946 / a=255:78 | 0 | 0 | 0 | (143,102,91) |
| `entity/turret_barrel_r.png` | 32×32 | a=0:946 / a=255:78 | 0 | 0 | 0 | (201,165,143) |
| `block/turret_base.png` | 32×32 | a=255:1024（全不透明） | 0 | 0 | 0 | (110,112,128) |
| `block/turret.png`（旧底座，已不引用） | 32×32 | a=0:554 / a=255:470 | 0 | 0 | 0 | — |

- 三张实体贴图都是**二值 alpha（透明=0 / 不透明=255）**，无半透明像素喵。
- **没有任何黑色像素**（rgb<32 为 0），最暗的不透明像素也只是深灰/深棕（rgb 143,102,91），不是黑喵。
- 所以**黑色不可能来自贴图内容本身**喵。

注意：三张实体贴图的**透明像素 RGB 都是 (0,0,0) 纯黑**，这是「透明像素变黑」类问题的常见放大器——只要透明区没被丢弃就会显示黑色方块（见第 1.3 节确认丢弃逻辑正常）喵。

### 1.2 底座方块：完全不透明，排除底座纹理喵

- 当前 `models/block/turret.json` = `cube_all`，贴 `blockdustry:block/turret_base`，`turret_base.png` 1024/1024 像素全不透明，且无黑色像素喵。
- 最暗像素 rgb(110,112,128)，即使乘 MC 侧面定向光照（×0.6）也只有 rgb(66,67,76)，达不到「黑」喵。
- 底座实体方块渲染为 SOLID（默认 cube_all + 全不透明贴图），顶面在 y=1.0，光照正常喵。
- **底座贴图不可能是黑色阴影的来源**喵。

### 1.3 渲染管线：entityCutout 丢弃逻辑正确，排除渲染类型喵

反编译 + 读取客户端 jar 内 `assets/minecraft/shaders/core/rendertype_entity_cutout.fsh` 确认喵：

```glsl
vec4 color = texture(Sampler0, texCoord0);
if (color.a < 0.1) { discard; }        // 透明像素被丢弃喵
color *= vertexColor * ColorModulator;
color.rgb = mix(overlayColor.rgb, color.rgb, overlayColor.a);
color *= lightMapColor;
fragColor = linear_fog(color, vertexDistance, FogStart, FogEnd, FogColor);
```

- `entityCutout` 是**丢弃**（alpha<0.1 就 discard），不是混合（渲染状态 `NO_TRANSPARENCY`）喵。
- 贴图 alpha=0 的透明像素会**被正确丢弃**，露出下方的底座顶面，不会变黑喵。
- 渲染状态：`TextureStateShard(loc, false, false)` → 采样器 NEAREST、**无 mipmap**（所以不存在 mipmap 黑边）；`COLOR_DEPTH_WRITE`（写深度）；深度测试 LEQUAL；`LIGHTMAP` + `OVERLAY` 绑定喵。
- overlay：`BlockEntityRenderDispatcher.render` 反编译确认传给 BER 的 overlay 是 `OverlayTexture.NO_OVERLAY`（= pack(0,10)，白色），与 drill 一致，**overlay 无误**喵。
- 光：`LevelRenderer.getLightColor` 在方块位置取光，白天地表满亮，法线 (0,1,0) 对 `DIFFUSE_LIGHT_0/1`（含 +Y 分量）`lightAccum=1.0` 全亮，**光照无误**喵。

结论：**只要正确用 `entityCutout`，透明像素绝不会变黑**。文档 `研究-炮塔动画.md` 注意事项 7 说的「不用 entityCutout 透明像素会变黑」，当前代码已满足喵。

### 1.4 与方块顶面的 z-fighting：排除喵

- quad 在 y=1.02，方块顶面在 y=1.0，间距 0.02喵。
- 24 位深度缓冲，near=0.05 时，20 格距离下深度精度约 0.0005，0.02 间距是精度的 40 倍，正常视距**不会**与方块顶面 z-fighting喵。
- 而且 drill 的转盘也在 y=1.02（单张 2×2 quad），用户反馈 drill 正常——若 quad 与方块顶面 z-fighting，drill 也该黑，所以**不是**这个喵。

### 1.5 与 drill 的唯一实质差异：三张共面重叠 quad vs 单张 quad喵

| 项目 | DrillBlockEntityRenderer（正常）喵 | TurretBlockEntityRenderer（黑阴影）喵 |
|---|---|---|
| RenderType | `entityCutout` 喵 | `entityCutout` 喵 |
| 叠画 quad 数量 | **1 张** 喵 | **3 张**（转盘 + 左右炮管）喵 |
| quad 高度 | 全部 y=1.02 喵 | 三张**全部 y=1.02，互相共面且重叠** 喵 |
| quad 尺寸 | 2×2（-1..1）喵 | 1×1（-0.5..0.5），炮管在 z 方向平移最多 0.25 喵 |
| 底座模型 | `drill_nw/ne/sw/se`：顶面俯视图 + **侧面 `drill_side`** 喵 | `cube_all`：六面全贴俯视 `turret_base` 喵 |
| 透明像素 RGB | (0,0,0) 黑 喵 | (0,0,0) 黑 喵 |

唯一能解释「炮塔黑、钻机不黑」的差异就是：**炮塔把三张 quad 画在了同一高度、互相重叠**喵。

## 2. 根因：三张共面 quad 的 z-fighting + 深色左炮管喵

### 2.1 几何事实喵

`TurretBlockEntityRenderer.render()` 里三张 quad 全部落在 y=1.02 这个水平面上喵：

```java
pose.translate(0.5f, 1.02f, 0.5f);          // 转盘本体喵
pose.translate(0, 0, topBack); drawQuad(...); // 转盘喵
drawBarrel(..., TEX_BARREL_L, topBack + 1.5f * rl / 8f, ...); // 左炮管喵
drawBarrel(..., TEX_BARREL_R, topBack + 1.5f * rr / 8f, ...); // 右炮管喵
```

`drawBarrel` 内部 `pose.translate(0, 0, back)` 只平移 z，**三张 quad 的 y 始终相同（共面）**喵。

### 2.2 z-fighting 的机制喵

- 三张 quad 都经过 `RenderType.entityCutout`，渲染状态 `COLOR_DEPTH_WRITE`（写深度）+ LEQUAL 深度测试喵。
- 后坐力位移：`topBack = pow(top,1.8)*0.5/8`（最大 0.0625），炮管另加 `1.5*rl/8`（最大 0.1875），所以开火后三张 quad **错位但仍在同一 y 平面**（共面）喵。
- 共面但错位的两张 quad 在同一像素上的深度**数学上相等**（光线与同一水平面的交点唯一），但**浮点插值路径不同**，产生逐像素的深度噪声喵。
- GPU 按深度噪声在重叠区**随机**决定谁通过 LEQUAL 测试，即 z-fighting：同一像素可能显示转盘、也可能显示炮管，且随视角/帧变化闪跳喵。
- 左炮管 `duo-barrel-l` 是深棕灰（RGB 143,102,91），比转盘（灰 96~224）暗很多；z-fighting 让深色炮管像素「一块块」盖到转盘上，形成**发暗、脏、闪跳的阴影**喵。

### 2.3 为什么阴影持续存在喵

`TurretBlockEntity.tickAnchor()` 里后坐力 `1/20` 线性衰减，reload=20 tick 又开火置 1，所以**连续开火时后坐力永远到不了 0**喵：

```
tick0: topBack=0.0625  barrelShift=0.2500   （三 quad 错位喵）
tick19: topBack=0.0003  barrelShift=0.0097  （仍错位喵）
```

20 tick 里 19 tick 三张 quad 都处于「共面但错位」状态，z-fighting **约 95% 时间持续存在**喵。

### 2.4 次要成因：底座 cube_all 侧面贴俯视图喵

`models/block/turret.json` 是 `cube_all`，六面全贴俯视 `turret_base`；而 drill 底座（`drill_nw/ne/sw/se.json`）侧面用 `drill_side`。俯视图贴侧面是「拉伸 + 带深色边框」的观感（turret_base 边缘 RGB 110,112,128），底座像一圈深色基台，**即使底座贴图完全不透明也消除不掉**，与用户「换了不透明底座贴图后依然存在」吻合（因为换贴图不影响侧面贴俯视图的事实）喵。

## 3. 修复方案喵

### 3.1 主修复（代码）：消除三张 quad 的共面性喵

给转盘、左炮管、右炮管分配**互不相同的微小 y 偏移**，让深度排序确定化、不再有浮点噪声喵。偏移 0.005（约 1/6 像素）肉眼不可见，但远大于深度精度喵。

修改 `TurretBlockEntityRenderer.java` 的 `drawBarrel` 与 `drawQuad` 调用，让三张 quad 的高度不同喵：

```java
// 转盘本体：保持在 y=1.02（drawQuad 内局部 y=0，世界 y=1.02）喵
pose.pushPose();
pose.translate(0, 0, topBack);
drawQuad(pose, buffer, TEX_TOP, light, overlay);          // 世界 y = 1.020 喵
pose.popPose();

// 双炮管：分别再抬 0.005 / 0.010，与转盘（及彼此）错开高度，消除共面 z-fighting 喵
drawBarrel(pose, buffer, TEX_BARREL_L, topBack + 1.5f * rl / 8f, 0.005f, light, overlay);
drawBarrel(pose, buffer, TEX_BARREL_R, topBack + 1.5f * rr / 8f, 0.010f, light, overlay);
```

`drawBarrel` 增加一个 `float liftY` 参数，平移时带上 y 偏移喵：

```java
private void drawBarrel(PoseStack pose, MultiBufferSource buffer, ResourceLocation tex,
                        float back, float liftY, int light, int overlay) {
    pose.pushPose();
    pose.translate(0, liftY, back);   // 原为 translate(0, 0, back)，加 liftY 喵
    drawQuad(pose, buffer, tex, light, overlay);
    pose.popPose();
}
```

要点喵：

- 三张 quad 现在位于 y=1.020 / 1.025 / 1.030，**不再共面**，LEQUAL 深度测试总是「后画的（更高、更近）赢」，转盘→左炮管→右炮管的叠画**确定化**，不再闪跳喵。
- 0.005 偏移在 1 格 = 32px 的密度下约 0.16px，完全不可见喵。
- 若想还原 Mindustry `RegionPart.under=true`（炮管画在转盘下方，转盘盖住炮管根部）的层级，可反过来：转盘 y=1.020，炮管 y=1.015/1.010（更低），效果是转盘盖住炮管根部、炮管尖露出，更贴 Mindustry 原版喵。

### 3.2 副修复（资源）：底座改为「顶面 + 侧面外壳」模型喵

参照 drill 底座 `drill_nw.json` 的写法，把 `models/block/turret.json` 从 `cube_all` 改成六面体：顶面贴 `turret_base`（俯视），侧面贴现成的 `blockdustry:block/drill_side`（或新建 `machine_side.png` 深灰金属外壳，见 `研究-机器侧面贴图.md` 方案 c）喵：

```json
{
  "parent": "minecraft:block/block",
  "textures": {
    "particle": "blockdustry:block/turret_base",
    "side": "blockdustry:block/drill_side",
    "top": "blockdustry:block/turret_base"
  },
  "elements": [
    {
      "from": [0, 0, 0],
      "to": [16, 16, 16],
      "faces": {
        "down":   { "uv": [0, 0, 16, 16], "texture": "#side" },
        "up":     { "uv": [0, 0, 16, 16], "texture": "#top" },
        "north":  { "uv": [0, 0, 16, 16], "texture": "#side" },
        "south":  { "uv": [0, 0, 16, 16], "texture": "#side" },
        "east":   { "uv": [0, 0, 16, 16], "texture": "#side" },
        "west":   { "uv": [0, 0, 16, 16], "texture": "#side" }
      }
    }
  ]
}
```

blockstate / Java / 物品模型均无需改动（物品模型直接继承方块模型）喵。

### 3.3 参考：drill 为什么没这个问题喵

drill 只画**一张** quad（转盘），没有第二张与它共面的 quad，所以不存在「quad 互 z-fighting」喵。它唯一的共面风险是与方块顶面（y=1.0），但间距 0.02 远超深度精度，且实体 quad 先丢弃透明区再与方块比深度，正常无冲突喵。turret 的问题在于**自己把三张 quad 叠在同一高度**喵。
