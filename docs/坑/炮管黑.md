# 研究：炮塔「炮管渲染成黑色」真正根因彻查喵

## 结论一句话喵

炮管「黑」**不是**贴图颜色、**不是** overlay、**不是**法线/方向光、**也不是**深度遮挡，而是**BER 透传的 `light` 参数在白天只有"天光"(blockLight=0) 这一路，entityCutout 光贴图在 (block=0, sky=15) 采样出的是很暗的灰蓝黑，深棕炮管 × 这个暗光 = 视觉上接近纯黑**喵。本 mod 的 `CombustionGeneratorBlockEntityRenderer` 和 `PowerNodeBlockEntityRenderer` 早就踩过同一个坑，并**硬编码 `setLight(0xF000F0)`(FULL_BRIGHT)** 绕开；只有 `TurretBlockEntityRenderer` 还在透传 `light` 参数，所以炮管/转盘一起发暗，而最深的炮管被用户描述为"黑色"喵。修复：把炮塔渲染器的 `setLight(light)` 改成 `setLight(0xF000F0)`(LightTexture.FULL_BRIGHT) 即可立即验证喵。

---

## 1. 直接证据：本 mod 其它渲染器已经踩过「light 参数太暗」的坑喵

对比 `src/main/java/com/blockdustry/client/` 下所有用 entity 着色器的渲染器喵：

| 渲染器 | RenderType | setLight | 用户观感喵 |
|---|---|---|---|
| `CombustionGeneratorBlockEntityRenderer` | entityTranslucent | **`0xF000F0` 硬编码** | 正常暖橙喵 |
| `PowerNodeBlockEntityRenderer` | entityTranslucent | **`0xF000F0` 硬编码** | 正常光束喵 |
| `DrillBlockEntityRenderer` | entityCutout | 透传 `light` | 正常（2×2 大 quad 显暗但不显黑）喵 |
| `BlockdustryBulletRenderer` | entityTranslucent | 透传 `light` | 正常（动态光也能亮）喵 |
| `TurretBlockEntityRenderer` | entityCutout | **透传 `light`** | **炮管黑** 喵 |

`CombustionGeneratorBlockEntityRenderer.java` 第 39 行注释白纸黑字喵：

```java
// 暖橙 #ff9b59 染色（255,155,89），全亮不随环境光变暗（之前受光照太微弱），NO_OVERLAY 避免越界采样染黑喵
```

`PowerNodeBlockEntityRenderer.java` 第 113 行注释同理喵：

```java
.setLight(0xF000F0) // 全亮，不随环境光照变暗喵
```

即：**mod 作者在燃烧发电机和电力节点上已经实测「透传 light 参数 → 受光照太微弱」，并靠硬编码 FULL_BRIGHT 修复**喵。炮塔渲染器正是漏改的那个喵。

## 2. 为什么 `light` 参数在白天会暗到把炮管变黑喵

### 2.1 `light` 的来源喵

`BlockEntityRenderDispatcher.setupAndRender`（`build/neoForm/.../blockentity/BlockEntityRenderDispatcher.java` 第 80-92 行）把 `light = LevelRenderer.getLightColor(level, blockEntity.getBlockPos())` 传给 BER 喵。

`LevelRenderer.getLightColor`（第 3628-3641 行）喵：

```java
int i = level.getBrightness(LightLayer.SKY, pos);    // 地表白天 = 15 喵
int j = level.getBrightness(LightLayer.BLOCK, pos);  // 无火把时 = 0 喵
return i << 20 | j << 4;                              // = 15<<20 | 0<<4 = 0xF00000 喵
```

地表白天的方块：**sky=15、block=0**，packedLight = `0xF00000`（注意 block 那一路是 0）喵。

### 2.2 shader 如何用它采样光贴图喵

`rendertype_entity_cutout.vsh`（客户端 jar 内）喵：

```glsl
lightMapColor = texelFetch(Sampler2, UV2 / 16, 0);
```

`setLight(0xF00000)` → `setUv2(0x0000, 0x00F0)` → `UV2 = (0, 240)` → `UV2/16 = (0, 15)`喵。

即采 16×16 光贴图 **(block=0, sky=15)** 那个格子喵。

### 2.3 光贴图在 (block=0, sky=15) 到底多亮喵

`LightTexture.updateLightTexture`（`LightTexture.java` 第 79-169 行）逐格生成光贴图喵：

```java
float f = clientlevel.getSkyDarken(1.0F);          // 白天正午 ≈ 0.2 喵
float f1 = f * 0.95F + 0.05F;                     // ≈ 0.24 喵
...
for (int i = 0; i < 16; i++) {        // i = sky 喵
  for (int j = 0; j < 16; j++) {      // j = block 喵
    float f8 = getBrightness(dim, i) * f1;         // 天光贡献，白天被 f1≈0.24 压暗喵
    float f9 = getBrightness(dim, j) * f7;         // 方块光贡献，block=0 → 0 喵
    ...
    this.lightPixels.setPixelRGBA(j, i, ...);
  }
}
```

按此公式在正午推算，**(block=0, sky=15) ≈ (115,115,161) 灰蓝 → 经 gamma 后约 (69~115, 69~115, 119~161)，即只有满亮的三四成**喵。而 **(block=15, sky=15) 才是纯白 (255,255,255)** 喵。这就是 `0xF00000`(透传 light) 与 `0xF000F0`(FULL_BRIGHT) 的实质差距——一个暗一个亮喵。

### 2.4 数值：深棕炮管 × 暗光 = 黑喵

| 贴图像素 | 源色 | × (0,15) 暗光 ~45% | 观感喵 |
|---|---|---|---|
| 左管（提亮前） | (143,102,91) | (64,46,41) | 近黑喵 |
| 左管（提亮后） | (184,146,127) | (83,66,57) | 仍近黑喵 |
| 右管 | (201,165,143) | (90,74,64) | 暗棕近黑喵 |
| 转盘高光 | (244,244,244) | (110,110,110) | 灰（勉强可辨，用户以为"正常"）喵 |

左管提亮 16% 在暗光下只差 19 个亮度值，炮管又只有细细一条斜条，**用户看不出变化 → "毫无变化，依旧黑色"**，与现象完全吻合喵。

## 3. 排除项（逐条证伪其它假说）喵

### 3.1 不是贴图颜色本身喵

- 右管源色是亮棕 (201,165,143)，若贴图被正确采样，满光下绝不可能是黑喵。
- 左管已提亮 (143→184)，暗光下仍近黑，故"黑"与贴图颜色无直接因果喵。

### 3.2 贴图确实加载了喵

- `RenderType.entityCutout(loc)` 是 `TextureStateShard(loc, false, false)` → **直接绑定 SimpleTexture，不走 block atlas**，路径即 `blockdustry:textures/entity/xxx.png`，与代码引用一致喵。
- `src` 与 `build/resources/main` 的 `turret_barrel_l/r.png` **逐字节一致**（14:39/14:40 都已更新为提亮版），且均为合法 32×32 RGBA PNG（IHDR/IDAT/IEND，PIL 与原始 zlib 解码都得到正确的亮棕像素）喵。
- `run/client/logs/latest.log`、`debug.log`（14:53/14:57/15:07/15:10 四次会话）**无一条 "Failed to load texture"**，故不是 missing texture 黑盒喵。

### 3.3 不是 overlay / 法线 / 方向光喵

- overlay 是 `BlockEntityRenderDispatcher` 传入的 `OverlayTexture.NO_OVERLAY`（=pack(0,10)，采 overlay 第 10 行全白像素），与 drill/正常渲染器一致喵。
- `light.glsl` 的 `minecraft_mix_light` 对法线 (0,1,0) 与 `Lighting.DIFFUSE_LIGHT_0/1`（都含 +Y 分量）得 `lightAccum = min(1, (1+1)*0.6+0.4) = 1.0` 全亮，方向光不暗喵。
- 转盘与炮管同一 `drawQuad`、同一 light/overlay/normal/color，唯一差别是贴图与 y 偏移，故差异只能来自光照/贴图采样，而贴图已确认正常喵。

### 3.4 不是几何遮挡 / z-fighting喵

- 逐像素计算：转盘 (turret_top) 与左炮管 opaque 像素**只重叠 1 个像素**（barrel 共 78 像素中 77 个可见），炮管并非被转盘盖住喵。
- y 偏移 0/0.004/0.008 在正常视距（<50 格）下远超深度精度，无 z-fighting 喵。
- 炮管 quad 法线朝上、绕序正确，entityCutout 的默认 CULL 不会把它剔除喵。

### 3.5 与 drill 的唯一实质差异喵

drill 也是 `entityCutout` + 透传 `light`，但 drill 是 **2×2 的大 quad + 亮棕金属色**，暗光下是"暗色转盘"，用户不当成黑；炮管是**1×1 上细细的斜条 + 深棕**，暗光下就成了"黑线"喵。若把 drill 的 light 也改成 FULL_BRIGHT，drill 会更亮，但 drill 现状并未被用户定性为缺陷喵。

## 4. 修复方案（可立即验证）喵

### 4.1 主修复（代码，改动最小）喵

把 `TurretBlockEntityRenderer.drawQuad` 里 `setLight(light)` 换成 `setLight(LightTexture.FULL_BRIGHT)`，overlay 一并换成 `OverlayTexture.NO_OVERLAY`，与本 mod 已验证正常的 `CombustionGenerator` / `PowerNode` 渲染器对齐喵：

```java
import net.minecraft.client.renderer.LightTexture;
import net.minecraft.client.renderer.texture.OverlayTexture;

private void drawQuad(PoseStack pose, MultiBufferSource buffer, ResourceLocation tex, int light, int overlay) {
    VertexConsumer vc = buffer.getBuffer(RenderType.entityCutout(tex));
    var matrix = pose.last().pose();
    // 全亮：entityCutout 光贴图在 (block=0,sky=15) 太暗，必须用 FULL_BRIGHT 才不会把深棕炮管压成黑喵
    vc.addVertex(matrix, -0.5f, 0f, -0.5f).setUv(0f, 0f).setColor(255, 255, 255, 255).setLight(LightTexture.FULL_BRIGHT).setOverlay(OverlayTexture.NO_OVERLAY).setNormal(0f, 1f, 0f);
    vc.addVertex(matrix, -0.5f, 0f, 0.5f).setUv(0f, 1f).setColor(255, 255, 255, 255).setLight(LightTexture.FULL_BRIGHT).setOverlay(OverlayTexture.NO_OVERLAY).setNormal(0f, 1f, 0f);
    vc.addVertex(matrix, 0.5f, 0f, 0.5f).setUv(1f, 1f).setColor(255, 255, 255, 255).setLight(LightTexture.FULL_BRIGHT).setOverlay(OverlayTexture.NO_OVERLAY).setNormal(0f, 1f, 0f);
    vc.addVertex(matrix, 0.5f, 0f, -0.5f).setUv(1f, 0f).setColor(255, 255, 255, 255).setLight(LightTexture.FULL_BRIGHT).setOverlay(OverlayTexture.NO_OVERLAY).setNormal(0f, 1f, 0f);
}
```

- `LightTexture.FULL_BRIGHT = 0xF000F0`（=15728880），`UV2/16 = (15,15)` 采光贴图最亮白像素喵。
- `light`/`overlay` 形参随之可删或忽略；转盘也会一起变亮（观感更贴近 Mindustry 原版浅色转盘）喵。
- 若想保留"环境光让炮塔夜晚变暗"的玩法效果，可改用 `Math.max(light, LightTexture.FULL_BLOCK | (light & LightTexture.FULL_SKY))` 之类的保底，但最直接的验证就是 FULL_BRIGHT 喵。

### 4.2 立即验证方法喵

1. 只改 `drawQuad` 的 `setLight` → 重跑 `runClient`喵。若炮管变亮棕/浅色 → 根因就是 light 太暗，铁证喵。
2. 若仍黑 → 再临时把 `TEX_BARREL_L/R` 的 ResourceLocation 换成 `TEX_TOP`（转盘图）喵。若"炮管"显示转盘圆形 → 贴图路径/加载有问题；若仍黑 → 与贴图无关，往渲染状态（如 CULL）查喵。

### 4.3 资源确认喵

`build/resources/main/assets/blockdustry/textures/entity/turret_barrel_l.png`（14:40）与 src（14:39）逐字节一致，都是提亮版 (184,146,127)，**已复制到位，无需再处理**喵。dev 运行按 `debug.log` 第 25 行 `Got mod coordinates 仓库%%D:\Blockdustry\仓库\build\resources\main` 从 build/resources 读资源，因此改 src 后必须重跑 `processResources`/`runClient` 才会生效喵。
