### 2.1 links 存储喵

### 2.2 linkValid 完整逻辑喵
```java
public boolean linkValid(Building tile, Building link, boolean checkMaxNodes){
    if(tile == link || link == null || !link.block.hasPower || !link.block.connectedPower
        || tile.team != link.team || (sameBlockConnection && tile.block != link.block)) return false;

    if(overlaps(tile, link, laserRange * tilesize)
        || (link.block instanceof PowerNode node && overlaps(link, tile, node.laserRange * tilesize))){ // 任一端在对方范围内即可（双向）喵
        if(checkMaxNodes && link.block instanceof PowerNode node){
            return link.power.links.size < node.maxNodes || link.power.links.contains(tile.pos()); // 对方已满但已连着本节点也放行喵
        }
        return true;
    }
    return false;
}
```
判定要素：非同点、目标 `hasPower` + `connectedPower`、同队、`sameBlockConnection=false` 允许连同类节点、距离双向重叠、对方未满（或已连）喵。

### 2.3 overlaps（圆 vs 包围盒相交）喵
```java
protected boolean overlaps(float srcx, float srcy, Tile other, Block otherBlock, float range){
    return Intersector.overlaps(Tmp.cr1.set(srcx, srcy, range),
        Tmp.r1.setCentered(other.worldx() + otherBlock.offset, other.worldy() + otherBlock.offset,
            otherBlock.size * tilesize, otherBlock.size * tilesize));
}
// 简单版本用 other.getHitbox(Tmp.r1)（包围盒），还有 Building/Tile 重载喵
public boolean overlaps(@Nullable Tile src, @Nullable Tile other){
    if(src == null || other == null) return true; // 空 tile 视为可连（预览时用）喵
    return Intersector.overlaps(Tmp.cr1.set(src.worldx() + offset, src.worldy() + offset, laserRange * tilesize),
        Tmp.r1.setSize(size * tilesize).setCenter(other.worldx() + offset, other.worldy() + offset));
}
```
即：以节点中心为圆心、`laserRange * tilesize` 为半径的圆，与目标方块尺寸的 AABB 求交喵。目标越大越容易连上喵。

## 3. 连接/断开与拆图喵

### 3.1 config(Integer) 单点连/断喵
```java
config(Integer.class, (entity, value) -> {
    PowerModule power = entity.power;
    Building other = world.build(value);
    boolean contains = power.links.contains(value), valid = other != null && other.power != null;

    if(contains){
        // 断开：双向移除喵
        power.links.removeValue(value);
        if(valid) other.power.links.removeValue(entity.pos());

        PowerGraph newgraph = new PowerGraph();
        newgraph.reflow(entity);    // BFS 从本节点重铺这一侧子图喵
        newgraph.update();

        if(valid && other.power.graph != newgraph){
            PowerGraph og = new PowerGraph();
            og.reflow(other);       // 另一端单独拆新图喵
            og.update();
        }
    }else if(linkValid(entity, other) && valid && power.links.size < maxNodes){
        power.links.addUnique(other.pos());
        if(other.team == entity.team){
            other.power.links.addUnique(entity.pos()); // 同队才回连（异队不能连）喵
        }
        power.graph.addGraph(other.power.graph);        // 合并电网（小并入大）喵
    }
});
```
断开即"拆图"：`reflow` 用 BFS 从断点重新收集可达建筑形成新图，替代旧图；若断点两端分别 reflow 则切成两个独立电网喵。

### 3.2 PowerGraph.reflow（BFS 重建）喵
```java
public void reflow(Building tile){
    queue.clear();
    queue.addLast(tile);
    closedSet.clear();
    while(queue.size > 0){
        Building child = queue.removeFirst();
        add(child);                 // 把建筑按产/耗/电池分类塞进 graph 喵
        checkAdd();
        for(Building next : child.getPowerConnections(outArray2)){
            if(closedSet.add(next.pos())){
                queue.addLast(next);
            }
        }
    }
}
```

### 3.3 PowerGraph.remove（拆节点时）喵
```java
public void remove(Building tile){
    for(Building other : tile.getPowerConnections(outArray1)){
        if(other.power.graph != this) continue;
        PowerGraph graph = new PowerGraph();
        graph.checkAdd();
        graph.add(other);
        queue.clear();
        queue.addLast(other);
        while(queue.size > 0){
            Building child = queue.removeFirst();
            graph.add(child);
            for(Building next : child.getPowerConnections(outArray2)){
                if(next != tile && next.power.graph != graph){
                    graph.add(next);
                    queue.addLast(next);
                }
            }
        }
        graph.update();             // 每个断开的支路生成新图并立刻更新，让断电路立即掉电喵
    }
    if(entity != null) entity.remove();
}
```
由 `BuildingComp.powerGraphRemoved()` 在方块被移除/拆除时调用：先 `power.graph.remove(self())` 拆图，再遍历自己的 `links` 把另一端 `links` 里的自己删掉，最后清空自身 links 喵。

### 3.4 getPotentialLinks（自动搜索 + 排序）喵
```java
protected void getPotentialLinks(Tile tile, Team team, Cons<Building> others){
    if(!autolink) return;
    Boolf<Building> valid = other -> other != null && other.tile != tile && other.block.connectedPower
        && other.power != null
        && (other.block.outputsPower || other.block.consumesPower || other.block instanceof PowerNode)
        && overlaps(tile.x * tilesize + offset, tile.y * tilesize + offset, other.tile, laserRange * tilesize)
        && other.team == team
        && !graphs.contains(other.power.graph)         // 已连图不重复连喵
        && !PowerNode.insulated(tile, other.tile)
        && !(other instanceof PowerNodeBuild obuild && obuild.power.links.size >= ((PowerNode)obuild.block).maxNodes)
        && !Structs.contains(Edges.getEdges(size), p -> {...}); // 排除贴邻喵

    tempBuilds.clear();
    graphs.clear();
    // 先把邻近导电图的 graph 加入 graphs 防重连喵
    for(var p : Edges.getEdges(size)){
        Tile other = tile.nearby(p);
        if(other != null && other.team() == team && other.build != null && other.build.power != null){
            graphs.add(other.build.power.graph);
        }
    }
    if(tile.build != null && tile.build.power != null) graphs.add(tile.build.power.graph);

    var worldRange = laserRange * tilesize;
    var tree = team.data().buildingTree;              // 空间索引，矩形范围查询喵
    if(tree != null){
        tree.intersect(tile.worldx() - worldRange, tile.worldy() - worldRange, worldRange * 2, worldRange * 2,
            build -> { if(valid.get(build) && !tempBuilds.contains(build)) tempBuilds.add(build); });
    }
    // 排序：PowerNode 优先，其次按距离近优先喵
    tempBuilds.sort((a, b) -> {
        int type = -Boolean.compare(a.block instanceof PowerNode, b.block instanceof PowerNode);
        if(type != 0) return type;
        return Float.compare(a.dst2(tile), b.dst2(tile));
    });
    returnInt = 0;
    tempBuilds.each(valid, t -> {
        if(returnInt++ < maxNodes){
            graphs.add(t.power.graph);
            others.get(t);
        }
    });
}
```
要点：优先连"别的电力节点"，再按距离近连；一次最多 `maxNodes` 个；相邻建筑不自动连（走近距导电）；同一个图不连两次（避免重复冗余连接）喵。

public void drawLaser(float x1, float y1, float x2, float y2, int size1, int size2, boolean light){

## 5. 交互（点选再点目标）喵

`PowerNodeBuild.onConfigureBuildTapped(Building other)` 实现两阶段交互喵：
```java
@Override
public boolean onConfigureBuildTapped(Building other){
    if(linkValid(this, other)){          // 点了一个合法目标 → 直接连/断喵
        configure(other.pos());
        return false;
    }
    if(this == other){                   // 双击自己喵
        if(other.power.links.size == 0){ // 没连接 → 自动找并设置整组连接喵
            Seq<Point2> points = new Seq<>();
            getPotentialLinks(tile, team, link -> {
                if(!insulated(this, link) && points.size < maxNodes){
                    points.add(new Point2(link.tileX() - tile.x, link.tileY() - tile.y));
                }
            });
            configure(points.toArray(Point2.class));
        }else{                            // 已有连接 → 清空喵
            configure(new Point2[0]);
        }
        deselect();
        return false;
    }
    return true;                          // 其余交给引擎（默认行为）喵
}
```
配合引擎：点击该方块时 `configTapped()` 返回 true 进入配置态（`drawConfigure` 显示），再点击任意目标方块会回调 `onConfigureBuildTapped`；`configure(value)` 会 `Call.tileConfig(player, self(), value)` 发到服务端执行 config 回调喵。蓝图预览用 `drawPlanConfigTop` + `planConfigClipSize`（返回 `laserRange * tilesize * 2f + size * tilesize`）喵。

## 6. 与电网关系喵

- 节点自身 `consumesPower=false`、`outputsPower=false`，故 `PowerGraph.add(Building)` 里三个分支都不命中，节点只进 `all` 列表，不参与产/耗/电池结算，纯连通喵：
```java
public void add(Building build){
    ...
    build.power.graph = this;
    build.power.init = true;
    all.add(build);
    if(build.block.outputsPower && build.block.consumesPower && !build.block.consPower.buffered){
        producers.add(build); consumers.add(build);
    }else if(build.block.outputsPower && build.block.consumesPower){
        batteries.add(build);
    }else if(build.block.outputsPower){
        producers.add(build);
    }else if(build.block.consumesPower && build.block.consPower != null){
        consumers.add(build);
    }
}
```
- 连接时 `power.graph.addGraph(other.power.graph)`：小图并入大图（比较 `all.size`），被并图销毁其 `PowerGraphUpdater` 实体喵：
```java
public void addGraph(PowerGraph graph){
    if(graph == this) return;
    if(graph.all.size > all.size){ graph.addGraph(this); return; } // 保证小并大喵
    if(graph.entity != null) graph.entity.remove();
    for(Building tile : graph.all){ add(tile); }
    checkAdd();
}
```
- 每个电网有一个 `PowerGraphUpdater`（Entity 组件），每帧 `graph.update()` 结算产/耗/电池/覆盖率；`distributePower` 按 `coverage = min(1, produced/needed)` 统一给消费者写 `status`，电池用 `useBatteries`/`chargeBatteries` 等比例充放喵。
- 放置邻近方块时 `onProximityAdded → updatePowerGraph()`：把近距导电的建筑图并入本图；`getPowerConnections` 返回"近距导电邻居 + links 远程连接"，且排除"两个纯消费方块且都非 conductivePower"的情况（两耗电块不会互相导电）喵。
- 断开/拆除时 `PowerGraph.remove` 从断点把每支路切成独立新图，每图立刻 `update()`，保证断电即时生效喵。

## 7. 与原作对照：方块工业 MC 版差距喵

MC 版（`PowerNodeBlockEntity` + `PowerGridManager` + `PowerGrid`）已实现的：0 产 0 耗、`links` 双向记录、`linkValid`（同队/有电/圆形距离/对方未满）、`autolink`（放置后一次扫描）、范围 `LASER_RANGE=6f` 与圆形范围 `dx*dx+dz*dz<=r*r`、每 tick Union-Find 全量重建连通并结算功率喵。

主要差距（可对照完善点）：
1. **拆图方式**：原作断连时局部 `reflow` BFS 增量拆图、即时 `update()`；MC 版每 tick 全量 Union-Find 重建 O(n)，无增量、无断电即时性喵。
2. **maxNodes**：原作默认 3，MC 版 10（可保留作玩法调整）喵。
3. **insulated 射线遮挡**：原作激光不能穿过 `insulated` 方块；MC 版无喵。
4. **候选排序**：原作优先连 PowerNode 再按距离近排；MC 版按扫描顺序喵。
5. **防重复连图**：原作 `graphs` 集合避免同图重复连接；MC 版未做喵。
6. **邻接排除**：原作紧邻建筑不自动激光连（走近距导电）；MC 版自动连会把贴邻也连上喵。
7. **存储格式**：原作 links 存 int pos 且可进 schematic（`Point2[]` config 相对坐标）；MC 版存 BlockPos 列表 NBT喵。
8. **交互**：原作引擎级 config 态 + `onConfigureBuildTapped`（连/断/双击自动/清空）+ 范围圈高亮；MC 版用玩家 NBT 记选中节点 + 右键 toggle 喵。
9. **激光渲染**：原作 `setupColor` 按满足率 `lerp` + 呼吸闪烁 + 双向只画一次；MC 版客户端激光具体实现需对照（颜色渐变可选加）喵。
10. **图数据结构**：原作 `PowerGraph` 实时维护 producers/consumers/batteries 分类列表，`getSatisfaction` 等直接可用；MC 版每 tick 从接口方法临时统计喵。
