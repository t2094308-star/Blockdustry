# 机器动画与粒子效果迁移研究

> 研究目标：把 Mindustry 机器（石墨压缩机 graphite-press、燃烧发电机 combustion-generator）的 warmup 预热动画、craft 粒子特效、燃烧火花粒子迁移到「方块工业」MC mod（NeoForge 1.21.1，mojmap）喵。
> 结论一句话：服务端在 BE 里维护 warmup 并同步给客户端，BER 按 warmup 做染色/发光/旋转动画；craft 与周期触发用 `ServerLevel.sendParticles` 广播 MC 原版/自定义粒子喵。

## 1. Mindustry 侧机制剖析

### 1.1 GenericCrafter（石墨压机基类）

文件：`D:\Blockdustry\Mindustry\core\src\mindustry\world\blocks\production\GenericCrafter.java`

**数据字段**（`GenericCrafterBuild`，L186-189）喵：
- `float progress`：0..1 合成进度，由 `updateTile` 每 tick 累加 `getProgressIncrease(craftTime)`（L238）喵。
- `float totalProgress`：累计运行量（`totalProgress += warmup * Time.delta`，L257），供旋转部件用喵。
- `float warmup`：预热量 0..1，是动画/粒子的总开关喵。

**warmup 计算**（L235-254）喵：
```java
if(efficiency > 0){
    progress += getProgressIncrease(craftTime);
    warmup = Mathf.approachDelta(warmup, warmupTarget(), warmupSpeed); // warmupSpeed = 0.019
    ...
}else{
    warmup = Mathf.approachDelta(warmup, 0f, warmupSpeed);
}
```
- `approachDelta` 按 delta 逼近目标：启动后约 `1/0.019 ≈ 53 tick` 从 0 爬到 1，停止时同样速率衰减喵。
- `warmupTarget()` 默认返回 1f（L287-289），子类可改喵。

**craft 触发粒子**（L301-316）喵：
```java
public void craft(){
    consume();
    ...
    if(wasVisible){
        craftEffect.at(x, y);   // 仅在客户端可见（wasVisible）时生成特效
    }
    progress %= 1f;
}
```
- `craftEffect` 字段默认 `Fx.none`（L41），由块定义指定（石墨压机 = `Fx.pulverizeMedium`）喵。
- `wasVisible`：只在本端渲染时触发，避免服务端/离屏浪费喵。

**持续粒子**（L249-251）喵：
```java
if(wasVisible && Mathf.chanceDelta(updateEffectChance)){   // updateEffectChance = 0.04
    updateEffect.at(x + Mathf.range(size * updateEffectSpread), y + Mathf.range(size * updateEffectSpread));
}
```

**graphite-press 定义**（`D:\Blockdustry\Mindustry\core\src\mindustry\content\Blocks.java` L1040-1050）喵：
```java
graphitePress = new GenericCrafter("graphite-press"){{
    requirements(Category.crafting, with(Items.copper, 75, Items.lead, 30));
    craftEffect = Fx.pulverizeMedium;
    outputItem = new ItemStack(Items.graphite, 1);
    craftTime = 90f;
    size = 2;          // 2×2

```
- 石墨压机**没有** `drawer` 覆盖 → 用 `DrawDefault`，只有基础方块纹理，**无 warmup 染色**，视觉动画全靠 craft 粒子喵。

**序列化**（L358-371）：`progress`、`warmup` 写入存档喵。

### 1.3 DrawWarmupRegion：按 warmup 染色/亮度

文件：`D:\Blockdustry\Mindustry\core\src\mindustry\world\draw\DrawWarmupRegion.java`（全文）喵：
```java
public class DrawWarmupRegion extends DrawBlock{
    public float sinMag = 0.6f, sinScl = 8f;
    public Color color = Color.valueOf("ff9b59");   // 暖橙
    public TextureRegion region;                    // = block.name + "-top"

    @Override
    public void draw(Building build){
        Draw.color(color);
        Draw.alpha(build.warmup() * (1f - sinMag) + Mathf.absin(Time.time, sinScl, sinMag) * build.warmup());
        Draw.rect(region, build.x, build.y);        // 顶面 -top 纹理
        Draw.reset();
    }

    @Override
    public void load(Block block){
        region = Core.atlas.find(block.name + "-top");  // 额外顶面纹理
    }
}
```
- 机制：基础层（DrawDefault 的 fullIcon）不变，上面叠加一层 **`-top` 顶面纹理**，用固定色 `#ff9b59` 染色，alpha 按 warmup 线性 + 正弦闪烁（`0.4*warmup .. 1.6*warmup` 区间呼吸），营造「预热发热」效果喵。
- MC 对应：顶面叠加一张自发光/半透明 quad，颜色固定橙，alpha 用同一公式喵。

### 1.6 粒子效果数据模型（Fx / Effect）

文件：`D:\Blockdustry\Mindustry\core\src\mindustry\content\Fx.java`、`D:\Blockdustry\Mindustry\core\src\mindustry\entities\Effect.java` 喵。

**Effect 类**（Effect.java）喵：
- 字段：`lifetime`（生命周期，tick）、`layer`（渲染层）、`clip`（裁剪半径）、`renderer`（渲染 lambda，入参 `EffectContainer e`）喵。
- 触发：`effect.at(x, y, rotation, color, data)` → `create(...)` → `shouldCreate()` 判 `!headless && renderer.enableEffects` → 先判相机裁剪（`camera.bounds.overlaps`）→ `add(...)` 生成 `EffectState` 实体喵。
- **数据**（EffectContainer，L291-329）：`x, y, time, lifetime, rotation, color, id, data`；`id` 由 Effect 全局序号给出喵。
- **时间插值**（Scaled 接口，EffectContainer 实现 `fin()`）喵：
  - `fin() = time / lifetime`（0→1 线性）
  - `fout() = 1 - fin`（1→0）
  - `finpow()/foutpow()`：幂次加速版本
  - `fset()`：正弦先增后减（起落）
  - `fslope()`：先快速升到 1 后保持
- **确定性随机**：`rand.setSeed(e.id)` + `Angles.randLenVectors(seed, count, len, cons)` —— 以 effect id 为种子，同一次特效每帧生成相同形状的粒子、整体随时间扩散，观感稳定喵。

**pulverizeMedium（石墨压机 craft 特效，Fx.java L2520-2525）**喵：
```java
pulverizeMedium = new Effect(30, e -> {
    randLenVectors(e.id, 5, 3f + e.fin() * 8f, (x, y) -> {
        color(Pal.stoneGray);                    // #8f8f8f 中灰
        Fill.square(e.x + x, e.y + y, e.fout() + 0.5f, 45);   // 旋转 45° 方块，尺寸从 ~1.5 缩到 0.5
    });
});
```
- 属性表：寿命 30 tick；5 个方块粒子；颜色 `stoneGray #8f8f8f`；散布半径 `3 + fin*8`（向外扩散）；尺寸 `fout + 0.5`（随时间缩小）；方块绕自身旋转 45°；不透明（默认 alpha=1）喵。

**generatespark（燃烧发电机周期特效，Fx.java L2456-2461）**喵：
```java
generatespark = new Effect(18, e -> {
    randLenVectors(e.id, 5, e.fin() * 8f, (x, y) -> {
        color(Pal.orangeSpark, Color.gray, e.fin());   // #d2b29c 橙灰 → 灰 渐变
        Fill.circle(e.x + x, e.y + y, e.fout() * 4f / 2f);  // 半径 2→0
    });
});
```
- 属性表：寿命 18 tick；5 个圆形点；颜色由 `orangeSpark #d2b29c` 渐变到 `gray #808080`（按 fin 插值）；散布半径 `fin*8`；半径 `fout*2`（快速缩没）喵。

> 注意：Mindustry 粒子是**客户端 CPU 即时绘制的几何体**（Fill.circle/square），不是贴图精灵；MC 原生粒子系统无法 1:1 复现，需映射（见 §3.3）喵。

## 3. MC 迁移方案

### 3.1 数据与同步（服务端为主）

给两个 BE 各加 `float warmup`（0..1），服务端在 `tickAnchor()` 维护，随 NBT 同步给客户端，BER 只读不写喵。

**GraphitePressBlockEntity** 修改喵：
- 新字段 `private float warmup;`（不持久化也可，重载后从头预热；建议持久化保持一致性）喵。
- `tickAnchor()` 里：可生产时 `warmup = Math.min(1f, warmup + WARMUP_SPEED)`，否则 `warmup = Math.max(0f, warmup - WARMUP_SPEED)`，`WARMUP_SPEED` 参照 Mindustry `0.019` 喵。
- 每 tick `sendBlockUpdated`（参照 Conveyor `syncBelt()`，L110-115）或仅 warmup 变化超阈值时同步，客户端 BER 读同步值 喵。
- craft 到 1 时（L72-79 内）触发粒子（见 3.3）喵。

**CombustionGeneratorBlockEntity** 修改喵：
- 新字段 `private float warmup;`；`tickAnchor()` 里 `warmup = Math.min(1f, warmup + (fuelTime > 0 ? WARMUP_SPEED : -WARMUP_SPEED))`，`WARMUP_SPEED` 参照 `0.05` 喵。
- 每 tick 按 `effectChance ≈ 0.01` 概率触发粒子 喵。
- `powerProduction()` 已由 fuelTime 决定，warmup 仅作视觉 喵。

同步实现：在 `saveAdditional`/`loadAdditional` 加 `bd_warmup`（float），并沿用现有 `getUpdateTag()`（= `saveWithoutMetadata`）+ `level.sendBlockUpdated(worldPosition, state, state, 3)`，客户端 BE 在 `loadAdditional` 收到 喵。

### 3.2 BER 渲染动画

新建两个 BER，都遵循「`if(!be.isAnchor()) return;`」只在锚点格渲染 喵。

**(A) CombustionGeneratorBlockEntityRenderer —— 复刻 DrawWarmupRegion 预热染色** 喵：
- 基座由原版方块模型渲染，BER 在顶面叠加一张 `combustion_generator_top` 纹理（新建 PNG，仿 Mindustry `-top`）喵。
- quad 用 `RenderType.entityTranslucent`（要光混合）或 `RenderType.eyes`（自发光、无视光照更像 Mindustry）喵。
- 颜色：固定橙 `#ff9b59`，alpha = `warmup * 0.4f + Mathf.absin(partialTick-driven) * warmup * 0.6f`，即 `warmup*(1-sinMag) + absin(worldTime, 8, 0.6)*warmup`（sinMag=0.6, sinScl=8，Mindustry 同款呼吸闪烁）喵。
- 顶点写法完全参照 `DrillBlockEntityRenderer`：`pose.pushPose()`、`translate(0.5, 1.001, 0.5)`、`buffer.getBuffer(...)`、`vc.addVertex(...).setUv(...).setColor(r,g,b,a).setLight(light)`，方块是 1×1 喵。
- 可选火焰发光：`warmup > 0` 时叠加一个随 `absin` 缩放的橙红半透明 quad（替代 DrawFlame 的同心圆）喵。

**(B) GraphitePressBlockEntityRenderer —— 预热染色 + 旋转压盘** 喵：
- 顶面叠加 `graphite_press_top` 纹理，alpha 随 warmup（石墨压机原版无 warmup 染色，但可加暖色/高亮提升动感，作为增强项）喵。
- 旋转压盘（增强项，参考 DrawBlockParts）：一张圆形 `graphite_press_rotator` 纹理，绕 Y 轴旋转 `(level.getGameTime() + partialTick) * 0.1f * warmup`，只在 warmup>0 时转；2×2 建筑中心 `translate(1.0, 1.02, 1.0)` 喵。

### 3.3 粒子触发（MC 映射）

触发点在服务端（现有 tick 只跑服务端），用广播 API 喵：
```java

                          int particleCount, double xOffset, double yOffset, double zOffset, double speed)
```
（签名已核对：`D:\Blockdustry\仓库\build\neoForm\...\transformed\net\minecraft\server\level\ServerLevel.java` L1258-1274；`DustParticleOptions(Vector3f color, float scale)` 见 `net/minecraft/core/particles/DustParticleOptions.java` L28）喵。

**映射表**（Mindustry → MC）喵：

| Mindustry 特效 | MC 替代 | 说明 |
|---|---|---|
| pulverizeMedium（30tick，5 方块，灰 #8f8f8f） | `ParticleTypes.DUST` + `DustParticleOptions(new Vector3f(0.56f,0.56f,0.56f), 1f)`，count=5 | 灰色尘点向外散，最贴近；或用 `ParticleTypes.SMOKE`/`ASH` 免费替代 |

- 石墨压机 craft 完成（`craftProgress >= 1` 分支，`GraphitePressBlockEntity.tickAnchor()` L72-79）：在锚点格中心偏上 `(ax+size/2, ay+0.5, az+size/2)` 调一次 `sendParticles(DUST, x, y, z, 5, dx范围, dy范围, dz范围, 速度)`，dx/dy/dz 取 0.15~0.3 模拟向外飞 喵。

### 3.5 风险与注意

- **同步**：`sendBlockUpdated` 每 tick 全量同步 NBT 在 conveyer 上已跑通；机器数量多时可只同步 warmup 变化（比较上次值）喵。
- **锚点格**：粒子坐标与渲染都基于锚点格 `worldPosition`，多格建筑要加 `size/2` 偏移（2×2 → +1,+1）；非锚点格 BER 直接 return 喵。
- **服务端不能 `level.addParticle`**：客户端 API；服务端一律 `ServerLevel.sendParticles`，且 `ServerLevel` 才能强转（`level instanceof ServerLevel`）喵。
- **z-fighting**：顶面 overlay 抬 `y = 1.001~1.02`，参照 drill rotator 喵。
- **光照**：`entityTranslucent` 传 `light` 会受环境光影响（更自然）；`RenderType.eyes` 自发光更像 Mindustry 顶面发热色，但会忽略光照——按观感取舍喵。
- **warmup 客户端滞后**：直接读同步值会有约 1 tick 延迟，可接受；若需平滑可在 BER 里存上次 warmup 并对 `partialTick` 插值 喵。
