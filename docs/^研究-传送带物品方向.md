# 研究：传送带上物品贴图方向（竖着 → 平放）喵

## 结论摘要喵

- 根因：`ConveyorBlockEntityRenderer` 只对物品做了绕 Y 轴旋转（让物品正面朝传送方向），没有绕 X 轴把物品放倒，所以 `item/generated` 的扁平贴图在水平传送带上保持「竖立贴图卡片」状态喵
- 修复：在 `pose.mulPose(Axis.YP.rotationDegrees(-facing.toYRot()))` 之后加一行 `pose.mulPose(Axis.XP.rotationDegrees(-90.0F))`，把贴图绕 X 轴 -90° 放倒，法线朝上即平躺喵
- 结论：**换 GROUND 解决不了问题**（原版掉落物其实也是竖立贴图绕 Y 转，只是缩小了），必须手动绕 X 旋转喵

## 1. 当前代码与问题定位喵

文件：`D:\Blockdustry\仓库\src\main\java\com\blockdustry\client\ConveyorBlockEntityRenderer.java`

```java
// 第 33-38 行：当前渲染喵
pose.pushPose();
pose.translate(0.5 + facing.getStepX() * along, 0.25, 0.5 + facing.getStepZ() * along);
pose.mulPose(Axis.YP.rotationDegrees(-facing.toYRot()));   // 只绕 Y，物品竖立喵
Minecraft.getInstance().getItemRenderer().renderStatic(
        items[i].getDefaultInstance(), ItemDisplayContext.FIXED,
        light, overlay, pose, buffer, be.getLevel(), 0);
pose.popPose();
```

问题拆解喵：
- 传送带上的物品（如 `blockdustry:graphite`，父模型 `minecraft:item/generated`）本质是 **XY 平面、法线朝 +Z 的扁平贴图 quad** 喵
- 当前只做 Y 轴旋转（对齐传送方向），quad 仍垂直于地面，看起来就是「竖着的一面广告牌/卡片」喵
- 传送带表面是水平的，物品应该把 +Z 法线转到 +Y（朝上），即绕 X 轴旋转 -90° 喵

## 2. 渲染管线原理（1.21.1 源码）喵

调用链喵：

```
ItemRenderer.renderStatic(stack, FIXED, light, overlay, pose, buffer, level, 0)
  └─ ItemRenderer.render(...)
       └─ ClientHooks.handleCameraTransforms(pose, model, FIXED, false)
            └─ model.applyTransform(FIXED, pose, false)      // IBakedModelExtension 默认实现喵
                 └─ getTransforms().getTransform(FIXED).apply(false, pose)  // 应用模型 JSON 的 display.fixed 喵
       └─ poseStack.translate(-0.5, -0.5, -0.5)              // 把模型居中到 [-0.5,0.5] 喵
```

关键点喵：
- `renderStatic` 用的 `ItemDisplayContext` 只决定**取模型 JSON 里 `display` 的哪一档变换**（`ItemTransforms.getTransform`），它不会自动让物品平躺喵
- 物品最终朝向 = 模型 `display` 变换（FIXED 档）+ **渲染者自己在 PoseStack 上加的旋转**喵
- `ItemTransform.apply` 源码：`poseStack.mulPose(quaternionXYZ(rotation))` 按 JSON 的 rotation 旋转，再缩放、平移喵

## 3. 原版 ItemEntity 到底怎么「平放」的喵

文件：`net/minecraft/client/renderer/entity/ItemEntityRenderer.java`（1.21.1 反编译源码）喵

```java
// ItemEntityRenderer.render 核心喵
float f1 = Mth.sin(((float)entity.getAge() + partialTicks) / 10.0F + entity.bobOffs) * 0.1F + 0.1F;
poseStack.translate(0.0F, f1 + 0.25F * f2, 0.0F);           // 上下浮动喵
poseStack.mulPose(Axis.YP.rotation(f3));                     // 只绕 Y 轴旋转（spin）喵
renderMultipleFromCount(...);                                // 内部 render(..., ItemDisplayContext.GROUND, ...) 喵
```

发现：**原版掉落物根本没有绕 X 轴旋转，它是「竖立贴图绕 Y 轴旋转」的**，看起来贴近地面只是靠 `generated` 父模型里 `ground` 档的 scale 0.5 缩小 + 低高度喵
所以「仿照原版 ItemEntity 就能平放」是误区，原版掉落物本身也是竖的喵

## 4. 为什么 GROUND 不够、FIXED 才是对的喵

`assets/minecraft/models/item/generated.json`（扁平物品父模型，1.21.1 客户端 jar 内实际内容）喵：

```json
"ground": { "rotation": [0, 0, 0], "translation": [0, 2, 0], "scale": [0.5, 0.5, 0.5] },
"fixed":  { "rotation": [0, 180, 0], "scale": [1, 1, 1] }
```

`assets/minecraft/models/item/handheld.json`（工具父模型，如镐/剑）喵：

```json
// 未定义 ground 与 fixed，两档都回退到 ItemTransform.NO_TRANSFORM（恒等）喵
```

对照喵：

| Context | `generated` 扁平物品 | `handheld` 工具类 | 能否平放喵 |
|---|---|---|---|
| GROUND | rotation [0,0,0]、scale 0.5 | 恒等（scale 1.0） | 不能（不旋转 X，且两类物品尺寸不一致 0.5 vs 1.0）喵 |
| FIXED | rotation [0,180,0]、scale 1.0 | 恒等（scale 1.0） | 不能（仍不旋转 X，但尺寸统一为 1.0）喵 |

结论喵：
- **GROUND 不能直接用**：它不旋转 X（还是竖着），而且 `generated`/`handheld` 缩放不一致，会出现有的物品大有的小喵
- **FIXED 是正确底座**：两类物品 scale 都是 1.0，尺寸统一；它的 [0,180,0] 只是把贴图翻面，不影响平放喵
- 无论哪种 context，**都必须靠渲染者加 `mulPose(Axis.XP.rotationDegrees(-90))` 才能真正平放**喵

## 5. 修复方法（推荐：FIXED + 绕 X -90°）喵

原理喵：`item/generated` 贴图 quad 法线朝 +Z；绕 X 轴 -90° 后 +Z → +Y（朝上），quad 落入水平 XZ 平面，即平躺喵（绕 +90° 会变朝下，错误）喵

最小改动（在 `ConveyorBlockEntityRenderer.java` 第 35 行后加一行）喵：

```java
pose.mulPose(Axis.YP.rotationDegrees(-facing.toYRot()));
pose.mulPose(Axis.XP.rotationDegrees(-90.0F));   // 关键：物品平躺，法线朝上喵
```

完整修复后的 render() 喵：

```java
@Override
public void render(ConveyorBlockEntity be, float partialTick, PoseStack pose,
                   MultiBufferSource buffer, int light, int overlay) {
    if (!be.isAnchor()) return;
    Direction facing = be.getFacing();
    Item[] items = be.beltItems();
    float[] prog = be.beltProgress();
    for (int i = 0; i < ConveyorBlockEntity.SLOTS; i++) {
        if (items[i] == null) continue;
        float p = Math.min(1f, prog[i]);
        double along = p - 0.5;
        pose.pushPose();
        pose.translate(0.5 + facing.getStepX() * along, 0.25, 0.5 + facing.getStepZ() * along);
        pose.mulPose(Axis.YP.rotationDegrees(-facing.toYRot()));  // 物品正面朝传送方向喵
        pose.mulPose(Axis.XP.rotationDegrees(-90.0F));            // 关键：物品平躺喵
        Minecraft.getInstance().getItemRenderer().renderStatic(
                items[i].getDefaultInstance(), ItemDisplayContext.FIXED,
                light, overlay, pose, buffer, be.getLevel(), 0);
        pose.popPose();
    }
}
```

## 6. 可选优化喵

- **缩小物品**：Mindustry 传送带物品通常比 1 格小，可加 `pose.scale(0.5f, 0.5f, 0.5f)`（放在平躺旋转之后）喵；不要为此换 GROUND，否则 `handheld` 工具类物品会变回 1.0 不一致喵
- **贴图朝向微调**：想让贴图「顶部」沿传送方向，可在平放后追加 `pose.mulPose(Axis.ZP.rotationDegrees(180.0F))` 之类的微调；一般资源（石墨、铜锭等）近似对称，非必需喵
- 高度 `0.25` 可随物品缩小适当下调（如 `0.1875`）让物品贴近带面喵
