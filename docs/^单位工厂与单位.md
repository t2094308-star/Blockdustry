# Mindustry 单位工厂与单位系统解析（移植参考）

> 目标：为移植到 MC 模组提供 Mindustry「单位工厂 + 单位系统」的详细参考喵。
> 源码根：`D:\Blockdustry\Mindustry\core\src\mindustry\` 喵。

## 1. 概览

- 单位工厂 = 从地面/空中/海军工厂持续生产单位的生产建筑喵。地面版叫 `groundFactory`，类为 `UnitFactory` 喵。
- 类继承链：`UnitFactory extends UnitBlock`，`UnitBlock extends PayloadBlock` 喵。
- 生产出的单位会被包成 `UnitPayload` 放进工厂的 payload 槽，再从方块出口 `dump` 出去（产出到门口）喵。
- 单位本体 = 静态配置 `UnitType`（速度/血量/武器等参数）+ 运行时实体组件（`UnitComp` 等，构建期生成 `Unit`/`UnitEntity`）喵。
- `mindustry.gen.*` 目录是构建期由注解处理器生成的，源码树里不存在，真正的源在 `core/src/mindustry/entities/comp/` 喵。

## 2. groundFactory 定义（Blocks.java，行 6269-6279）

```java
groundFactory = new UnitFactory("ground-factory"){{
    requirements(Category.units, with(Items.copper, 50, Items.lead, 120, Items.silicon, 80));
    plans = Seq.with(
        new UnitPlan(UnitTypes.dagger, 60f * 15, with(Items.silicon, 10, Items.lead, 10)),
        new UnitPlan(UnitTypes.crawler, 60f * 10, with(Items.silicon, 8, Items.coal, 10)),
        new UnitPlan(UnitTypes.nova, 60f * 40, with(Items.silicon, 30, Items.lead, 20, Items.titanium, 20))
    );
    size = 3;
    consumePower(1.2f);
    researchCostMultiplier = 0.5f;
}};
```

参数明细：

- `requirements(...)`：建造工厂本体所需材料（铜50、铅120、硅80），属于 `Category.units` 喵。
- `plans`：`Seq<UnitPlan>`，本工厂可生产的单位列表喵。每个 `UnitPlan` = 单位类型 + 生产时间（tick 数）+ 材料清单喵。
  - `dagger`：时间 `60f*15` = 900 tick（15 秒），消耗 硅10 + 铅10 喵。
  - `crawler`：`60f*10` = 600 tick（10 秒），消耗 硅8 + 煤10 喵。
  - `nova`：`60f*40` = 2400 tick（40 秒），消耗 硅30 + 铅20 + 钛20 喵。
- `size = 3`：3×3 方块占地喵。
- `consumePower(1.2f)`：静态功耗 1.2 功率单位喵。
- `researchCostMultiplier = 0.5f`：科技树研究成本倍率喵。
- 注意：`consumeItems` **不**在这里显式写，而是 `UnitFactory` 构造函数里用 `ConsumeItemDynamic` 按当前配方动态消耗喵。
- 同类还有 `airFactory`（行 6281，size=3、功耗 1.2f，产 flare/mono）、`navalFactory`（行 6292，`floating = true`）喵。

## 3. UnitFactory 机制（UnitFactory.java）

### 3.1 关键字段与构造

```java
public class UnitFactory extends UnitBlock{
    public int[] capacities = {};
    public Seq<UnitPlan> plans = new Seq<>(4);
    public Sound createSound = Sounds.unitCreate;
    public float createSoundVolume = 1f;

    public UnitFactory(String name){
        super(name);
        update = true;
        hasPower = true;
        hasItems = true;
        solid = true;
        configurable = true;
        clearOnDoubleTap = true;
        outputsPayload = true;
        rotate = true;
        commandable = true;
        // 动态消耗：当前配方需要什么就扣什么
        consume(new ConsumeItemDynamic((UnitFactoryBuild e) ->
            e.currentPlan != -1 ? plans.get(Math.min(e.currentPlan, plans.size - 1)).requirements : ItemStack.empty));
    }
}
```

`UnitPlan` 内部类：`unit`（UnitType）、`requirements`（ItemStack[]）、`time`（float，tick 数）喵。

### 3.2 initCapacities —— 工厂自动扩容

```java
public void initCapacities(){
    capacities = new int[Vars.content.items().size];
    itemCapacity = 10; // 外部设置无效，由工厂自己算
    for(UnitPlan plan : plans){
        for(ItemStack stack : plan.requirements){
            capacities[stack.item.id] = Math.max(capacities[stack.item.id], stack.amount * 2);
            itemCapacity = Math.max(itemCapacity, stack.amount * 2);
        }
    }
    consumeBuilder.each(c -> c.multiplier = b -> state.rules.unitCost(b.team));
}
```

- 每种物品容量 = 所有配方里该物品最大需求量的 2 倍，`itemCapacity` 取最大喵。
- 所有消耗的倍率乘上 `rules.unitCost(team)`（队伍/规则层面的单位成本倍率）喵。

### 3.3 配置（config）机制

```java
config(Integer.class, (UnitFactoryBuild build, Integer i) -> {
    if(!configurable) return;
    if(build.currentPlan == i) return;
    build.currentPlan = i < 0 || i >= plans.size ? -1 : i; // 越界=停止生产
    build.progress = 0;
    ...
});
config(UnitType.class, ...);          // 直接选单位类型
config(UnitCommand.class, ...);       // 设置产出单位默认命令
```

- 玩家点击选择要生产的单位，存到 `currentPlan` 索引，切配方时 `progress` 归零喵。

### 3.4 UnitFactoryBuild.updateTile() —— 核心生产逻辑

```java
@Override
public void updateTile(){
    if(!configurable) currentPlan = 0;
    if(currentPlan < 0 || currentPlan >= plans.size) currentPlan = -1;

    if(efficiency > 0 && currentPlan != -1){
        time += edelta() * speedScl * Vars.state.rules.unitBuildSpeed(team);
        progress += edelta() * Vars.state.rules.unitBuildSpeed(team);
        speedScl = Mathf.lerpDelta(speedScl, 1f, 0.05f);
    }else{
        speedScl = Mathf.lerpDelta(speedScl, 0f, 0.05f);
    }

    moveOutPayload(); // 把已有 payload 推向输出

    if(currentPlan != -1 && payload == null){
        UnitPlan plan = plans.get(currentPlan);

        if(plan.unit.isBanned()){ currentPlan = -1; return; }

        if(progress >= plan.time){
            progress %= 1f;

            Unit unit = plan.unit.create(team); // 创建单位实体
            if(unit.isCommandable()){
                if(commandPos != null) unit.command().commandPosition(commandPos);
                unit.command().command(command == null && unit.type.defaultCommand != null ? unit.type.defaultCommand : command);
            }

            createSound.at(this, 1f + Mathf.range(0.06f), createSoundVolume);
            payload = new UnitPayload(unit); // 单位装进负载槽
            payVector.setZero();
            consume(); // 一次性扣掉本配方所有材料
            Events.fire(new UnitCreateEvent(payload.unit, this));
        }

        progress = Mathf.clamp(progress, 0, plan.time);
    }else{
        progress = 0f; // 没配方或有负载时进度归零
    }
}
```

机制说明：

- `progress` 每帧按 `edelta() * unitBuildSpeed(team)` 累加，`unitBuildSpeed` 是队伍级生产速度倍率喵。
- `progress >= plan.time` 时判定完成，`progress %= 1f` 是为了进度条连续动画，生产则整批结算喵。
- 完成瞬间 `consume()` 一次性扣除该配方全部材料（动态消耗已按配方缓存）喵。
- 产出单位以 `UnitPayload` 形式存在 `payload` 槽里，`moveOutPayload()` 会把它向方块前方推，直到 `dumpPayload()` 输出喵。
- 没有产出单位前 `payload == null`，此时才允许消耗材料（见下）喵。

### 3.5 消耗/接收约束

```java
@Override
public boolean shouldConsume(){
    if(currentPlan == -1) return false;
    return enabled && payload == null && team.activateUnitFactories();
}

@Override
public int getMaximumAccepted(Item item){
    return Mathf.round(capacities[item.id] * state.rules.unitCost(team));
}

@Override
public boolean acceptItem(Building source, Item item){
    return currentPlan != -1 && items.get(item) < getMaximumAccepted(item) &&
        Structs.contains(plans.get(currentPlan).requirements, stack -> stack.item == item);
}
```

- `shouldConsume()`：只有选中配方、方块启用、**负载槽为空**、队伍开启单位工厂时才消耗材料喵。
- `acceptItem()`：只接收当前配方用得到的物品，且不超过该物品容量喵。
- `fraction()` = `progress / plans.get(currentPlan).time`，供进度条显示喵。

### 3.6 单位输出（UnitBlock.java）

```java
public class UnitBuild extends PayloadBlockBuild<UnitPayload>{
    public float progress, time, speedScl;

    public void spawned(){
        progress = 0f;
        payload = null;
    }

    @Override
    public void dumpPayload(){
        if(payload.dump()){          // 负载离开方块范围
            Call.unitBlockSpawn(tile); // 远程调用，通知本方块单位已出生
        }
    }
}
```

- 单位不是直接放置在世界里，而是作为负载被运送到别的负载块，或用传送带/方块推出，落地瞬间才真正成为世界里的单位喵。
- `@Remote(called = Loc.server)` 保证 spawn 只在服务端逻辑执行，客户端收到同步喵。
- 序列化（UnitFactoryBuild.write/read，version=3）：写入 `progress`、`currentPlan`、`commandPos`、`command` 喵。

## 4. UnitType —— 单位静态类型（type/UnitType.java）

### 4.1 核心数值字段

```java
public float speed = 1.1f,          // 移动速度（世界单位/帧；1 格=tilesize=8 世界单位）
             boostMultiplier = 1f,  // 加速(boost)速度倍率
             floorMultiplier = 1f,  // 地形影响系数
             rotateSpeed = 5f,      // 转身角速度（度/帧）
             drag = 0.3f,           // 移动阻力(比例)
             accel = 0.5f,          // 加速度(速度比例)
             hitSize = 6f;          // 碰撞箱半边(方块尺寸=hitSize/8)
public float health = 200f;         // 基础血量
public float armor = 0f;            // 护甲(固定减伤)
```

- 关键布尔开关：`flying`（飞行，elevation=1）、`canBoost`、`targetAir/targetGround`、`useUnitCap`（占单位上限）、`playerControllable/logicControllable`、`allowedInPayloads`、`omniMovement`（全方向移动）喵。
- 携带容量：`itemCapacity = -1` 时在 `init()` 自动算为 `max(round(hitSize*4, 10), 10)` 喵。
- 采矿/建造：`mineTier`、`mineSpeed`、`buildSpeed`（<0 禁用）喵。
- 命令/姿态：`commands`（Seq<UnitCommand>）、`stances`、`defaultCommand`，空时 `init()` 按能力自动补齐（移动、进负载、开采、修理、建造等）喵。

### 4.2 创建与生成（create/spawn）

```java
public Unit create(Team team){
    Unit unit = constructor.get();   // 由 EntityMapping 提供的实体构造器
    unit.team = team;
    unit.setType(this);              // 同步 maxHealth/drag/armor/hitSize + 武器挂架
    if(unit.controller() instanceof CommandAI command && defaultCommand != null){
        command.command = defaultCommand;
    }
    for(var ability : unit.abilities) ability.created(unit);
    unit.elevation = flying ? 1f : 0;
    unit.heal();                     // 满血出生
    return unit;
}

public Unit spawn(Team team, float x, float y, float rotation, @Nullable Cons<Unit> cons){
    Unit out = create(team);
    out.rotation = rotation;
    out.set(x + offsetX, y + offsetY);
    out.add();                        // 加入世界
    if(cons != null) cons.get(out);
    // 多段体(segment)单位还会生成额外 segment
    return out;
}
```

- `constructor` 默认映射自 `EntityMapping.map(name)`，后备为 `UnitEntity::create` 喵。
- `create()` 只造实体不加入世界，`spawn()` 会调用 `add()` 加入并触发队伍计数与单位上限检查喵。

### 4.3 dagger 示例（UnitTypes.java 行 99-118）

```java
dagger = new UnitType("dagger"){{
    researchCostMultiplier = 0.5f;
    speed = 0.5f;
    hitSize = 8f;   // 碰撞箱半边 8 -> 占地 1x1 格
    health = 150;
    stepSoundVolume = 0.4f;

    weapons.add(new Weapon("large-weapon"){{
        reload = 13f;    // 装填帧数(13 tick)
        x = 4f;
        y = 2f;
        top = false;
        ejectEffect = Fx.casing1;
        bullet = new BasicBulletType(2.5f, 9){{   // 速度 2.5、伤害 9
            width = 7f;
            height = 9f;
            lifetime = 60f;  // 子弹存活 60 tick
        }};
    }});
}};
```

- 单位血量 = `health`，减伤 = `armor`；武器用 `Weapon` 声明，子弹用 `BulletType` 声明喵。
- `Weapon` 关键参数：`reload`（装填帧数）、`bullet`（弹种）、`mirror`（init 时自动生成对称副本）、`alternate`（交替开火）、`continuous`、`inaccuracy`（散布）、`x/y`（武器在单位上的偏移）喵。
- 武器会在 `UnitType.init()` 里自动镜像、自动算 `maxRange`/`range`、初始化 `WeaponMount` 数组喵。

## 5. 单位实体组件系统（entities/comp/）

Mindustry 用注解处理器从 `*Comp.java` 生成 `mindustry.gen.*` 实体类（`Unit`、`UnitEntity`、`Building` 等）喵。单位实体 = `Unit` 接口，`UnitEntity` 是其默认实现喵。

### 5.1 UnitComp —— 单位核心组件

```java
@Component(base = true)
abstract class UnitComp implements Healthc, Physicsc, Hitboxc, Statusc, Teamc, Itemsc, Rotc, Unitc, Weaponsc, Drawc, Syncc, Shieldc, Displayable, Ranged, Minerc, Builderc, Senseable, Settable{
    @Import boolean dead, disarmed;
    @Import float x, y, rotation, maxHealth, drag, armor, hitSize, health, shield, ...;
    @Import Team team;
    @Import Vec2 vel;
    @Import WeaponMount[] mounts;

    private UnitController controller;
    Ability[] abilities = {};
    UnitType type = UnitTypes.alpha;   // 单位类型引用
    boolean spawnedByCore;
    double flag;
    @SyncLocal float elevation;        // 0=地面, 1=飞行
}
```

关键行为：

- `isGrounded()` = `elevation < 0.001f`，`isFlying()` = `elevation >= 0.09f` 喵。
- `setType(UnitType)`：把 `type.health/drag/armor/hitSize` 拷到实体，并按 `type.weapons`/`type.abilities` 重建 `mounts`/`abilities` 喵。
- `speed()` = `type.speed * strafePenalty * boost * floorSpeedMultiplier`，地形速度用 `floor.speedMultiplier^type.floorMultiplier` 喵。
- 移动接口：`moveAt(vector, accel)`（改 vel）、`movePref`（全向用 moveAt，否则 rotateMove）、`approach`（加速逼近目标）喵。
- `update()`：处理边界弹回/死亡、溺水（`drownTime`）、环境不适(`supportsEnv`)自爆、abilities 更新、拖尾、AI 更新（仅服务端 `controller.updateUnit()`）喵。
- 死亡流程：`kill()` 远程同步 → `killed()` 置 `dead` 并播坠落音 → `destroy()` 爆炸/残骸/掉落 → `remove()` 喵。
- `add()/remove()`：更新 `team.data().updateCount(type, ±1)` 计数，超过单位上限时 `Call.unitCapDeath` 直接杀死喵。

### 5.2 WeaponsComp —— 武器组件

```java
@Component
abstract class WeaponsComp implements Teamc, Posc, Rotc, Velc, Statusc{
    @SyncLocal WeaponMount[] mounts = {};
    boolean isShooting;

    void setupWeapons(UnitType def){
        mounts = new WeaponMount[def.weapons.size];
        for(int i = 0; i < mounts.length; i++){
            mounts[i] = def.weapons.get(i).mountType.get(def.weapons.get(i));
        }
    }

    @Override
    public void update(){
        for(WeaponMount mount : mounts){
            mount.weapon.update(self(), mount); // 每个武器挂架自己管理装填/开火
        }
    }
}
```

- `aim(x, y)` 让所有可控挂架指向目标，`canShoot()` = `!disarmed` 喵。
- 每个 `WeaponMount` 记录 `reload/heat/warmup/recoil/target` 等运行态，由 `Weapon.update(unit, mount)` 驱动装填与射击喵。

### 5.3 HealthComp —— 生命组件

```java
@Component
abstract class HealthComp implements Entityc, Posc{
    float health;
    transient float maxHealth = 1f;
    transient boolean dead;

    float healthf(){ return health / maxHealth; }

    void damage(float amount){
        health -= amount;
        hitTime = 1f;
        if(health <= 0 && !dead) kill();
    }

    void heal(){ dead = false; health = maxHealth; }
}
```

- `maxHealth` 由 `UnitType.setType` 设为 `type.health`，`heal()` 全满血（工厂/核心出生时调用）喵。

### 5.4 单位上限（entities/Units.java）

```java
public static boolean canCreate(Team team, UnitType type){
    return !type.useUnitCap || (team.data().countType(type) < getCap(team) && !type.isBanned());
}

public static int getCap(Team team){
    if((team == state.rules.waveTeam && !state.rules.pvp) || ... || state.rules.disableUnitCap || team.ignoreUnitCap){
        return Integer.MAX_VALUE; // 波次队伍无上限
    }
    return Math.max(0, state.rules.unitCapVariable ? state.rules.unitCap + team.data().unitCap : state.rules.unitCap);
}
```

- 单位上限来自地图规则 `rules.unitCap`，队伍数据里可附加 `unitCap`（unitCapVariable 模式）喵。
- 工厂的"单位数" bar 就是 `countType(type) / getCap(team)`，无限时显示 ∞ 喵。

## 7. 移植到 MC 模组的要点

1. **生产队列**：工厂的 `plans`（单位类型 + 时间 tick + 材料）可直接映射为 MC 的配方表（如 JsonRecipe / 条件解锁）喵。
2. **动态消耗**：Mindustry 用"当前配方"动态扣材料而不是写死多组消耗，MC 可做一个 `currentRecipe` 字段 + 每 tick 检测材料充足则扣一次的容器逻辑喵。
3. **进度与产出**：`progress += delta / time`，满则把产物放到输出槽；Mindustry 的产物是"负载(UnitPayload)"从方块口推出，MC 可直接在方块前 spawn 实体喵。
4. **单位静态/动态分离**：`UnitType`（静态参数：血量/速度/武器）类比 MC 的 `EntityType` + 属性注册；实体实例只存运行时状态（`UnitComp` 的 health/vel/team/controller）喵。
5. **队伍归属与敌对**：`Team` 决定敌对关系与单位上限，MC 可用团队/分数板或阵营组件实现喵。
6. **单位上限**：`Units.getCap` 逻辑（规则上限 + 队伍附加），MC 可做全局/阵营数量上限检查喵。
7. **血量/护甲**：`health` + `armor`（固定减伤），MC 可用属性 `max_health` + 减伤机制实现喵。
8. **武器**：`Weapon`（reload/bullet/mirror）可映射为 MC 的主动攻击组件或抛射物，装填帧数注意换算 tick（20 tick/s）喵。
