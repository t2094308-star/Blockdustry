# 研究：单位工厂修复（Jade 显示 / 不生产排查 / 生产动画）

> 目标：修好地面单位工厂（ground_factory，3×3）的三件事——① Jade 显示内部硅/铅资源量；② 排查「填满 20 硅 + 20 铅后不生产 dagger」的根因并修复；③ 顶面预热动画（warmup 染色呼吸）+ 完成粒子喵。
> 工程：`D:\Blockdustry\仓库`（NeoForge 1.21.1），改完 `./gradlew compileJava` 通过喵。

## 一、任务一：Jade 显示单位工厂内部资源量（硅/铅）

### 现状

`jade/BuildingInfoServerDataProvider.java` 里只有两类特判：
- 石墨压机（`GraphitePressBlockEntity`）：写 `bd_coal` / `bd_graphite` 喵。
- 其它建筑走通用库存：读 `building.getStoredItem()` 等喵。

单位工厂的库存是**独立字段** `siliconCount` / `leadCount`（没用基类 `storedItem`），所以：
- `getStoredItem()` 恒为 null → 通用分支不输出任何内容喵。
- 玩家看工厂，Jade 面板只有一行「队伍: X」，看不到硅/铅，完全像"死方块"喵。

### 改动

`jade/BuildingInfoServerDataProvider.java`：
- 新增常量 `KEY_SILICON = "bd_silicon"`、`KEY_LEAD = "bd_lead"` 喵。
- `appendServerData` 里新增 `else if (building instanceof UnitFactoryBlockEntity uf)` 分支，写 `KEY_SILICON`/`KEY_LEAD` 喵。
- 顺手把石墨压机判断从 `be`（原格，可能是非锚点格显示 0）改成 `building`（统一读锚点格），修掉多格建筑从格显示 0 的隐患喵。

`jade/BuildingInfoComponentProvider.java`：
- 新增 `else if (data.contains(KEY_SILICON))` 分支，显示「硅: N | 铅: N」（参考石墨压机「煤: N | 石墨: N」样式）喵。

### 显示效果

```
队伍: SHARDED
硅: 20 | 铅: 20
[====================] 制作进度
```

（制作进度条见任务二，同一面板喵。）

## 二、任务二：硅铅填满后不生产的排查与根因

### 排查过程（逐项核对）

| 怀疑点 | 结论 |
| --- | --- |
| ① 方块是否创建 BE（EntityBlock.newBlockEntity） | ✅ `BlockdustryBuildingBlock implements EntityBlock` 且覆写 `newBlockEntity`，`UNIT_FACTORY` 注册时用 `BlockdustryBuildingBlock` 构造，BE 正常创建喵 |
| ② Dagger 实体/属性是否注册 | ✅ `BlockdustryEntities.DAGGER` 已注册；`Blockdustry.registerAttributes` 里 `EntityAttributeCreationEvent.put(DAGGER, ...)` 已挂喵 |
| ③ getFacing() 读取 | ✅ 工厂方块无 `HORIZONTAL_FACING` 属性，`getFacing()` 兜底返回 NORTH，不会抛异常喵 |
| ④ spawnUnit 是否异常被吞 | ✅ `BlockdustryBuildings.tickAll` 有 try-catch 记 `建筑 tick 异常` 日志；查 `tools/.game_log.txt` 无此类错误，spawnUnit 未抛异常喵 |
| ⑤ 物品是否真的进锚点格 | ✅ `acceptItem`/`handleItem` 非锚点格都转发 `level.getBlockEntity(getAnchor())` 给锚点，锚点 `siliconCount++`/`leadCount++`；`setBlockAndUpdate` + `setAnchor` 链路确认每格 anchor 都设置喵 |

### 根因

**生产逻辑本身没坏**，真正让玩家觉得「不生产、进度不动」的是三层反馈缺失 + 一个出生点缺陷：

1. **Jade 没有单位工厂的进度条**（根因核心）喵。
   `jade/ProgressServerProvider.getGroups()` 里制作进度条**只特判了 `GraphitePressBlockEntity`**，单位工厂没进任何分支 → 面板上根本没有「制作进度」条。「进度不动」字面成立：压根没有进度条可看喵。

2. **Jade 不显示硅/铅内容**（任务一已修）喵。
   通用库存分支读 `getStoredItem()`，工厂恒 null → 只有队伍行，看不到库存，「像没在工作」喵。

3. **生产周期长达 45 秒**（900 tick = 15 秒的笔误已按原作 900tick 实现）喵。
   即使材料满，第一架也要 45 秒才出；没有进度反馈时，短测必然觉得"没反应"喵。

4. **出生点固定朝北且可能在实心方块里**喵。
   `spawnUnit` 固定 `worldPosition.relative(NORTH)` 一格、且 Y 与方块底面齐平。若玩家把物品源/墙体摆在工厂北侧（常见喂料摆法），dagger 会**出生在实心方块内**，被卡住/顶出，表现为「无单位产出」喵。

### 修复

`building/UnitFactoryBlockEntity.java`：
- `spawnUnit()` 改为 `findSpawnPos()` 找空闲出生点：**门口 → 门口上方 → 门口四邻 → 工厂顶面**，保证 dagger 一定出现在空气格里不卡墙喵。
- 完成生产时在门口 `ServerLevel.sendParticles(ParticleTypes.CLOUD, ...)` 播白色烟团，肉眼可见产出反馈喵。

`jade/ProgressServerProvider.java`：
- 新增单位工厂制作进度条分支（`info instanceof UnitFactoryBlockEntity`），并统一把多格建筑重定向到锚点格取 `getCraftProgress()`（顺带修了石墨压机从格显示 0 的问题）喵。

`jade/BuildingInfoServerDataProvider.java` + `BuildingInfoComponentProvider.java`：见任务一，补上硅/铅显示喵。

### 关键判断依据

- `BlockdustryBuildings` 用 `onLoad()` 注册、模组新 tick 驱动（`BlockdustryTicks` + `ServerTickEvent.Post`），石墨压机同链路已验证可用，工厂 BE 同样被驱动喵。
- 生产判定 `siliconCount >= 10 && leadCount >= 10` 满足时 `craftProgress += 1/900`，满 1 扣料 `spawnUnit`；材料满时进度必然推进喵。

## 三、任务三：单位工厂生产动画

### 设计

Mindustry `groundFactory` 顶面有预热染色区（`DrawWarmupRegion`）+ 完成粒子喵。照搬 `CombustionGeneratorBlockEntity` 的 warmup 模式 + `CombustionGeneratorBlockEntityRenderer` 的染色画法喵。

### 改动

`building/UnitFactoryBlockEntity.java`：
- 新增 `warmup`（0..1）字段 + `getWarmup()`，`tickAnchor` 里生产时 `+0.02` 爬升、否则 `-0.02` 衰减喵。
- `|warmup - lastSyncedWarmup| > 0.02f` 时 `level.sendBlockUpdated(...)` 同步客户端（与燃烧发电机同款阈值）喵。
- `saveAdditional`/`loadAdditional` 新增 `bd_warmup` 持久化喵。

新增 `client/UnitFactoryBlockEntityRenderer.java`（参考 `CombustionGeneratorBlockEntityRenderer`）：
- 顶面 y+1.001 叠画 `textures/block/ground_factory.png`（96×96 九宫格），按本格 `CORNER` 裁对应 1/3 象限 UV，与方块模型顶面裁剪精确对齐喵。
- 固定暖橙染色 `#ff9b59`（255,155,89），alpha = `warmup*0.4 + |sin(gameTime*2π/8)|*0.6*warmup` 呼吸闪烁喵。
- warmup 只存在锚点格（非锚点格不 tick 也不同步），渲染时从锚点 BE 读 warmup，保证 3×3 整栋同步亮喵。
- `setOverlay(NO_OVERLAY)` + `setLight(0xF000F0)` 全亮，防越界采样染黑/环境光过暗（沿用炮管黑坑的解法）喵。

`BlockdustryClient.java`：
- `registerRenderers` 里新增 `event.registerBlockEntityRenderer(BlockdustryBlocks.UNIT_FACTORY_ENTITY.get(), UnitFactoryBlockEntityRenderer::new)` 喵。

### 完成粒子

`spawnUnit` 里在门口播 `ParticleTypes.CLOUD`（10 个，白色烟团）作完成特效，Mindustry `UnitFactory.create` 的近似喵。
