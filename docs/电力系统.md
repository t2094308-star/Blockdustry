## 1. 电力核心概念喵

### 1.1 PowerGraph（电网）喵

文件：`core/src/mindustry/world/blocks/power/PowerGraph.java`喵。

PowerGraph 是整个电力系统的核心数据结构，代表一个互联的电网喵。它把整张地图上所有电气建筑（发电、耗电、电池）分成若干个互不相连的「图」喵。每个图的更新由一个独立的实体 `PowerGraphUpdater` 驱动，每 tick 调用一次 `graph.update()` 喵。

核心成员变量：

```java
// 电网中的分类列表喵
public final Seq<Building> producers = new Seq<>(false, 16, Building.class);  // 纯发电者喵
public final Seq<Building> consumers = new Seq<>(false, 16, Building.class);  // 纯耗电者喵
public final Seq<Building> batteries  = new Seq<>(false, 16, Building.class); // 电池（缓冲）喵
public final Seq<Building> all        = new Seq<>(false, 16, Building.class); // 全部成员喵

private final @Nullable PowerGraphUpdater entity;   // 每 tick 驱动 update 的实体喵
private final WindowedMean powerBalance = new WindowedMean(60); // 60 tick 滑动平均的功率平衡喵
private float lastPowerProduced, lastPowerNeeded, lastPowerStored;
private float lastScaledPowerIn, lastScaledPowerOut, lastCapacity;
private float energyDelta = 0f; // 二极管等直接搬运电量的累计量喵
```

关键要点喵：

- `producers / consumers / batteries` 三个列表由 `add(Building)` 按 `block` 的属性归类喵（见 1.3）喵。
- 每个图有一个全局唯一递增的 `graphID` 喵。
- `powerBalance` 用 60 tick 的滑动窗口记录 `(生产 - 需求 + 能量搬运) / 每tick时长`，供 UI 显示「±功率」喵。
- 电量单位：内部所有数值均为「每 tick」功率喵，`getPowerBalance()` 的返回值乘 60 才是每秒功率喵。

### 1.2 Building.power（PowerModule，电网节点）喵

文件：`core/src/mindustry/world/modules/PowerModule.java` 与 `core/src/mindustry/entities/comp/BuildingComp.java`喵。

每个有电的建筑实体上挂一个 `PowerModule power` 字段，它就是电网里的一个节点喵：

```java
public class PowerModule extends BlockModule{
    public float status = 0.0f;   // 见下方注释喵
    public boolean init;
    public PowerGraph graph = new PowerGraph();  // 该建筑所属的电网喵
    public IntSeq links = new IntSeq();          // PowerNode 手动连接的对方 pos 列表喵
}
```

- `status` 语义分两种喵：对**无缓冲耗电方**，它是「供电满足率」（1.0 = 100% 功率满足，不足则降效运行）喵；对**有缓冲的电池/耗电方**，它是「当前电量 / 最大容量」喵。
- `graph` 即所属电网喵，建筑被拆除/移动时用 `graph.remove(self())` 拆图重建喵。
- `links` 只有 PowerNode 会用，保存指向对方建筑 `pos()`（打包的 tile 坐标）的整型列表喵。

节点如何被创建（`BuildingComp.create()`）喵：

```java
if(block.hasPower){
    power = new PowerModule();
    power.graph.add(self());   // 建好即把自己加入一个新图喵
}
```

### 1.4 PowerGraph.add()：节点归类规则喵

`PowerGraph.add(Building)` 决定一个建筑进哪个列表，是理解电网的基础喵：

```java
public void add(Building build){
    if(build == null || build.power == null) return;
    if(build.power.graph != this || !build.power.init){
        // 移除旧图引用喵
        build.power.graph = this;
        build.power.init = true;
        all.add(build);

        if(build.block.outputsPower && build.block.consumesPower && !build.block.consPower.buffered){
            producers.add(build);   // 自产自销但非缓冲 → 同时是生产者+消费者喵
            consumers.add(build);
        }else if(build.block.outputsPower && build.block.consumesPower){
            batteries.add(build);   // 既能进又能出且 buffered → 电池喵
        }else if(build.block.outputsPower){
            producers.add(build);   // 只出 → 生产者喵
        }else if(build.block.consumesPower && build.block.consPower != null){
            consumers.add(build);   // 只进 → 消费者喵
        }
    }
}
```

- 发电机同时 `outputsPower && consumesPower`，但 `consPower.buffered=false`（普通发电机的 consPower 只有 usage，无缓冲），所以进 `producers+consumers` 喵。
- 电池 `outputsPower && consumesPower` 且 `buffered=true` → 进 `batteries` 喵。
- 电网合并用 `addGraph(PowerGraph)`：小图并入大图，保留大的那个实体，销毁小的喵。

### 2.2 如何连接其他建筑喵

节点通过「配置（config）」机制保存连接列表，支持两种连接方式喵。

**方式一：手动配置（Integer 类型的 config）**喵。点击一个合法建筑后，`config(Integer.class, ...)` 回调执行连接/断开喵：

```java
config(Integer.class, (entity, value) -> {
    PowerModule power = entity.power;
    Building other = world.build(value);
    boolean contains = power.links.contains(value), valid = other != null && other.power != null;

    if(contains){
        // 断开连接：删除双方 links 里的记录，然后从本端开始 reflow 重建图喵
        power.links.removeValue(value);
        if(valid) other.power.links.removeValue(entity.pos());
        PowerGraph newgraph = new PowerGraph();
        newgraph.reflow(entity);   // BFS 重建本侧电网喵
        newgraph.update();
        if(valid && other.power.graph != newgraph){
            PowerGraph og = new PowerGraph();
            og.reflow(other);      // 另一端也重建喵
            og.update();
        }
    }else if(linkValid(entity, other) && valid && power.links.size < maxNodes){
        // 建立连接：双方 links 互相记录对方 pos，然后合并两个电网喵
        power.links.addUnique(other.pos());
        if(other.team == entity.team){
            other.power.links.addUnique(entity.pos());
        }
        power.graph.addGraph(other.power.graph);  // 关键：电网合并喵
    }
});
```

**方式二：放置时自动连接（autolink + `placed()`）**喵。放置后调用 `getPotentialLinks(tile, team, ...)` 找出范围内所有合法目标，逐个 `configureAny(other.pos())` 自动建链喵。

### 2.3 合法性判断 linkValid 与范围喵

```java
public boolean linkValid(Building tile, Building link, boolean checkMaxNodes){
    if(tile == link || link == null || !link.block.hasPower || !link.block.connectedPower
        || tile.team != link.team || (sameBlockConnection && tile.block != link.block)) return false;

    if(overlaps(tile, link, laserRange * tilesize) ||
       (link.block instanceof PowerNode node && overlaps(link, tile, node.laserRange * tilesize))){
        if(checkMaxNodes && link.block instanceof PowerNode node){
            return link.power.links.size < node.maxNodes || link.power.links.contains(tile.pos());
        }
        return true;
    }
    return false;
}
```

要点喵：

- 必须同队、对方 `hasPower && connectedPower` 喵。
- 距离判定用**圆 vs 方形包围盒**的相交（`Intersector.overlaps`）喵：以本节点为中心、`laserRange * tilesize` 为半径的圆，与目标建筑的矩形相交即可喵。
- 若目标是 PowerNode，则只要任一方向（本节点范围或对方范围）命中即可喵，且要检查对方 `maxNodes` 未满喵。
- `getPotentialLinks` 里用空间索引 `team.data().buildingTree` 快速取范围内的建筑，然后排序：PowerNode 优先、再按距离近优先喵。
- `insulated(tile, other)` 用 `World.raycast` 检测两点连线之间是否有 `isInsulated()` 的方块（如 PowerDiode）挡路，有则不能连喵。

### 2.4 激光渲染喵

```java
public void drawLaser(float x1, float y1, float x2, float y2, int size1, int size2){
    float angle1 = Angles.angle(x1, y1, x2, y2),
        vx = Mathf.cosDeg(angle1), vy = Mathf.sinDeg(angle1),
```

`ConsumeGeneratorBuild.updateTile()` 完整逻辑喵：

```java
public void updateTile(){
    boolean valid = efficiency > 0;  // efficiency 由消费器系统算出喵

    warmup = Mathf.lerpDelta(warmup, valid ? 1f : 0f, warmupSpeed); // 预热插值喵
    productionEfficiency = efficiency * efficiencyMultiplier;        // 效率 = 消费满足度 * 倍率喵
    totalTime += warmup * Time.delta;

    // 随机生成粒子特效喵
    if(valid && Mathf.chanceDelta(effectChance)){
        generateEffect.at(x + Mathf.range(generateEffectRange), y + Mathf.range(generateEffectRange));
    }

    // 从已消耗物品查时长倍率喵
    if(filterItem != null && valid && itemDurationMultipliers.size > 0 && filterItem.getConsumed(this) != null){
        itemDurationMultiplier = itemDurationMultipliers.get(filterItem.getConsumed(this), 1);
    }

    // 周期性消耗燃料：generateTime <= 0 时触发 consume()，并重置 generateTime = 1喵
    if(hasItems && valid && generateTime <= 0f){
        consume();  // 调用 ConsumeItemFilter 等真正的扣料喵
        consumeEffect.at(x + Mathf.range(generateEffectRange), y + Mathf.range(generateEffectRange));
        generateTime = 1f;
    }

    // 可选副产液体喵
    if(outputLiquid != null){
        float added = Math.min(productionEfficiency * delta() * outputLiquid.amount,
            liquidCapacity - liquids.get(outputLiquid.liquid));
        liquids.add(outputLiquid.liquid, added);
        dumpLiquid(outputLiquid.liquid);
        if(explodeOnFull && liquids.get(outputLiquid.liquid) >= liquidCapacity - 0.01f){
            kill();
            Events.fire(new GeneratorPressureExplodeEvent(this));
        }
    }

    // 发电计时：一个物品烧完后才会再次 consume 喵
    generateTime -= delta() / (itemDuration * itemDurationMultiplier);
}
```

机制解读喵：

- 「燃料」由 `ConsumeItemFilter`（如 `ConsumeItemFlammable`、`ConsumeItemExplode`、`ConsumeItemRadioactive`）消费喵。`consume()` 每 `itemDuration` tick 扣一个物品喵。
- `productionEfficiency = efficiency * efficiencyMultiplier`，而 `efficiency` 是所有消费器（含电力消费器）满足度的最小值喵。所以燃料不足/停电都会降低发电喵。
- `warmup` 是视觉效果与状态过渡用的预热值，用 `lerpDelta` 平滑变化喵。
- `itemDurationMultipliers` 让特定物品更耐烧（如 pyratite 倍率 3）喵。

### 4.2 电力消费器 ConsumePower 喵

文件：`core/src/mindustry/world/consumers/ConsumePower.java`喵。

```java
public class ConsumePower extends Consume{
    public float usage;      // 每 tick 最大耗电喵
    public float capacity;   // 最大蓄电量（buffered 时）喵
    public boolean buffered; // 是否缓冲（能存电）喵

    public ConsumePower(float usage, float capacity, boolean buffered){...}

            (1f - entity.power.status) * capacity :   // 缓冲型：把电充满需要的量喵
```

- `Block.consumePower(usage)` 创建 `new ConsumePower(usage, 0f, false)` 喵（在 Block.java 里）喵。
- 每个方块最多一个 `ConsumePower`，`consume()` 里会先移除旧的再设 `consPower` 喵。

### 4.3 PowerGraph.update() 功率平衡机制（核心）喵

每 tick `PowerGraphUpdater.update()` → `graph.update()`，算法如下喵：

```java
public void update(){
    // 作弊模式：直接把所有消费者的 status 置 1喵
    if(!consumers.isEmpty() && consumers.first().cheating()){
        for(Building tile : consumers) tile.power.status = 1f;
        lastPowerNeeded = lastPowerProduced = 1f;
        return;
    }

    float powerNeeded = getPowerNeeded();     // 所有消费者的需求总和喵
    float powerProduced = getPowerProduced(); // 所有生产者的产出总和喵

    lastPowerNeeded = powerNeeded;
    lastPowerProduced = powerProduced;

    lastScaledPowerIn  = (powerProduced + energyDelta) / Time.delta; // 单位换算成每秒喵
    lastScaledPowerOut = powerNeeded / Time.delta;
    lastCapacity   = getTotalBatteryCapacity(); // 全部电池总容量喵
    lastPowerStored = getBatteryStored();        // 全部电池当前总电量喵

    powerBalance.add((lastPowerProduced - lastPowerNeeded + energyDelta) / Time.delta);
    energyDelta = 0f;

    if(!(consumers.size == 0 && producers.size == 0 && batteries.size == 0)){
        boolean charged = false;

        if(!Mathf.equal(powerNeeded, powerProduced)){
            if(powerNeeded > powerProduced){
                // 生产 < 需求：用电池补差喵
                float powerBatteryUsed = useBatteries(powerNeeded - powerProduced);
                powerProduced += powerBatteryUsed;
                lastPowerProduced += powerBatteryUsed;
            }else if(powerProduced > powerNeeded){
                // 生产 > 需求：多余的充进电池喵
                charged = true;
                powerProduced -= chargeBatteries(powerProduced - powerNeeded);
            }
        }

        distributePower(powerNeeded, powerProduced, charged); // 结算每个消费者的 status喵
    }
}
```

核心机制喵：

1. **先算总需求** `getPowerNeeded()`：累加每个 `consumers` 里 `shouldConsumePower` 的 `consPower.requestedPower(consumer) * consumer.delta()` 喵。
2. **再算总产出** `getPowerProduced()`：累加每个 `producers` 的 `producer.getPowerProduction() * producer.delta()` 喵。
3. **电量撮合**：需求>产出时 `useBatteries` 从电池抽电补差；产出>需求时 `chargeBatteries` 把盈余存进电池喵。
4. **按比例分配** `distributePower` 决定每个消费者的 `status`（满足率）喵。

`distributePower` 的分配算法喵：

```java
public void distributePower(float needed, float produced, boolean charged){
    float coverage = Mathf.zero(needed) && Mathf.zero(produced) && !charged && Mathf.zero(lastPowerStored)
        ? 0f : Mathf.zero(needed) ? 1f : Math.min(1, produced / needed);
    // coverage = 产出/需求，封顶 1喵
    for(int i = 0; i < consumers.size; i++){
        var consumer = consumers.items[i];
        var cons = consumer.block.consPower;
        if(cons.buffered){
            // 缓冲型：按覆盖率往缓存里充等比例的百分比喵
            if(!Mathf.zero(cons.capacity)){
                float maximumRate = cons.requestedPower(consumer) * coverage * consumer.delta();
                consumer.power.status = Mathf.clamp(consumer.power.status + maximumRate / cons.capacity);
            }
        }else{
            if(consumer.shouldConsumePower){
                consumer.power.status = coverage;  // 非缓冲：直接赋满足率喵
            }else{
                // 还没激活的消费者给一个估算值喵
                consumer.power.status = Math.min(1, produced / (needed + cons.usage * consumer.delta()));
                if(Float.isNaN(consumer.power.status)) consumer.power.status = 0f;
            }
        }
    }
}
```

电池充放电算法喵：

```java
// 放电：从所有电池里等比例取出 needed 的电喵
public float useBatteries(float needed){
    float stored = getBatteryStored();
    if(Mathf.equal(stored, 0f)) return 0f;
    float used = Math.min(stored, needed);
    float consumedPowerPercentage = Math.min(1.0f, needed / stored);
    for(Battery : batteries) if(enabled) battery.power.status *= (1f - consumedPowerPercentage);
    return used;
}

// 充电：把盈余均匀分给所有未满电池喵
public float chargeBatteries(float excess){
    float capacity = getBatteryCapacity(); // 所有电池剩余可充空间喵
    float chargedPercent = Math.min(excess/capacity, 1f);
    for(Battery : batteries) if(enabled && capacity>0f)
        battery.power.status += (1f - battery.power.status) * chargedPercent;
    return Math.min(excess, capacity);
}
```

补充喵：

- `getBatteryStored()` = Σ `power.status * consPower.capacity`（所有 enabled 电池的已存电）喵。
- `getBatteryCapacity()` = Σ `(1f - power.status) * consPower.capacity`（剩余可充空间）喵。
- `getSatisfaction()` = `clamp(produced/needed)`，UI 上用来控制状态灯和激光颜色喵。

### 4.4 PowerDiode（二极管，单向送电）喵

文件：`core/src/mindustry/world/blocks/power/PowerDiode.java`喵。

- `insulated = true`，所以它隔断两侧电网、阻挡 PowerNode 激光喵。
- 每 tick 比较前后两个图的电池存量百分比，若 `back` 比例高于 `front`，则把差量的一半从后图搬到前图喵：

```java
float backStored  = backGraph.getBatteryStored();
float backCapacity  = backGraph.getTotalBatteryCapacity();
float frontStored = frontGraph.getBatteryStored();
float frontCapacity = frontGraph.getTotalBatteryCapacity();
if(backStored/backCapacity <= frontStored/frontCapacity) return;
float targetPercentage = (frontStored + backStored) / (frontCapacity + backCapacity);
float amount = Mathf.clamp((targetPercentage * frontCapacity - frontStored) / 2, 0, frontCapacity - frontStored);
backGraph.transferPower(-amount);
frontGraph.transferPower(amount);
```

- `transferPower(amount)` 把正负电量记进 `energyDelta`，下一 tick `update()` 时计入功率平衡喵（这就是 energyDelta 存在的意义喵）。

## 6. 移植到 MC 模组的要点总结喵

1. **电网本质是「连通集合并查/图」**：Mindustry 用 BFS（reflow）和图的合并/拆分维护连通性喵。MC 里可以用并查集（Union-Find）或按 tick 的 BFS 重建喵，关键是「断开连接要拆图、建立连接要合并」喵。
2. **功率按 tick 结算、按比例分配**：先求总产、总耗，电池补差，再把「覆盖率 = min(1, 产出/需求)」广播给每个耗电方块喵。MC 实现建议同样「每 tick 全局结算一次电网能量」喵。
3. **区分 buffered（电池）与 unbuffered（直接耗电）**：电池存 `status*capacity` 能量，直接耗电方块只关心满足率喵。MC 若用 FE/Energy 单位，可按 `usage`（每tick）与 `capacity` 对应 RF/t 与容量喵。
4. **效率 = 所有消费器满足度的最小值**：发电机效率由燃料满足度和电力满足度共同决定喵。MC 的发电机可参考「燃料不足 → 效率下降」而不是硬开关喵。
5. **节点只是连通工具**：PowerNode 本身 0 产 0 耗，只负责把多个电网 merge 成一个喵。MC 的电线/能量管道可等价建模喵。
6. **二极管/绝缘**：`insulated` 阻隔连接、`PowerDiode` 单向按电池百分比搬电喵。MC 若要单向传输，可参考其「百分比差额」算法喵。
7. **单位换算**：Mindustry 内部是每 tick 功率，显示乘 60 喵。MC 常按秒算，移植时注意统一换算喵。
